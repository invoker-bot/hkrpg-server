# 4.6 宇宙待选动作的原始请求边界

原生命令5676的已实现子集仍是祝福选择、奇物选择和祝福重选。现在在DynamicMessage解析之前验证原始字节：uint32必须位于0～4294967295，单值字段不得重复，同一oneof不得携带多种操作，嵌套请求、字段类型和长度必须有效。边界为16KiB、嵌套深度4和每个重复字段最多128项；这些限制是项目规则。钟表小子的面值放置共用此验证器，packed/unpacked面值行为保持原有规则。

新增UniversePendingWire46Test共37项检查。修复前22项断言失败，包括祝福/奇物编号和批次被截断后仍被接受、重复字段被合并后消耗菜单，以及截断或错误字段类型导致解析异常。修复后34种异常请求返回REQ_PARA_INVALID，保存的玩法对象逐字JSON相同；3项正向检查验证实际祝福取得、奇物取得和扣除30碎片后的重选。客户端重选按钮省略批次的原生请求继续作用于当前唯一菜单，不因这次检查被禁用。

本批不新增命令映射、不修改生成协议、CmdId或版本常量。命令和字段的静态来源仍见client-protocol-evidence.md；此处的Java检查使用已保存候选和独立测试资源，不能算游戏客户端UI验收。真实网络探针、完整构建和独立源码导出结果须分别记录，未执行项目不算通过。全部宇宙事件、奇物语义和自然玩法仍未完成，功能维持partial。
