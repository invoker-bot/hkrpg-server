# 玩家队伍任务副本的动态试用角色

本批把可完整识别的剧情试用单指令接入无额外编队限制的 `Player` 任务 Raid。实际角色、技能、装备和队伍先创建并保存，原有条件随后观察完成。支持范围仍为部分实现，不能视为全部副本、完整剧情或官方 4.6 客户端验收。

## 原始范围

固定来源为 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。新增夹具保持八份源 Git blob、17 条完整记录及其中 35 条原始子任务。角色、单指令脚本、技能和装备沿用普通场景批的固定原件。

原始 Raid `40301` / 主任务 `1036004` / 目标 `103600414` 在 `40301/40301002` 通过 `AddTrialPlayer` 追加 `1021225`；原始 Raid `40414` / 主任务 `1040212` / 目标 `104021212` 在 `40414/40414001` 通过 `ReplaceVirtualTeam` 使用 `1021404`。这些原始副本行均使用 `Player` 队伍，且没有角色门槛、固定领队或禁止换队限制。

资源、实际父任务状态、主子任务接取、当前副本归属和实际场景必须匹配。创建要求实际副本位置有效；保存恢复还校验固定副本定义、所属 Raid 编号、完整脚本、实际技能资源和执行收据。只有已验证的脚本可使 Player 队伍临时包含试用角色；客户端选择列表不能自行提供任意试用编号。既有 TrialOnly、TrialOrPlayer、冻结玩家队伍及其原始限制继续使用原管理器，本批不合并两种角色来源。

## 保存、暂离和恢复

每个 `MissionRaidRun` 独立保存 `MissionTrialState`；普通场景的试用记录仍归普通任务存档。角色快照、技能、装备、生命/能量、领队、秘技点和执行历史均随对应 Raid 保存。

暂离副本先解除活跃归属并移除本管理器拥有的临时缓存，再加载原返回位置。保存的副本队伍和历史保留，普通场景队伍不会被改写。重新进入同一未完成副本，从原快照发布角色并恢复队伍，查询和已完成目标不重新创建或重置角色。暂停时持有旧队伍对象也不能修改已暂停队伍；普通场景任务不能覆盖暂停副本的角色记录。

当前、全部编队、角色详情和场景角色查询使用同一实际队伍。主任务结束或取消时清理该副本自身队伍，保留执行收据；外来临时角色不删除。取消后正常登录由原副本恢复流程返回原位置。源任务、副本定义、技能、装备或收据损坏时拒绝发布，不改坏记录。

追加、单人虚拟替换、最多四人和普通场景楼层清理沿用本服策略，仍未确认全部官方执行器语义。本批的角色快照还补充实际缓存光锥等级、突破和叠影校验，避免复用与冻结来源不一致的战斗数据。暂停和跨任务队伍分离不代表所有跨楼层、销毁指令或异步演出都已实现。

## 验证边界

新增 26 项 Java 回归，覆盖两个原始副本目标、暂停返回与独立数值、两次真实 Player/Morphia 文档读取、损坏副本绑定/资源/收据、八种无效上下文、实际暂离接口、取消/结束的唯一清理和普通任务隔离。两个有完整资源和实际副本归属的角色创建断言确实先失败；三项实际缓存装备数值损坏断言也确实先失败。编译错误和夹具哈希适配错误不计入行为失败。

`python -s -X utf8 scripts/smoke-raid-scripted-trials.py --resources <只读资源目录>` 使用独立资源镜像与独立 H2 数据库。通过 4.6 KCP 的 `StartRaid` / `LeaveRaid` 检查两个独立 UID 的实际角色发布、同进程重连、暂离/再进入和正常进程重启后的恢复；最后只在隔离存档中取消主任务，检查角色清理和原返回位置。

根目录与独立导出服务包各通过 144 条 KCP 请求、14 次状态检查、4 次正常 stop、3 次同 UID H2 进程重启；四次离线检查共八份玩家读取、两次隔离操作共四份玩家写入通过，2433 份来源资源 SHA 保持不变。

网络中父任务接取、`103600405` 前导目标完成、只以目标作为首步和未完成结束目标 `199988999` 均为明确夹具。`40301` 原始首步在楼层一，本测试首步设到原始目标楼层二；不代表官方前导任务或跨楼层脚本自然完成。目标子任务、创建脚本、角色技能装备、Raid 配置和原始楼层不改；生产配置、存档和资源不写入。

原型只用于定位问题；全量 Java、Python、独立源码导出构建、同 jar 网络和原件 SHA 结果以 `build/raid-scripted-trials-verification.json` 为准。根目录与导出源码各通过 5601 项 Java 回归、132 项 Python 检查；2341 份源码一致，151 份冻结协议不变。同一根目录 jar 的普通场景银狼回归另通过 49 条 KCP，通用 47 项 / 33 项玩家状态及 Dispatch 两项账户重启检查通过。完整副本剧情、既有试用队伍的动态合并、固定领队/禁止换队与剧情强制替换的关系、所有销毁/演出、完整战斗输入回放、小游戏、游戏客户端 UI 和断电原子性仍待继续完成。
