# 宇宙探索积分任务目标

原始目标 `403000601` 已接入服务端真实探索积分结算。只有结算时已接取、尚未完成、未取消并且定义完全匹配的目标才能完成；过去的积分不能完成后来接取的目标。这里采用“本服经典宇宙实际结算了一笔正积分”的服务端规则。任务标记中的位面和楼层是原始导航声明，结算可以发生在宇宙实例中。功能仍为部分支持，完整官方引导、客户端 UI 和其余宇宙模式没有验收。

## 来源与边界

夹具固定在 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`，记录八份完整 Git 文件的 SHA256，保留原始主任务、子任务、空任务图、主任务表、区域 110、两条周期常量、两条宇宙常量及空奖励 100。原始目标为单步 `NoPara/RogueExploreScore`，脚本全文为无动作任务；未知字段、改动脚本、额外参数或不同目标不使用这一条件。

只有归属于当前玩家且仅有一个有效存档键的终止结果可以入账。结果必须具有实际房间分数、已清房间数、可结算收益和冻结的有效积分周期；探索中的结果、无归属对象、重复对象引用、已入账记录、分数不一致和损坏的预留记录均不产生新积分。周期溢出或不一致时，任务观察记录和结算标志也不变化。

积分、冻结任务签名和一次结算标志存于同一个 Player 文档，随后才刷新任务。保存后任务推进中断时，恢复使用原始签名、已入账结果和对应实际周期继续推进，不再次加分。旧存档没有任务签名时不能补造历史目标；跨周期恢复仍记入结果冻结的周期。这里的顺序和正常停服恢复证据不等于断电原子性。

## 验证

新增 29 项 Java 回归，其中原条件有五项真实行为先失败，积分归属与损坏记录检查有四项真实行为先失败。覆盖三种终止结果、零清房间、接取时序、取消、脚本变动、缺失积分周期、损坏历史、中断与 JSON 恢复、真实 Morphia Player 两次重载、32 个并发调用、积分溢出、周期边界和第二笔正常积分。

`scripts/smoke-rogue-explore-score-mission.py` 使用独立、明确标记的 `build/smoke` 目录和数据库。四项前置任务由无奖励 Auto 夹具开放，原始目标及其主任务、脚本、奖励、区域和分数保持不变；首房指定原始房间 100，并补充隔离地图池中的线性站点别名。加入分地图默认池后，该脚本显式写入仅属于测试目录的 `maps.101.1=[100]`，继续隔离同一个积分条件。该历史夹具末站是精英房，因此同时以 `RogueBossGen.json` 的空区域映射关闭该夹具的 Boss 绑定。该入口配置是联调夹具，没有验证完整官方房间生成或原始前置流程。

探针通过固定 4.6 描述符和 UDP/KCP 请求进行登录、五场原始房间战斗、离开和放弃结算，再查询任务与周期积分。只读 H2 检查器核对正常停服后的同 UID、任务阶段、结果、目标签名及周期积分。该脚本必须实际通过后才算联调证据；编译、处理器存在或单元测试通过均不替代这项结果。它不启动游戏客户端，也没有重演客户端战斗输入或验证游戏画面。

实际联调已有 58 次 KCP 请求通过，四份同 UID 快照分别为进度/积分 `0/0、1/260、1/260、1/260`。五个原始关卡全部核对怪物波次及移除，五次重复战斗报告被拒绝，只有一次积分通知。三次正常 stop、三份只读 H2 Player 恢复检查通过；五场战斗的实际掉落响应合计 180 信用点，与正常重连和停服恢复的钱包相同。2,265 份输入资源前后完整字节 SHA256 不变。最终交付认证还要求当前工程与独立源码副本全量构建、Python 回归及同一最终 jar 的必要检查通过；以 build 中带校验和的核验报告为准。

协议、命令号、生成类和版本声明没有变化。原始资源、运营配置和已有数据库不作为测试写入目标。
