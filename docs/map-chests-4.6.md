# 跨地图战利品领取

用户反馈卡芙卡开场能看到普通战利品，但按交互键无法打开。旧的 `WorldChests` 只登记了少量固定宝箱；此前基座舱段补丁又只包含组 6 的六个探索宝箱，遗漏了开场组 36 的 `20001607`。其他地图的合法宝箱也会因不在目录内返回奖励配置不存在。

本次将领取身份扩展到完整资源目录。`scripts/generate-map-chest-catalog.py` 从原始楼层维度索引、地图组的 `ChestID`、`MazeChest` 和 `MazeProp` 关联生成 `src/main/resources/gameplay/map-chests-4.6.json`。来源为 `TurnBasedGameData@724b139d8c9c32d12552eb95745a4fee72bfe48b`；目录包含七个世界的 1,754 个 Town/Maze 宝箱、717 个完整组以及 2,148 条相关配置摘要。用 `--check` 可重新核对全部关联，不会改写运营资源。

运行时按真实世界、地图、维度、入口、组和物件实例定位宝箱，校验原始组、配置和已加载实体，不再按少数手写编号决定能否领奖。组定义按需加载并检查文件内容摘要，同大小、同修改时间的内容变化也不能绕过校验。旧的时隙、金矛、吉祥物和六箱探索收据继续使用原有身份及流程，已有领取记录兼容。

开场组 36 的箱子遵循自身剧情条件，不套用探索组 6 的 `1000401` 前置。探索组仍保持原来的任务门槛。Hidden 和 ChestLocked 状态不能靠开箱请求变成可领奖状态；由对应挑战或机关流程解锁到 ChestClosed 后，才进入统一领取流程。实例活动有自己的奖励域，本目录不纳入 20 个以太战线实例宝箱，也不猜测没有正式 `ChestID` 的物件身份。

领取沿用同一份 `worldChests` 保存域：先保存待投递记录，再发放物品，最后保存完成记录并发送状态和 `OpenChestScNotify.chest_id`。重复点击、换图、重连和正常 H2 进程重启不会再次发奖。首次保存失败允许重试；物品投递或最后保存中断保留待核对记录，阻止同账号跨地图重复投递。没有删除、重置或预写运营账号的宝箱记录。

奖励沿用本服基础经济预设，并根据资源世界和宝箱等级选择星琼、信用点、经验及对应地区货币。该预设不是已验证的官方完整掉落表。世界 501 的普通宝箱仅对已接取且满足窗口的对应活动计数，其他世界不会增加该活动进度。

回归入口：

```powershell
.\gradlew.bat test --tests '*MapChest46Test' --tests '*BaseZoneChest46Test' --tests '*WorldChestActivity46Test'
python scripts/generate-map-chest-catalog.py --check
python scripts/smoke-world-chests.py --map-chests --output build/map-chests-20261020/native-maps.json
python scripts/smoke-opening-stage-win.py
```

`MapChest46Test` 使用七个世界的完整原始组和楼层，覆盖实际领取、防重、保存/投递失败、换图、资源变化、地区货币缺失、活动计数和锁定拒绝。修复前 11 项定向测试中有 10 项因宝箱未接入而失败，证据在 `build/map-chests-20261020/red-behavior.xml`。跨地图网络探针只在独立账号和 H2 库中移动测试角色；领取、奖励、通知和收据由实际 UDP/KCP 请求产生，停服后按真实库存核账。开场探针另外验证未经剧情预置的新号卡芙卡领取与重连、重启恢复。

本次修复的是地图宝箱的通用识别、领取和保存链路。目录覆盖不等于每个机关和任务脚本都已实现，也不证明所有宝箱均已通过真实游戏客户端操作。完整机关演出、实例宝箱、官方完整掉落和全地图收集统计仍保持 partial。
