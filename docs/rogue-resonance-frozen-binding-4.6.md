# 回响存档的冻结来源一致性

原校验只限制命途、祝福类型、回响事件和四个祝福 ID 的取值范围，以及九条来源行的数量。恢复的存档可以保留原始来源行，却改成另一命途的类型、事件或祝福标识；损坏的 JSON 或重复来源行也不会被读取。本批十五项参数回归逐项以实际断言复现，证据为 `build/rogue-resonance-binding-fifteen-red.xml`。

现在 `Plan.valid` 解析自身保存的九条来源行，并核对命途/版本/类型、事件路径/ID/SPReserved、事件归属、主动/被动技能 ID 与触发键、主动精确 SPNeed 100、被动无 SPNeed，以及基础和三个强化祝福的 ID、等级、命途、类型、版本、Tag 和基础/强化角色。空值、坏 JSON、过长记录、重复或缺失祝福均拒绝。校验失败时不建立菜单、不附加战斗事件，也不修改已保存的能量和局状态。

校验使用每局自身冻结来源，不依赖重新加载后的全局目录；已有资源缺失后继续当前局、JSON 与实际 Player/Morphia 恢复测试仍需保持通过。它验证字段之间的一致性，不是外部防篡改签名，也没有新增普通祝福来源快照或证明任意来源行的官方真实性。

完整回响动作、强化组合、原始阈值/初始能量以及实际游戏 UI 仍待完成，功能保持 `partial`。本批完整构建和同产物网络验证完成后记录到 `build/rogue-resonance-binding-verification.json`。

最终完整构建通过 Java 8448 项（347 类）、Python 212 项及 151 份冻结协议核对。产物 SHA256 为 `966f8ecbcb8ea1564559bdccccd56980585cc31ce1f7d9b786868cb3c8774b4f`，同产物通过原始怪物能量报告 60 次请求/96 项检查、缺菜单重入恢复 56 次请求/64 项检查及 HTTP 账号重启恢复。两个 KCP 流程各含六次正常停止、五次同 UID H2 重启和十二次实际 Player 读取；资格种入与合成报告边界仍按各自网络文档记录，不作为官方战斗或 UI 验收。
