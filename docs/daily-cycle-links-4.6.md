## 来源和当前范围

固定资源提交为 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。测试保留 32 份完整原始行及 JSON 路径、资源 SHA、来源 blob SHA，涉及 `QuestData`、`FinishWay`、`CycleQuest`、`DailyQuest`、`ScheduleDataQuest`、`DailyActiveQuestPool`、`RewardData` 和 `MainMission` 八份来源。还保留 `2100159` 与 `UseItem 110/34` 两个子目标，作为未实现分支的反例；没有猜测这两个物品的使用入口。

当前仅支持原始单目标、`Cycledays=1`、完整七个星期日、有效等级区间及有效日程的裸 `RogueFinishCnt / NoPara / Progress 1` 周期目标。父目标须是单目标日常、一个不同编号列表中的目标完成，所有分支均有匹配的原始周期、日程和解锁定义，且已支持的分支足以达到目标。原始 GridFight 的明确形状可以参与列表核对，但始终提供零条完成证据。其他周期、多目标、星期限制、回溯和未知参数暂不接入。

`CycleQuest` 的一天周期与现有日常共用国服 04:00 边界，是本项目当前规则。日程文本按 UTC+8 严格读取，采用开始包含、结束不包含；尚未核对游戏客户端完整周期计算链。日常池继续沿用每类选择一个可完成且已解锁目标的既有项目策略。

## 存档和发奖

每一天有独立的 `DailyCycleQuestState.Window`，窗口自身保存日期，记录原始目标、周期、日程和奖励的内容指纹。目标进度和父目标进度保存在同一玩家文档。只有 `UniverseManager` 接受了本局实际最后房间胜利，并写入新的通关记录后，才推进周期目标；单个非末尾战斗、失败、退出和查询均不推进。

目标、日程、解锁或奖励发生变化时，已有记录停止推进和领奖，不重新套用新配方。缺失、别名、无效进度、异常完成时间和跨日记录不能计数；父目标领奖还要重新检查本日子记录。旧普通存储中的已知日常和周期目标不再重复出现在当前列表中。

原始子目标奖励 `100` 是空奖励，可以完成一次领取关闭，但没有物品到账。父目标原始奖励 `103005` 为 500 活跃点，不进入物品库存。领取预留保留 `CLAIMING` 状态，中断后不自动重发；旧窗口和预留仍保存在原日。通用跨文档崩溃恢复与自动对账不在本批验收范围内。
