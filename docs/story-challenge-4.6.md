# 4.6 传统虚构叙事的两半场入口

原生 StartChallengeCsReq 的 stage_info 字段 14，绑定 ChallengeBuffInfo.story_info 字段 13，以及 buff_one 7 / buff_two 13，已直接解析。两半场保留原生队伍次序，各一至四名实际持有的正式角色，拒绝跨半场重复角色、未知字段、重复字段、uint32 截断、Boss 分支和缺失选择。现有忘却之庭请求保留；故事切换、宇宙、活动跑酷、钟表、节奏、试用战斗及其他实例占用时不入场。

新增来源目录只接受两个半场、两入口一致的 Normal 虚构叙事，关卡与 GroupID / MazeBuffID 必须匹配，原始组选项全部具备正确 ID / Lv=1 的战斗资源，SubMazeBuffList 必须为空。Fever、Tierce 和带额外子增益的形状继续拒绝，不能代表全部 4.6 虚构叙事。来源资源不被修改；目录在既有加载流程读取。

两半场选择在原生开始和当前状态中返回，战斗只绑定对应半场的选择与基础增益。ChallengeInfo.ext_info 按匹配语义转换为 CurChallenge.stage_info；4.6 不再发送空 Boss 单选分支，4.2 行为保留。4.6 的传统计分容器 10003 来自 March7thHoney fe00bdbda3c28ca33d01f171566aa35b5ab95083 的 ChallengeStoryInstance.OnBattleStart；没有修改冻结协议、字段号或命令号，也没有把本机未匹配到明文协议类型名当成客户端验收。

同半场的累计报告现在按上一半场基数计算，避免第二次报告丢失前一次分数。倒退的累计分数在消费战斗前拒绝，可合法重试；退出不写分数。回合耗尽时清理旧半场遇敌而不发布击杀事件，再切换半场。分数仍来自被接受的客户端报告，本批没有实现完整服务端战斗演算或额外计分校验。

新结算在单次历史保存中保留两半场分数，原生历史界面分别返回 score_id / score_two。旧记录缺少半场标记时保留总分兼容方式；新增字段没有改变 4.2 历史协议。
