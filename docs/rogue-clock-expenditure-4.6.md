# 4.6 公司咕咕钟的商店与复活支出

公司咕咕钟70的原始参数0.25现在接入祝福商店、奇物商店和复活装置的实际扣费，与已有强化、祝福重置共用费用校验与破碎转换。原始奇物9/70和效果参数沿用 `src/test/resources/fixtures/rogue-broken-clock-4.6.json` 的固定来源，不增加未确认协议或修改客户端文件。

商店在首次生成库存时保存每项总价、附加费用和产生报价的咕咕钟取得实例。后续查询、JSON与Morphia恢复保留报价；旧存档没有附加费用的报价继续按原价格处理。取得新咕咕钟不重新计价，也不继承其他实例报价的累计值。祝福批量购买先核对全部项目，再一次扣费、累计附加费用和转换；奇物购买先校验支付，再提交取得效果，余额不足或计数溢出不消耗库存、不取得奇物。

复活使用新局保存的基础单价与恢复比例，按请求发生时当前咕咕钟计算每人的附加费用。原生复活信息和实际扣费使用同一计算；全部倒地目标与当前装置校验通过后才一次支付和恢复。取得咕咕钟及转换成破碎钟后更新已有原生复活价格通知。交易保存后才通知破碎替换、钱包与队伍状态。

整数取整采用项目规则：每个商品或每名复活角色的单价先乘0.25并向下取整，再合并批次。商店基础价格仍是已明确标注的项目规则，祝福强化折扣不用于商品价格。破碎判定继续采用已记录的项目规则“累计额外支出超过499”；499/999来自原始参数，官方比较表达式尚未核实。转换奖励与购买/复活同存一份Player文档，记录原取得实例的一次999碎片奖励；这不证明突然断电时的数据库原子性。

新增18项Java回归。首轮13项中11项为真实断言失败，随后复活价格通知1项先失败；其余4项核对多商品取整、旧报价、损坏报价和实际Morphia两次保存恢复。没有以夹具错误计入行为回归。商店NPC、剧情图和余额使用现有隔离场景夹具；只有咕咕钟来源行保持原始数据，因此不代表官方商店生成或真实客户端UI验收。

当前下载装置没有碎片扣费，不凭咕咕钟描述补造下载价格。事件成本和未实现玩法仍须各自接通；本项不代表全部奇物或宇宙玩法已完成。完整构建与当前产物验证结果记录在 `docs/verification.md`。


基础原生消费检查：scripts/smoke-rogue-clock-shop.py先购买奇物70再首次查询另一原始商人的祝福库存，按原始分类及项目基础价格核对附加费用、批量扣费/祝福/钱包通知、重复拒绝、取得前报价冻结及重连/H2重启恢复。首房1000012、组1/35/117与1500初始钱包为隔离配置，12份原始场景/图/表SHA保持不变。这项基础检查不包含破碎转换。

追加scripts/smoke-rogue-clock-conversion.py：实际KCP取得70、购买第一批祝福并保存186附加费，正常停服重启后购买另外三件奇物及第二批祝福，累计额外支出522。核对已有原生替换载荷70→9、一次999奖励、准确余额3177和复活报价由100恢复80；全部购买重试、再次购买70、重连及再次H2进程重启均不重发替换或奖励。取得前200奇物报价和取得后250奇物/312祝福报价继续冻结。转换阶段三份同UID快照中替换通知为1/0/0，钱包通知4/0/0；14份原始来源SHA保持不变。

该检查只在临时目录中把房间1000012配置为原始组1/35/101/117/118、初始钱包5000及六条未修改的原始传奇祝福。为保证取得70，初始私有奇物目录包含2/9/12/70，首次正常停服后扩为2/9/12/13/19/66/70；9的原始定义用于冻结转换参数，不作为商品。原始资源、客户端及运营者配置不写入。未验证官方房间/商店生成、实际复活扣费、突然断电原子性或真实游戏UI。超过499仍为已记录的项目判定规则。

首次追加探针把进入响应后发送的现有复活报价误当成转换通知而失败；按已存在的服务端顺序分别核对进入报价和转换报价后重验通过。该探针时序错误不计入真实行为回归。
