# 任务地图的场景入口选择

## 问题与修复

用户报告在「列车长的馈赠」地图点击「前往」出现「场景获取失败」。截图对应目标 `405000502`，目的地为观景车厢 `P10000_F10000000`，帕姆位于组 62。只读核对正式存档时，返回列车的主任务 `1000501`、目标 `100050102` 已完成，`405000502` 仍处于已接取、待交谈阶段。

原始 `MapEntrance.json` 为同一车厢登记了普通入口 `1000001` 及四个指定剧情锚点入口 `100000102` 至 `100000105`。旧的 `GetSceneMapInfoScRsp` 把五个入口分别作为一张地图返回，但五条记录的 `SceneIdentifier` 相同。本机客户端 `NavMapModule._OnCmdGetSceneMapInfoScRsp` 按 `SceneIdentifier` 转成 `MapDataKey`，逐条调用 `MapData.SyncServerData`，后面的剧情入口会覆盖前面的普通入口。

`SceneMap46` 现为每个请求楼层只返回一条记录。同楼层优先使用玩家实际保存的入口；远处地图使用原有编号排序中的普通入口。地图查询继续保持只读，实际传送沿用入口任务前置、锚点解锁、战斗与副本占用检查。

## 验证边界

- 新增四项回归使用原始观景车厢的五条入口：远处查询、当前剧情入口、重复场景标识和整批拒绝未知楼层。修复前前三项失败，修复后全部通过。
- 冻结候选包的 129 项专项通过，包含地图查询、锚点、完成记录、剧情入口、列车场景及当前场景角色传送。
- 同一包的隔离 UDP/KCP 验证覆盖远处车厢查询、实际返回列车后的查询、重连及 H2 重启。原运行包的相同网络请求明确复现五条重复记录。网络夹具只清空隔离副本中列车与雪原两条入口的前置；正式资源和玩家任务进度不受此操作影响。
- 本轮没有取得用户此次点击的真实请求，也没有操作游戏界面。因此这次已复现并修复地图缓存覆盖问题，截图所述错误是否完全消失仍需用户复测；完整帕姆交谈与任务领奖不属于本轮自动化验收结论。
