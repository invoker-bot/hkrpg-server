# 4.6 怪物死亡、场景移除与秘技击杀

本批修复普通场景移除被当作怪物死亡的问题。任务组卸载、removeEntity按编号移除及对象移除仅清理实体；死亡触发由Scene.defeatMonster在玩家当前Scene、实体所属Scene、实际缓存对象和存活编号均一致后执行。对象入口核对引用身份，旧楼层对象或未注册对象即使编号与当前怪物相同，也不能误删当前实体。既有召唤物清理回调保留。

invokePropTrigger同时核对事件类型和原有组/实例条件。MONSTER_DIE与PUZZLE_FINISH不能借相同组号互相触发。胜利结算经过原有战斗/关卡/统计检查后调用实际死亡路径，失败和退出保持怪物存活；farm实体继续沿用原有不移除策略。

MazeSkillSetAttackTargetMonsterDie核对实际所属场景角色引用，仅对当前场景的已注册Minion或MinionLv2执行击杀。未知/缺失Rank、精英与Boss、旧场景、其他玩家、未注册目标及伪造同编号施法者均不计算掉落。玩家锁内移除真实目标后才计算原有掉落；同一实体的重复列表、再次调用及并发调用只产生一次死亡与一次掉落计算。未增加跨文档掉落事务或断电恢复保证。

实际死亡统一推进KillMonster、KillMonsterList和KillMonsterGroupList，使用被击杀场景的楼层、组号和实例编号。战斗不再另行重复调用击杀事件，秘技秒杀补上此前缺失的任务推进。普通移除不推进目标，不匹配的楼层/组号仍保持未完成。剧情图与条件解释沿用已有有限实现。

新增25项Java检查使用明确的合成场景、目标和战斗夹具，调用实际Scene、秘技动作、BattleService和MissionManager。最初22项中的16项先失败保留于 `build/scene-monster-defeat-lifecycle-red.xml`；另补三条任务事件检查，其中秘技未推进目标的先失败记录为 `build/scene-monster-defeat-mission-red.xml`。重叠用例不合计为独立缺陷。并发掉落计数使用同步夹具，夹具漏导入导致的编译失败已修正，不计为生产缺陷。当前25项及33项相关旧检查通过。

最终验证继续使用既有原生脚本：32个经典区域原始Boss/实际结果/实际地图角色移除/掉落积分及正常H2恢复，第一世界默认入口与原始加权敌人，以及43315空恢复与末尾对话。Boss首房安排和解锁、43315前置及早期对话/战斗结果为原脚本明确隔离夹具；既有战斗结果验证不等同于自然战斗输入回放。根目录、源码导出包、151份协议快照及原生计数以 `build/scene-monster-defeat-verification.json` 为准，未完成复验不算通过。

另按原始AvatarConfig核对，角色1317对应Rappa；本批纠正前一批文档及功能目录误写的流萤名称。服务端和既有协议验证使用的1317/1021317身份始终保持原始值，历史封存产物保留不改写。

完整演出、其他未识别秘技动作、所有场景死亡语义、正式游戏客户端UI、自然战斗回放及断电原子性仍待完成，场景、战斗和任务状态保持partial。生成协议、命令号、版本常量及运营配置/数据库/资源保持不变。
