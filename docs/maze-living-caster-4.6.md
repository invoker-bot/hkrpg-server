# 普攻与秘技的存活角色预检

本次修复 `SceneCastSkillCsReq` 在 4.6 实验入口和继承协议入口中的同一问题：当前阵容中的角色生命值为零时，原先仍可进入普攻/秘技执行路径，秘技还会扣除点数并执行施法动作。两条入口现在均在这些副作用之前调用角色对当前阵容的存活判断，返回参数错误，保留点数与生命状态。原有技能解锁、施法索引、资源能力名和目标预检仍适用。

新增 20 项回归覆盖两种协议、普攻/秘技、零生命、负输入归一化到零、最低存活生命 1、满生命 10000，以及超过上限的输入正常归一化。正确夹具中的八项死亡施法断言先失败后修复；相邻的原有施法预检和剧情试用技能锁检查一起通过 44 项。最初夹具错误地预期生命设置器保留负数和超过上限的值，这部分错误已归档排除，不能计为行为失败证据。单元场景和试用角色为组装夹具，未执行官方游戏客户端。

`scripts/smoke-maze-living-caster.py` 使用原始事件 305001、原始关卡 3050010 和正式角色 8001，通过实际服务进程的 4.6 KCP 入口接受构造的战斗生命报告，再检查实际当前状态的施法行为。报告的错误战斗 ID 与重复结算先后拒绝；零生命下普攻/秘技拒绝且没有点数通知；重新接受满生命报告后，两种施法成功，秘技仅扣一个点数、发送一次点数通知。这里的报告是构造测试数据，不是客户端战斗输入回放或原版复活机制的验收。

正常关服后的 H2 检查读取实际 Player 和 GameAvatar 各两次，确认死亡状态确实保存为零；重新登录后现有普通世界规则会把死亡队长恢复至 2000，该规则属于既有实现。探针再次通过新的已接受战斗报告产生零生命，检查拒绝路径，再用新的满生命报告恢复合法施法。最后一次进程重启保留满生命和剩余点数。三个正常 stop、两次同 UID 重启、三份 Player/Avatar 双读均不直接写入 H2 状态。

每份源码的最终验证预期为 51 次请求、36 项检查和 2254 份输入 SHA 不变；同时复验银河大乐透的商人、物件、通知及正常恢复，防止当前生命检查误拒绝损毁后仍存活的角色。两项外部探针的请求计数现包含结尾用于报告的六次状态查询：此前银河大乐透报告的 48 次表示这些查询之前的流程计数，完整计数为每份 54 次；旧封存报告保持原样，后续报告记录校正范围。

完整构建、独立源码及最终同产物网络检查见 `build/maze-living-caster-verification.json`。两条受测入口的行为通过不等于全部战斗动作或剧情已完成。真实 4.6 客户端表现、官方输入回放和异常终止的原子恢复仍未验证；功能目录保持 `partial`。
