## 原始来源与本机字段

原始资源固定于 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。九条 `RogueAeon`、十八条基础/强化组、六条解锁定义与六条 `FinishWayRogue` 完整保存在测试夹具中；读取前核对安装资源与 Git 原始 blob 的 SHA256 和 JSON 内容。相关二十五条递归祝福组及一百四十三条原始祝福行另存完整夹具，保留 `RogueBuffTag`、`AeonID`、`BattleEventBuffType` 等原始字段。

本机国服 4.6 `GameAssembly.dll` SHA256 为 `8cc7380066343b6152069a6d1c90e230322aa78b780b1e738c13185b3692f1d3`，元数据 SHA256 为 `09ce2093b78779d4bbe9dc866bb472438efd96cc6546b7cbc34edf4006736130`。二十个完整 PE 函数共 7378 字节、函数范围、原始字节与 SHA 保存在 `rogue-aeon-catalogue-4.6.json`。原生 `RogueAeonType` 枚举及六个响应结构身份已匹配；原生 `RogueBuffRow` 的三个独立编号与战斗事件类型字段另有只读元数据证据。

`StartRogue` 默认传 0，`StartRogueWithAeon` 传额外命途参数；网络构造器发送命令 1805。其实例偏移 48 写入字段 10，偏移 52 写入字段 5。两项参数含义通过命名包装器和已有协议别名推断，再与本服正向流程核对；源 `.proto` 的偏移注释在此处与安装客户端不符，不能把偏移当作 wire 编号，也不能据此交换两个 wire 字段。

## 当前行为

查询按原始 `Sort` 返回实际解锁的命途。没有完成记录时开放存护 1、记忆 2、欢愉 7；原始任务 `8013106` 和 `8016105` 真正完成且未取消后，分别开放繁育 8、智识 9。虚构通关计数不会替代 `RogueKillMonster`；狩猎、毁灭、虚无、丰饶的四条原始条件暂时保持锁定，计数语义仍需核实。

选择只能在新局开始时确定。非零编号需要实际目录和解锁条件；未知、越界、未解锁及运行中覆盖请求均拒绝。字段重复、uint32 溢出、未知类型与截断在 protobuf 解析前拒绝，不扣费、不创建新局。默认 0 保留既有开局兼容。

`RogueRun.selectedAeon` 与实际局编号、暂停状态和队伍一同保存；旧存档缺失此字段视为 0。暂停、重连、正常 H2 重启保持原局选择；当前目录后来缺失不会改写历史选择。进入场景失败恢复原局与普通阵容，新局不会继承前局选择。实际回响强化数量尚未接通，响应保留真实的 0。

原始 `RogueBuffGroup` 子项是 Tag 或嵌套组。展开器按唯一一级、版本 1 的 `RogueBuffTag` 找到实际 `MazeBuffID`；重复 Tag、未知节点、循环或用 Buff 编号冒充原始 Tag 均不可展开。保留明确不带 Tag 的旧定义兼容。普通战斗奖励按事件类型排除回响、回响强化和交错，不能随机发放尚未挣得的回响。
