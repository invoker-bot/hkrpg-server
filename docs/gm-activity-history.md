# 历史活动目录与独立复刻周期

本批补充 1.0–4.6 的 31 个版本、208 期游戏内活动索引，支持版本、期次、名称和编号搜索，以及本服起止时间和一键复刻。**索引覆盖与玩法完成分开计算：当前开放 29 期签到、2 个材料提交活动和 2.6「音律狩猎忍法帖」的独立复刻；2 期因缺少面板排除，其余 174 期仍需对应资源或接通玩法，按钮保持不可用。整个历史活动补齐请求尚未完成。**

## 使用

打开 `/gm` →「活动管理」→「历史活动复刻」，选择版本和期次，搜索并查看详情。可复刻条目支持立即开放 1–365 天，或设置明确的本地开始和结束时间。历史原始日期与本服时间分别展示。每次「一键复刻」创建新周期；「关闭本期复刻」「按原周期恢复」保留该周期的时间、进度与领奖记录，不创建新周期。

复刻全服生效，无需选择玩家。保留原始等级、任务与入口条件；签到天数由真实登录登记，查询不会增加天数。相同模块的活动同时只启用一个版本，切换前后的周期各自保存。玩家须重新打开活动页面获取新周期；旧页面的领取或材料提交请求被拒绝，防止把旧操作记到新周期。

「原始资源排期」页保留既有资源目录和启停。它仅管理排期，不能作为全部活动可玩的证明。

## 来源与排除

历史事实来自 [BWIKI 活动一览](https://wiki.biligame.com/sr/活动一览) 及各条目的来源链接，只提取名称、版本、时间、分类，不导入文章内容或参考项目代码。固定来源 240 条，筛除 30 条网页活动和 2 条 4.7 活动，剩余 208 条；这是当前固定索引的覆盖范围，不能据此断言官方没有其他历史活动。

`scripts/data/gm-activity-history-web.json` 固定事实与摘要；`scripts/generate-gm-activity-history.py` 离线生成 JAR 内档案。期次按已有、核对过的版本跃迁换期日期与活动开始时间分类，原活动「第 N 期」保留在名称中；分类不冒充官方活动分期。显式对应在 `gm-activity-history-mappings.json` 留存依据，名称存在歧义时不猜编号。

当前资源固定为 TurnBasedGameData `724b139d8c9c32d12552eb95745a4fee72bfe48b`。按用户决定，已确认缺面板的条目不复刻：

| 历史活动 | 原始活动 | 4.6 证据 |
| --- | --- | --- |
| 1.1 实验助手请就位 | 30005 | ActivityConfig 保留材料模块，但没有 ActivityPanelID，ActivityPanel 没有此面板 |
| 2.0 匹诺康尼美食庆典 | 30009 | 同上，原始提交项 101–107 尚在，缺少明确的活动面板入口 |

博物馆、地城探宝、杯中逸事等仍保留面板及玩法表，只能列为待接通，不能按「资源移除」排除。待对应的歧义记录也保持待核对。

## 进度与奖励

`Gameplay46.json.activities` 的目标模块携带 `replayId`（本次请求 UUID）和 `replayKey`（固定历史身份），`activityReplayRuns` 保留复刻档案。严格验证整份配置、备份原文、原子保存后发布。重复请求沿用原操作结果，不生成第二周期。停用后重启保持停用；恢复沿用原 UUID。

玩家 `GameplayState.activityReplays` 保存各周期签到天数及材料提交收据。原 `activityDays`、`materialSubmission` 和全局旧领奖账本保留；新的领奖键带周期 UUID。材料提交继续核对真实持有材料、按原数量扣除、保存预留与完成收据，再领取原始奖励。未决预留保持待对账，不自动重新扣费或补造完成。

材料活动 30011「寒腿叔叔的小店」对应原始 201–207 七单，30014「圣城鉴宝」对应原始 301–307 七项，两个状态和奖励命名空间独立。请求范围在保存期间冻结周期；GM 同时换期不会把处理中请求的进度写入新周期。原始 30014 的资源指纹与存档格式保持兼容。

2.6「音律狩猎忍法帖」50022 的 27 关、编曲、演出报酬 5 和 20 个原始限时目标各自进入本周期命名空间。原有剧情和地图解锁条件继续保留；原剧情完成记录可满足本轮剧情条件，不宣称重新演出剧情。最高难度继续要求本轮普通/困难关的真实评级。具体来源、费用、领奖和测试边界见 [音律独立复刻](music-activity-replay-4.6.md)。

## 可重复验证与边界

```powershell
python -m unittest scripts.tests.test_gm_activity_history
python scripts/generate-gm-activity-history.py --check
powershell -File scripts/build.ps1 -TestForks 8 -RerunTests
python scripts/smoke-server.py
python scripts/smoke-gm-activity-history.py
```

先失败回归覆盖历史接口缺失、复刻共享旧签到进度、复刻材料未重置、保留的贝洛伯格七单被拒、遗漏已领奖天数，以及同面板混合周期未拒绝。定向测试检查两个独立周期、七次真实登录日期、七单顺序/消耗/防重、旧存档保留、旧页面拒绝和关闭/恢复。

原生脚本使用独立端口、真实 KCP 和隔离 H2，执行签到两周期、材料原版及复刻共五轮/35 单，并核对材料和奖励的实际变化、重复请求及同 UID 正常重启。前置等级 21 和主任务 1000510 只由源码内的测试命令设置，命令仅编译进隔离探针 classpath，不进入生产 JAR；不宣称验证了这些前置剧情。可加 `--browser-pause` 验证 GM 页面。

已有 Chrome/Playwright 验证 GM 页面身份、非空内容、无错误覆盖、业务异常、桌面/手机截图，以及版本筛选、搜索、空状态、分页、自定义时间、取消、关闭和恢复；Browser 插件不可用。GM 网页验证与服务器原生回归不等于真实游戏客户端完整进入、演出和玩法验收。未推送、未部署，运营数据和常驻服务未用于测试。
