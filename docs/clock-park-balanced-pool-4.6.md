# 4.6 钟表小子版本化普通牌组

新局的明确本服默认规则为 `hkrpg.clockpark.cards-1001-1007-1008.v2`，发出原始卡牌1001、1007、1008。1001按骰面增加A，1007增加A/B，1008增加B/C；仍读取固定来源的Card、CardAction、Effect和Const完整文件，并按每个原始剧本的属性上限限幅。这使201的原始211检查点B≥30有正常通过的路径，不保证每局通过，也不修改条件。官方回合抽牌分布尚未核实，此固定牌组是本服规则。

每次开局将牌组规则保存到本局的poolPolicy，正常回合、检查点、章节历史、抵达证明、失败证明和结局证明均按该规则重放。没有poolPolicy的旧记录继续使用1001/1002/1003的v1规则；没有nextCardPool的新字段使用构造默认值，仅影响之后开局。显式null、未知规则、cardPool与规则不一致，以及使用另一套效果重放得到的属性不符均拒绝，不通过查询修复存档。

存档内的未来牌组偏好与已开始的本局规则分开保存，变更偏好不会重写已有回执。当前没有运营命令或客户端设置入口用于修改偏好。协议仍使用现有卡牌槽位和1至6的实际骰面字段，未修改命令号、151份协议快照或生成类。脚本2进入202时沿用属性、UUID及本局牌组，先确认原始20201剧情，再继续原始普通回合。

新增27项Java回归覆盖重排卡牌与不同/重复骰面、原始三属性效果和211通过、外来旧牌组拒绝、未来偏好与当前局分离、跨章、旧STORY/DICE缺字段恢复、五类损坏规则、保存回退和六路并发。七个阶段各两次实际Player/Morphia读取，另以实际旧Player BSON删除新增字段后读取两次，核对查询没有写回。最初三项中两项真实断言先失败；最早编译失败的夹具尝试不计入生产缺陷证据。

`scripts/smoke-clock-park-balanced.py`从活动入口开始，使用真实服务器随机骰面与新默认牌组，按原始条件完成211。未通过时走真实无奖励失败结算，再在有界次数内重新开局；通过后分别正常停止并恢复CHECKPOINT、BRANCH、202剧情、202骰子及已放置回执。每轮均试验外来1002请求和重放，核对完整等待响应未变化、实际属性公式、原始章节抵达和无结局物品/进度。夹具只写等级/原始关闭前置记录及活动窗口，不写骰面、属性或通过标志。

旧opening/dice/checkpoint/branch/ending/failure原生夹具明确将下一局规则固定为v1，以保留各自历史验证范围；它们不能代表新默认牌组。新balanced夹具不设置牌组字段，独立读取真实保存的v2规则。来源资源、运营配置、钱包和正式阵容逐次核对。完整双源码构建、合成KCP/H2恢复与旧结局/失败回归以`build/clock-park-balanced-verification.json`为准。

仍为部分实现：更多分支/结局、电影/射击/抽奖、官方发牌、完整剧情脚本、Buff/天赋/无尽与实际游戏客户端UI尚未完成或验收。正常H2停止/恢复不证明断电原子性。
