# 回响菜单与奇物取得的首次保存

此前商店购买火漆、购买会替换为火漆的骰子以及大乐透取得火漆，会先保存奇物/付款/收据，随后在通知阶段建立应得回响菜单。直接取得普通奇物还存在没有保存实际归属的分支；骰子同时强化祝福时，也可能先保存强化而后保存菜单。

现在奇物商店的两条购买路径、大乐透奖励提交和直接取得均在首次 Player 保存前建立应得回响菜单。付款、已购买标记、取得 UUID、普通祝福、强化计数及已有收据随同当前玩家状态保存，然后发布通知。`Acquisition.syncEffects` 只发送相关通知与既有进度事件，不再建立菜单或替调用方补保存。奇物选择原有的“清空待选后建立菜单再保存”顺序保持一致；骰子预览仍不修改实际玩家。

`RogueResonanceTransaction46Test` 新增八项回归，初始五项已用实际断言复现缺口。测试在首次 save 快照之后主动抛出异常，分别检查商店火漆/商店骰子/直接普通奇物/直接骰子强化组合/大乐透奖励；五种完整 Gameplay 快照各经过两次实际 Player/Morphia 读取，核对菜单、归属、余额、取得收据、祝福、图鉴及强化计数。另检查两条正常商店路径只保存一次、选择回响后不能重购，以及直接奇物重复取得不保存。最终证据见 `build/rogue-resonance-transaction-verification.json`。

来源使用已有固定提交的原始回响、奇物、效果、600000 的两个祝福等级和 MazeBuff 记录。单个可取得火漆祝福、限制到 22 或 20/22 的原始奇物候选池、300 碎片、合成商店/物件放置和受控大乐透 UUID 为明确单元资格夹具；不代表官方随机分布、原版事件触发或真实游戏 UI。第一次编译使用了不存在的 ExcelMap.remove，后续新增正常用例缺少 Retcode import，两次编译错误不计行为 RED。首次绿色检查中余额原先误写成“已有 100 再加 300”，现夹具显式设为 300；五项原始菜单/缺保存 RED 不依赖这处后续余额断言。

这修复一次玩家文档保存前的状态准备，没有证明真实断电写入原子性。完整回响能力、全部宇宙/剧情/日常/活动和国服客户端验收仍为待完成。原始怪物战斗的能量网络证据另见 [能量报告](rogue-energy-network-4.6.md)。

首次全量运行的失败均来自旧测试把准备阶段奇物取得的保存次数也计入目标操作，再断言绝对 0/1/2/3 次。直接取得现在确实保存，这些检查改为取得之后记录基数，继续严格断言非法领取不增加保存、菜单/修复/复活通知之前增加规定次数；没有取消通知顺序或防重断言。这些旧基数调整不计入五项行为 RED。

最终全量 Java 8433 项（347 个测试类）、Python 198 项及独立相邻回归 80 项均通过；2615 份交付文件和 151 份冻结协议快照核对通过。当前产物 SHA256 为 `a662e4b30554c53381ba3eb199cff429affe2c55d7dac128fcad6e0f3761944e`。同一产物另通过重入恢复 56 次请求/64 项检查、大乐透 54 次请求/30 项检查及 HTTP 账号重启恢复。大乐透为已有受控普通奖励路径复验，新火漆取得的首次保存窗口由前述单元断点覆盖。
