# 密集账号创建与旧账号保留

验证全部 32 个经典宇宙区域时，旧 Snowflake32 每秒仅使用四位序号，却用可溢出的 byte 不断递增。密集创建跨秒时不同账号能获得相同 ID；原来创建账号调用保存/upsert，覆盖了已有账号及其令牌，后续真实 KCP 登录被拒绝。

两项实际分配回归分别复现序号回退和第 256 次重复 ID。真实 Mongo/Morphia 第三项回归预存后续 ID，新增账号后记录数仍是 512 而非 513，确认覆盖已发生。对应行为证据保留在 `build/account-id-burst-behavior-red.xml` 与 `build/account-id-overwrite-behavior-red.xml`，与网络探针超时记录分开。

分配器保留原有正数格式和时间解析，16 个槽位用完后保留下一逻辑秒；时钟回退继续分配未用槽位，数值范围耗尽时拒绝，不绕回旧值。新账号通过 Mongo 插入，ID 冲突时重新分配，用户名冲突则保留原账号。并发登录的第二次查询读取已经创建的同名账号。已有账号及令牌更新继续使用原有存储路径。

14 项 Java 检查覆盖真实分配密集请求、逻辑秒与回退、边界拒绝、格式兼容、2,048 次并发分配、512 个已存账号全部身份/令牌/权限/预留玩家 ID 保留、24 次同名并发创建，以及 48 个实际创建账号的令牌不被后续创建覆盖。没有迁移或重新编号既有账号，也没有自动恢复在旧问题下已被覆盖的记录。

全量构建后，全部 32 区域的独立 SDK/游戏账号、通用 4.6 服务及 Dispatch/正常重启验证使用同一最终产物。具体结果以本批 build 认证报告为准；这批没有改变登录认证条件、加密或真实客户端验收状态。

最终根产物和独立源码产物的 32 账号矩阵均通过，各 896 次 KCP 请求及三次正常停服后的 96 份玩家记录恢复通过；通用登录与 Dispatch 重启检查也通过。认证记录位于 `build/rogue-boss-levels5502-verification.json`，保留所有失败原型与行为回归，不将它们计作成功探针。
