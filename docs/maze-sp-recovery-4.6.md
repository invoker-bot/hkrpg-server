# 4.6 探索能量回复

停云原始SP叶现在读取技能120207的一级 `SkillMaze` 参数0，以及施放者角色表的基础 `SPNeed`。原始参数为50、基础上限为130；本项目存储的能量条是0..10000，因此单次增量为 `floor(50 / 130 * 10000) = 3846`，而不是固定5000。满能量、零增量不重复保存或通知，超大有效增量先封顶再转换整数。

`MazeRecoveryValues.spRatio` 仅接受明确SP类型、精确的 `TargetAlias/Caster` 选择器、缺省/明确 `Add`，以及非负固定 `ModifyValue` 或停云限定动态绑定：角色1202、`LocalPlayer_TingYun_MazeSkill`、单一哈希457361642与 `AQAR`，技能必须出现在实际角色 `SkillList` 中。参数缺失、错误触发键/攻击类型、未知表达式和目标、额外比例或其他运算均不补默认50。基础容量缺失、为零/负数、字符串或非有限数不能参与换算。

原生静态证据见 `client46-maze-sp-evidence.json`。本机 `AvatarDataComponent.ResetAvatarProperty` 的普通能量分支，实际从 `ICharacterRowData` 类型槽/方法10读取 `SPNeed`，用 `FixPoint.op_Multiply` 与 `op_Division` 计算输入量×容量/输入基数，再设置已核对枚举 `AbilityProperty.CurrentSP=12`；普通上限为11，特殊能量另用13/14。方法来自固定客户端SHA并覆盖其unwind范围，参数类型也独立读取。

**验证边界：**普通能量初始化公式已静态核对，网络数据到全部初始化参数的赋值链和探索能量任务执行器尚未完整核对。把 `ModifyValue` 解释为绝对单位、以及停云SkillMaze参数0的绑定，仍是原始任务/表行、字段区别和本机记录共同支持的受限推断。源记录包含正确角色名、技能名与单哈希/SkillMaze0字节，但整个字符二进制和表达式解释器尚未完成。容量修饰器、特殊/额外能量、原生取整和完整原始秘技不在本次支持范围，不声称真实客户端已验收。

回复在玩家锁内核对实际施放者对象仍属于当前队伍，只修改该施放者能量。正式角色沿用角色保存，剧情试用角色沿用自身保存规则，宇宙独立生命/能量仍保存到当前局；完成变化后同步实际当前队伍。保留既有Java百分比构造函数供插件使用，资源任务不再走该默认构造函数。
