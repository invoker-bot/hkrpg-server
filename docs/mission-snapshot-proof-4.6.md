# 4.6 任务查询和同步的记录校验

服务端前置已拒绝损坏完成记录，但Gameplay46的查询和同步仍仅按phase不等于DOING输出完成，导致空阶段、时间/目标进度不符或错编号可能被发送为完成。MissionSnapshotRecords现在先核对完整快照：主记录的存档键、编号、阶段、时间和目标1一致；已知子记录还须有结构有效的父记录并符合其原始有效目标。空键、错键、空阶段、非法时间或进度不能进入成功快照。

GetMissionData在异常记录时返回PLAYER_DATA_ERROR及空数据列表，刷新前先预检，不补造进度或借查询完成任务。GetMainMissionCustomValue对实际存在的请求主记录先预检，失败不发送半份变量列表。PlayerSyncScNotify的任务部分出现异常时不发送，避免无返回码的MissionSync假报完成。快照构建持玩家锁，验证和读取使用同一份状态；不修改存档、完成时间、取消标记或奖励。

这里核对的是结构有效的只读历史，不能代替MissionStateRecords的游戏资格判断。已取消但结构正常的历史保留既有查询表达，不因此恢复前置/奖励资格；本批未新增客户端取消状态或删除通知。来源缺失或负目标的DOING记录保留合法的既有进度，不能凭其状态显示完成；缺少子目标定义的完成记录不能通过预检。正常FINISHED/CLAIMING/CLOSED历史保持原生完成字段，旧目标0按有效目标1读取。
