# 普通 NPC 的客户端归属与任务组切换

## 现场和原因

用户在主控舱段洛奇旁看到两个同名交互项，且完全退出并重新打开游戏后仍可复现。用正式存档的只读任务状态、实际运行包及完整楼层的原始组重建，G5 主线、G6 特殊任务和 G31 常驻组均未加载，只有 G18 支线组有洛奇（10106/400001）和伯纳德（10403/400002）。4.6 转换后的场景快照各有一份该组 NPC。重建是隔离诊断，未连接或代替操作真实客户端。

同一客户端的 G18 原始设计数据已完全解码，人物编号、任务条件及归属字段与服务器来源匹配，NPC 坐标和朝向只有 JSON 小数显示精度差异。客户端原始记录未写 `LoadSide`，构造函数 `RtLevelGroupInfoBase` RVA `1da323e0` 和 `RtLevelGroupInfo` RVA `1da31530` 保留该字段的零值 `Client`。`LevelNPCInfo` 构造函数 RVA `1d787c80` 将偏移 `0x60` 的人物 `LoadOnInitial` 写为 true。G18 在「致：黯淡星」接取后由客户端加载。继承的 Java 资源模型将省略值当作 Server，也曾通过场景报文下发同组 NPC。G18 洛奇的对白主图只含一个 `ShowMenu` 节点。

2026-11-05 安装归属修复后，用户重新登录仍看到两个「洛奇」。服务已运行修复包，游戏进程沿用安装前的一次启动。以复现时存档重建完整楼层，服务端仅保留 G18 的逻辑洛奇，实际 4.6 场景快照的 NPC 列表中已无洛奇。G5 主线版和 G31 常驻版与 G18 的站位相近或相同。G5 由主任务 1000302 完成退场，G31 由 2000110 接取或完成退场。

后续核对发现初次进图和当前场景查询均遗漏 `SceneInfo` 字段 1284。原生客户端的 `AdventureModule.EnterMap` 在进图准备中调用 `_EnterMap_SetupMissionModule`（`c5db6c0`），读取 `KHNBFDNKLHE+0x28` 的 `KKODEADFMJM`，调用 `_UpdateMissionStatus`（`d6f8570`）将完成标记应用到主任务实例。`KHNBFDNKLHE.WriteTo`（`1e81ced0`）将该位置序列化为标签 `a2 50`。子对象的 `CalculateSize`（`1e84e4d0`）与 `.cctor`（`1e84e9c0`）交叉核对出字段 15 为已完成主任务，字段 3 为未完成主任务。客户端普通本地组的 `IsLegacyGroupCanLoad`（`e073b90`）和 `IsLegacyGroupCanUnload`（`e073e20`）按这些任务实例判断。登录快照的静默完成历史不能代替进图时的实例更新。

## 修复范围

保留客户端 4.6 原始运行时普通组的归属来源；仅处理明确初始启用或具有原始加载条件、未指定服务端归属、无任务专属组所有者的普通组。在默认大世界的原生 4.6 报文中，按实际场景、组、实例和 NPC 编号识别原始客户端人物，抑制重复的全量实体和增删消息。纯本地人物组的空快照或空刷新不下发组条目；混合组的机关、状态、属性和确需服务端发布的实体继续同步。

任务加载条件、逻辑 NPC、对白和距离校验仍使用原场景与存档。显式服务端角色、其他合法站位、程序创建的角色、气氛/任务专属组、非默认维度或剧情场景、旧 4.2 协议保持现有规则。缺少初始启用或任务激活证据的普通组也保持原行为。范围是已核实的重复加载类型，其他原因的重叠需要分别定位。

进图与当前场景查询同时投影当前场景客户端普通 NPC 组原始加载或卸载条件引用的主任务和子任务，包含服务端已经判定退场的组。状态沿用任务资格校验。子任务仅发送有合法进度的有效记录，已取消、损坏或随父任务完成而退场的未完成目标不会被同步。全量任务查询仍由原入口处理。此实现依据本机固定 4.6 原件，未引入参考实现代码。

对默认维度登记的普通世界资源做静态盘点，8 个世界共 237 个组、668 个初始 NPC 放置符合来源形状。与本机客户端的固定设计数据索引交叉核对，235 个组完整读取并匹配归属、加载条件和人物编号，其中 P10501/F10501001/G645 按楼层声明的 `RuntimeGroup` 路径读取。剩余两组的机关或场景脚本尚未完整解析，但均核对了归属字段和人物放置：P20421/F20421001/G106 的唯一匹配 NPC 列表可从已核实字段解析到记录末尾，P20502/F20502001/G101 的 NPC 列表已在脚本字段前完整读取。具体角色何时加载仍由原始任务条件决定，静态核对不等同于这些地点都已实机复现或验收。证据见 `world-npc-source-catalog.json` 及 `world-client-*-audit.json`。

## 伯纳德的监控任务站位

「致：黯淡星」的两个连续步骤 200011018 和 200011008 都显示「据监控影像指认幕后黑手」。主控舱段监察域锚点旁的原始 G16 含伯纳德（10403/400001）和第一段对话入口（300001）。G16 由客户端加载，要求 200011007「前往监控室察看幕后原委」完成。现场存档的 200011007 已完成，200011018 正在进行。原运行包具备 G16 的逻辑人物，但进图和当前场景响应的 1284 字段只同步主任务，遗漏了这条子任务状态。
