# 4.6 普攻弱点入战日常

原始日常 `2100123` 要求三次、`2100142` 要求一次 `ExcellentEnterBattleAndWin`，各领取原始奖励 `103002` 的道具 `23` 活跃点 100。两项现在可进入服务端日常池，通过实际普攻入战与成功结算推进，达到目标后由领取请求发放活跃点。状态仍是部分支持。

当前采用明确的项目判定：实际当前场景的已持有角色，以普通攻击（客户端请求 `skill_index=0`、原始技能解析后的服务端编号为 1） 命中实际存活主目标；主目标对应原始 `StageExcel` 首波至少一只怪物的 `StanceWeakList` 包含角色攻击属性，并且战斗实际绑定相同属性的入战增益。必须使用当前加载的原始关卡、怪物和入战增益定义。助攻列表单独命中的弱点、怪物伏击、直接关卡入口、秘技、无视弱点标记、缺失或损坏定义不能借此记分。这一判定不是已经逆向还原的官方 `Excellent` 完整判定。

入战时冻结本次战斗、当天日期和已接取目标对象；只有服务器接受相同战斗的胜利结算后消费一次。错误战斗号、失败、退出、重复或并发结算不增加进度；换角色、修改资源或换入新的任务对象也不能追认入战。跨 04:00 日常边界不将旧战斗转移到新一天。目标计数与已经领取的活跃点持久化，活动中的战斗证明只存在内存，不提供进行中战斗重启恢复。

固定来源 `TurnBasedGameData` 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。测试夹具保存 18 条完整原始记录、完整三月七技能文件和十份完整源表的资源 SHA256、Git 原始内容 SHA256 / blob SHA1。单元测试将原始 NPC 与关卡明确组合成隔离场景，并使用简化演员与无掉落服务；这不是原始场景脚本的完整演出。运行实现新增读取怪物弱点字段，不修改生成协议类、命令号或版本常量。

40 项行为回归已通过，其中最初三项隔离日常选取/普攻胜利断言和一项原始技能解析后的胜利断言先失败、随后修复。实际原生首轮验证还发现客户端编号 0 与解析编号 1 混淆造成真实战斗漏记；已用完整原始技能文件重现并修复，不能用仅有抽象技能替身的通过结果代替这一检查。覆盖三次与一次目标、两次各 100 活跃点领取、防重、实际主目标和助攻区别、入战前后角色变化、失败/退出、24 个并发结算、跨日、替换目标、损坏资源和恢复资源、三个实际 Player/Morphia 阶段各两次读取。测试开发中的 Gson/初始化/编译及结果对象类型错误不计为行为先失败。测试不证明保存故障或断电的原子性。

原生网络夹具入口为 `scripts/smoke-daily-weakness-entry.py`。它使用原始第一世界 110 / 地图 101 / 房间 304 / 组 18 的加权怪物和正式角色 8001，在独立目录运行；四个无奖励前置图与只含这两项原始记录的日常池是明确隔离条件。源怪物波次、弱点、增益、任务与奖励保持原样，进度和活跃点不直接写入。验证流程包含实际普通攻击、错误结果拒绝、三次获胜、两项目标领取、防重、重连与正常 H2 进程重启，并由只读实际 Player/Morphia 检查器核对存档。修正后的候选产物已通过九个网络阶段、107 个请求、四次正常停止和同一 UID 三次正常 H2 进程重启；四个存档阶段各使用实际 Player/Morphia 读取两次，源码资源 2266 份 SHA 保持不变。三个独立来源关系检查及 168 项 Python 检查通过。全量构建与最终同 SHA 产物复验另记于忽略的 `build/` 验证产物，执行完成以前不视为通过。并行 Gradle 造成共享构建输出冲突的一次验证已作废；网络探针第一次漏发 LeaveRogue 的退出顺序错误亦不计为游戏行为缺陷。

尚待补齐：官方判定的完整客户端证据、秘技和特殊入战动作、不同关卡动态弱点、所有剧情/玩法中的语义适用性、真实游戏 UI 接受、进行中战斗重启与断电事务恢复。合成 UDP/KCP 和正常停止后的 H2 重启不代表这些边界已经完成。
