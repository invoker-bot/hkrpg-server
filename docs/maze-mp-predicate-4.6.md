# 4.6 探索技能秘技点条件

`AdventureByCompareMP`现在读取实际施放者当前队伍的秘技点，支持资源中六种明确比较类型、有限浮点阈值和布尔`Inverse`。它可以独立使用或嵌入已有`ByAnd`/`ByAny`条件树。包含MP的整树在玩家锁下取得一次队伍快照，再在角色效果锁下取得同一时刻的效果状态；释放锁后才执行动作，不缓存第一次判断。

本机客户端的类型24280、方法138032和字段103506/103507已经核对：`CompareValue`是R4浮点字段，构造函数`0x1d38ac10`只设置基础启用标记后返回，未指定阈值保持0。`CompareType`的0值为`Unknow`，因此缺失比较类型不默认为相等。有限阈值按原生浮点精度读取；字符串、表达式对象、无穷值、未知类型和未解释字段不执行任一分支。证据见`client46-maze-mp-evidence.json`。

缺少玩家、施放者不属于当前队伍、施放者身份不匹配或秘技点越界时，条件返回“不可判断”，成功和失败列表都跳过；反向和组合条件不能把不可判断变成成功。普通队伍和剧情独立队伍使用各自当前数值。已有公开的效果条件构造器及效果任务入口保持兼容。

固定提交`724b139d8c9c32d12552eb95745a4fee72bfe48b`中的银狼新形态`OnStage`原始任务完整保存在`src/test/resources/fixtures/maze-mp-predicate-4.6.json`，它声明`LessEqual`且省略阈值，成功分支销毁施放者的召唤物15061。测试显式创建原始配置召唤物并调用这条任务：0点销毁，1/5点保留；技能复用、攻击和命中分别重查。此测试不是完整修饰器生命周期调度，也没有启动真实游戏客户端。

新增33项Java回归，首批28项中21项修复前真实断言失败；随后5项验证实际反向、剧情队伍隔离及原生浮点精度。原始自动使用恢复道具、其他动态变量、所有修饰器事件、移动/距离/投射物及完整技能链仍待实现。既有含自动恢复判断的原始组合树继续拒绝直接执行成功叶。

继承核心的施放入口另补16项回归，修复前7项真实断言失败：缺少场景、已有战斗、非法技能索引、不存在的施放者、缺少秘技和秘技点不足，均在扣点、动作及通知前拒绝。4.6原生入口原先已有这些检查；这里对齐继承入口，并验证普通攻击在0秘技点时继续可用。未改动151份冻结协议、客户端文件或运营数据。
