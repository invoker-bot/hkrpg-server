# 4.6 支持日常委托未完成换日

登录和任务查询沿用国服04:00日界，新增已支持纯对话/内部子任务汇总图的未完成退场。原始3000201当天未做或只完成四段对话时，下一日先保存旧主任务、子任务、原始目标、动作游标、接取日和退场时间，再创建实际新轮，第一段进度为0。旧图没有变成已完成，没有发放5000信用点或200活跃点；旧汇总进度不能推进新轮。

参考hkrpg-go的GetCurDay/DelDailyTask在换日时清理旧委托并重新抽选，固定提交ef47e49a233133c46d70ab5a4deb4bc71ae49571、AGPL-3.0，路径gameserver/model/db_base.go。这里使用独立Java实现，将旧记录归档而非丢弃。04:00边界沿用本项目日常规则，安全图限制与保留历史是本项目政策，不宣称官方完整过期语义。

只有来源Daily主任务、单个有效进行中视图、明确旧接取周期、已支持图、子任务奖励0及无支付/奖励挂起记录才退场。缺失日期、复杂变量图、多个进行中视图、坏归属/日期、CLAIMING、待执行动作、已有冻结主奖励及异常分组都保留，不能推测它们已经过期或结算。旧轮归档与新轮分配同属玩家锁和保存流程；过期前后的查询不重复归档，未知旧存档不补造日期。

新日到达后，已知旧纯图的末段对话和再次接取在修改记录之前拒绝；任务查询才将安全旧图归档并分配新轮。已归档同编号的下一轮使用周期奖励键，保留更早已发奖励的原键/收据。新轮实际完成原始五段对话和三项汇总后发放5000信用点，2100003实际领取200点且防重；已发轮、过期未付轮和新付轮各自保持证明。

归档损坏时当前支持图的对话在保存前拒绝，缺失周期容器/映射的手动接取返回数据错误，不抛异常、不创建任务。已有已结算归档的拒绝码保持兼容，没有为了新检查修改旧拒绝结果。旧自动分配测试从“当前旧图保留”更新为“旧对象原样归档、新图独立创建”；未知日期与复杂图仍有不清除回归。

新增30项Java检查；原实现17项中的9项行为断言先失败，归档证据第二轮27项中的10项断言先失败，合计19项。编译阶段误用游标方法、接入期间九项旧拒绝码变化，以及新增消息检查把枚举当整数的失败均不计数。固定49条沿用原件/14份来源，包括3000201完整图、三候选目录、5000信用点与200活跃点奖励；24路并发、12次无额外保存查询、实际Player文档两次Morphia恢复和冻结4.6任务查询字段已验证。
