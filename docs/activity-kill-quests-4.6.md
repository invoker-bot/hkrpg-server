# 4.6 原始活动击杀目标

本批接入活动 30013、模块 3001301 的五个原始非周期目标 6029841 至 6029845。三个主线前置的历史、活动开放窗口、测试队伍和隔离场景位置是验收夹具。完整活动二十项目标、真实客户端操作和战斗演出仍未完成。

来源为 TurnBasedGameData 的 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。结束条件为 `KillMonsterInGameModeList`，按原始 `MonsterTemplateID` 分别累计 4012010、4012020、4012030、4012040 各三次及 4013010 一次；变体使用原始显式映射，不通过数字除法推断。计数上限合计十三次。源表、关卡组与地图原件记录在测试夹具；来源只作为数据核对，不引入参考项目运行依赖。

本地客户端元数据确认 `GameModeType.Maze=2`、`Raid=8`，与服务端 `PlaneType` 数值不同。客户端死亡枚举只确认数值 0 至 3；本批沿用既有任务与宇宙统计策略：胜利结算中来源 1、2 可计数，0、3 不计数。这不是对死亡枚举语义或实际战斗过程的完整还原。

入战冻结当前玩家、任务接受记录、窗口、场景、故事线、队伍及原始阵容。结算核对整个报送批次的实体唯一性、关卡、怪物和数量上限，重复结算不能累计。普通迷宫与仍有效的任务副本分别核对模式及副本运行；普通世界的历史保存不依赖旧战斗对象。该目标不统计败退、退出或入战外的即时击杀。

计数与来源收据先保存，再开始战斗结算。保存失败时恢复原保存域并保留当前战斗，允许重试。领奖复用已有保存预约与库存写入流程：中断的 `CLAIMING` 需要对账，当前跨文档库存并无事务保证。活动关闭后停止展示及领奖；经过完整来源校验的完成和已领奖历史分别保留供后续条件查询。

定向回归包含原始五项接取、原始阵容计数、空胜利、保存失败重试、恢复、显式变体、重复实体、阵容超额、其他关卡、死亡来源、窗口替换和前置撤销。旧实现三十二项中二十一项出现预期行为失败；补充八项资源、场景、接受记录和存档边界后，四十项定向回归通过。

隔离原生验证通过 136 次请求：在 20411 与 20412 两张原始地图，正式夹具角色实际攻击七个原始 NPC，核对每场原始阵容后报送合计二十八条死亡记录，形成十三条有来源的有效目标收据。七次重复结算均拒绝；五份原始奖励分别成功发放一次，合计星琼 100、信用点 60000、213 四个、233 四个、110202 六个，另独立核算正常战斗掉落。四次正常停服、同 UID 三次 H2 进程重启，以及活动到期后的只读恢复检查均通过。未预写活动接取、计数、完成或领奖结果。

地图只精简关卡组引用；相关整组原始定义没有替换、删减或放宽开门条件。地图位置、正式队伍、三个已领奖的主线历史及开放窗口是夹具。此次原生覆盖迷宫模式；任务副本模式的真实入口与击杀尚需专门验收。原生报送证明网络入口、服务端结算和存档，并未执行真实客户端 UI、动作输入、AI 或动画。

全量构建通过 12861 项 Java 检查、476 个测试类，零失败、错误或跳过；2416 个构建输入保持不变。当前构建另外恢复上一批时间轴活动的两份实际 H2 存档，四次只读进程恢复保留原有八项已领奖任务与二十四条来源收据，不重新发送旧原生请求。两组打包调度与 SDK 账号恢复、两项源码交付工具检查、3389 份源码交付文件及 151 份冻结协议校验均通过。385 份既有 Python 文件与前一提交一致；本批未重新执行完整 Python 测试集。
