# 剧情试用姬子首次打开角色页的兼容修正

## 原因与范围

用户确认：首次进入姬子光锥页显示 5 级「智库」，切到其他角色再返回后显示未装备。
装备列表打不开的协议问题已在 `8aee427` 修复并获用户确认，本次是独立的角色身份问题。

本服空间站剧情采用已认可的兼容预设 1011003：8 级姬子，自带 5 级智库。
原预设在客户端中属于 `TYPE_TRIAL`（1），普通角色页首次进入会使用这份试用数据；
列表切换则使用正式角色 1003。10001 正式姬子为 17 级、未装备，双方没有相互覆盖存档。

固定客户端 `AvatarMainPage.get_init_avatar` / `_get_show_avatar` 会过滤 `TYPE_PLOT` 剧情试用，
不会过滤这份普通试用预设。因而本次修正客户端中 **1011003/0 的界面分类 1→4**，
让它走现有剧情试用过滤流程。首次打开角色页将选择正常编队中的非剧情试用成员；
列表中的正式姬子继续显示她实际拥有的装备。

这是本服兼容映射的适配，不宣称原版预设错误，也不修改正式角色、试用战斗数值或服务器资源。
试用编号、等级、技能、属性、5 级智库及背包归属全部保留。

- 原生 `SpecialAvatarRow.FromBinary`：101594 / `1dacdc20`，完整核对 38 个字段。
  Type 位于掩码第 6 位、对象偏移 `0x5c`；不是凭 JSON 顺序猜测位置。
- `SpecialAvatarType` 的显式值为 `TYPE_TRIAL=1`、`TYPE_PLOT=4`。
  `CheckIsPlotTrial` 577051 / `c6d66a0` 读取同一个枚举组件并比较 4。
- Lua 原记录 `c56e7702f1d62cc2` 完整读取；角色页初始化和过滤函数留有直接条件分支。
- 固定 SpecialAvatar 记录完整读取 4,925 行，原始 SHA-256
  `e1b6600025248d35914aef36ac10b9e5e82aa07b08c7072c38f8c62a295802d9`。
  只修改记录偏移 18100 的一个字节 `02→08`（有符号变长枚举 1→4）。
  所有行在恢复这一枚举后与原表逐字段相同。
- 不改 GameAssembly、元数据、输入或网页组件，不向游戏加载 DLL 或执行引用仓库的二进制。
  修正依赖现有客户端界面逻辑；真实游戏效果须另行确认。

`scripts/patch-client-station-trial-ui.py` 默认在客户端目录外生成可检查的副本。
`--install` 要求正常退出游戏，核对固定程序/元数据与索引、原数据块、目标记录和预设后，
生成新的数据块，备份原索引，再原子切换索引中的数据块摘要。原数据块保留。
未知版本、已有不同内容、索引或数据块并发变化均拒绝；安装后核对失败会恢复本次已知索引。
`--restore` 核对固定版本后恢复原索引，保留未使用的新数据块，不删除客户端数据。

原索引 SHA-256：`5a5981c06b0d7d1cbff5f89b8450fefb40278c60a5ca10b092b3381094dfcbed`。
修正索引 SHA-256：`bcac71ed6783dfd447de127bdcab7c40ae4e21d488c39cba1af6ef6aa801b608`。
设计数据只读工具仅显式接受这一新增配置，原来的默认值与未知版本拒绝规则保持。
客户端缓存分类表，因此需要完整重开一次；仅服务重连无法加载修正。
