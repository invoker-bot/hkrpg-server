# 小小哈努控制组与存档恢复

本轮将关卡原文的控制状态接入实际场景和玩家持久记录。关卡3使用控制组156，原始 `GroupStateList` 定义1→2（变小）、2→1（变大），开始状态1、结束状态0。服务端只接受目录指定控制组及原文允许的转换；状态名称保留原始JSON值，不按名称推测完整变身脚本。

来源仍为 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。原始17关目录和关卡3的入口、楼层、组共23条记录、7份文件未改写。控制定义签名冻结组ID、名称及状态列表的SrcState、DstState、StateName；描述性Comment不属于玩法身份，后续已修正其保留并维持旧签名字节，见 [group-transition-comments-4.6.md](group-transition-comments-4.6.md)。签名不包含完整场景几何、物件或缺失的GroupGraph。转换引用的脚本仍未实现，不能由状态1/2证明角色模型、技能或碰撞已变身。

实际1466请求通过冻结的4.6 `GroupStateChangeCsReq`，1486响应保留原始字段。仅活动中的哈努原始控制组接入；其他组、结束状态0、非原始边、错误入口、额外交互值及坏字段拒绝。不是通用剧情机关接口。开始、退出分别写原文开始/结束状态；实际场景组和 `group-state:楼层:组` 持久记录同时更新，保存成功后才发布场景组状态通知。失败恢复旧记录、原组对象及活动身份，不发奖励。

存档记录当时控制状态和来源签名。恢复时，实际玩家位置、旋转和控制状态共同在保存前更新，随后返回客户端恢复响应；保存失败三者恢复，重复同坐标且同状态不保存。此前缺少控制快照的旧记录仍可读、仍可恢复既有坐标，不猜测或补写旧机关快照，也不允许其直接提交新控制转换。半缺失快照、来源变化、实际组与持久值矛盾都保留原值并拒绝。
