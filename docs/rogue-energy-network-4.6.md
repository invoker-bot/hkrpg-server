# 原始怪物遭遇的回响能量报告

经典宇宙保持 `partial`。本批增加可重复的自有 KCP 探针，验证已有能量结算与正常 H2 恢复；没有新增回响能力脚本，没有把合成报告当作游戏客户端操作或官方战斗结果。

`scripts/smoke-rogue-energy.py` 启动六次隔离 Java 服务，使用同一账号、同一局 UUID 与实际玩家存档。自有探针由实际 4.6 原生请求开始命途 7、重入、攻击原始场景怪物、报告结果和暂停。最终证据见 `build/rogue-energy-verification.json`；60 次请求、96 项断言、六次正常停止、五次同 UID 正常 H2 重启及十二次实际 Player 读取均逐项记录。

隔离首房池明确固定为原始房间 100。第一次正常停止后，仅一次资格写入种入原始基础回响 612620 和归一化能量 2500；这不是战斗赢得回响，也不证明官方初始能量。原始房间/放置怪物/关卡/波次不改，2254 份来源资源哈希逐份核对。所有资源、配置和 H2 写入位于 `build/smoke/rogue-energy-*`，不修改运营配置、数据库或安装客户端。

原始组 3 的 NPC 8011020 使用关卡 80010011，发送怪物波次 `[8011020, 8011010]`；退出后的再次入战仍是该未消耗怪物。胜利后下一原始组 4 的 NPC 8012010 使用关卡 80010021，波次为 `[8011020, 8012010]`。脚本独立读取原始 StageConfig 并严格核对全部波次。原始关卡等级为 7，发送的自定义等级为 0（继承代码省略覆盖）；此次没有验证客户端如何使用默认关卡等级，不能将默认值直接认作怪物等级 0 或凭猜测更改协议。

同一局的能量链如下：

| 实际请求 | 构造的事件报告 | 保存能量 | 结算检查 |
| --- | --- | --- | --- |
| `QuitBattleCsReq` | 7 / 40 | 1750 | 关闭本场，怪物保留，重复拒绝 |
| `PVEBattleResultCsReq` 退出 | 匹配事件但省略能量条 | 1750 | 保留原能量，关闭本场，重复拒绝 |
| `PVEBattleResultCsReq` 胜利 | 1 / 3 | 3333 | 消耗实际怪物，按既有规则归一化，重复拒绝 |
| `PVEBattleResultCsReq` 失败 | 0 / 100 | 0 | 本局进入 FAILED，重启后不能重入 |

正式结算前另外提交七种非法 PVE 统计：外来事件、重复事件、重复当前条、未知属性、无符号溢出、最大值零、当前值超过最大值。每次均拒绝，随后查询仍是同一个未消费战斗及原能量；合法报告仍能结算一次。报告只是探针构造的消息，没有复算官方伤害、技能消耗或官方胜负。

能量 wire 字段的十三个本机完整 PE 函数交叉证据见 [恢复与字段说明](rogue-resonance-recovery-4.6.md)。现有冻结字段和命令未改。复验命令：

```powershell

```
