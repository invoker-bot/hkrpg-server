# 探索技能的当前生命比例条件

`AdventureByCompareHPRatio` 的显式 `TargetAlias/Caster` 条件现在读取当前施放者所属队伍的实际生命条。六种比较使用固定浮点阈值；省略阈值按零处理，`Inverse` 只反转已成功读取的结果。复用动作时重新读取，不能冻结第一次施法的生命状态。服务端生命条按现有 `GameAvatar` 的 0..10000 归一化值计算比例；这里没有把本机字段表当作官方条件求值函数的验收。

生命条件与秘技点条件在同一个玩家锁内读取当前队伍、施放者身份及所需数值，组合判断使用这一次快照，并保留同一 Buff 锁和判断时刻。剧情独立队伍读取其存档生命值，不借用正式角色的普通队伍生命。缺少玩家、脱离当前阵容、同编号的替代对象、越界存档生命或秘技点均保持不可判断，即使反向也不执行成功或失败分支。生命比例条件单独使用时不要求无关秘技点有效。

严格接受当前已核对的目标与固定数值形状。其他目标、未知字段、动态表达式、字符串数值、非有限值和未核对的比较类型仍拒绝编译；战斗用的 `ByCompareHPRatio/DynamicFloat` 是另一种类型，未因此接通。

## 原始来源与静态证据

固定资源提交为 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。夹具保留 `LocalPlayer_Anaxa_00_Ability.json` 中 `ADV_StageAbility_Anaxa_00_LineupAttackListener.OnAttack[0]` 的完整原始任务、原始文件路径、安装字节 SHA256 和 Git 原始 blob SHA256。该任务的条件为施放者生命比例大于省略的零阈值，成功叶仍保留 `ParamEntityList` 目标、`Fear` 行为判断及原始 140502 Buff；没有将这些未实现部分改造成无条件施放。

本机国服客户端只读核验两个固定 SHA256 文件：元数据类型 20777 的 `AdventureByCompareHPRatio` 字段为 `TargetType`、`CompareType` 和原生 R4 的 `CompareValue`。构造方法 120391 的 64 字节范围由 PE 异常表独立限定，完整字节和哈希保存在夹具中；构造器没有写入比较阈值，零阈值处理结合新对象默认零值作出。没有执行 DLL、修改客户端或推导 wire 字段号，也没有证明官方运行时目标选择和生命计算语义。
