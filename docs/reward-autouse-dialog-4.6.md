# 奖励窗口自动使用检查异常

## 现场与定位

2026-11-15 用户反馈买书后卡住。本机会话在 00:55:56 和 00:55:58 左右等待过商店购买响应 `1575`，随后的采样中对应等待项消失；这些采样没有记录商品、响应结果或库存，不能据此断定哪本书已到账、是否扣款或购买成功。

同次客户端 `Player.log` 在切到城郊雪原后记录 `RewardDialog.bytes:453` 的 `attempt to call a nil value`，调用栈经过奖励窗口关闭时的 `_on_dispose` 和 `_trigger_autouse_item`。只读采样在此后记录过输入锁，但锁属于 `InControlActionsManager`，采样中曾释放又重新出现；不能仅凭先后顺序断定它由奖励窗口创建，或断定这一异常解释了所有画面卡顿。另有 `MissionDetailPanel` 的独立空引用，当前证据不能把它归因于买书。

当前客户端原始 `Ui/Common/RewardDialog` 在处理 `IsAutoUse` 物品时调用 `G.InventoryUtils.check_item_ban`，而当前 `Logic/LogicUtils/InventoryUtils` 没有这个函数，提供的是 `is_item_banned`。后者由普通 `check_item_use` 调用，并以真值表示物品被禁用。静态盘点当前 Lua 索引全部 19,644 条记录，另外两处同形调用位于 `Ui/Shop/RechargeRewardDialog` 和 `Ui/ActivityMonopoly/MiniGamePage/ActivityMonopolyMiniGameRewardDialog`；该盘点针对函数名，不能证明其他名称的所有 UI 问题已经覆盖。

## 兼容候选

`scripts/client_lua_reward_autouse.py` 仅接受当前固定 Lua 入口、三份奖励页、物品工具及既有地图补丁的已核对摘要。候选把三处不存在的调用改为当前 `is_item_banned`，同时反转对应跳转：被禁用的物品跳过后续自动使用，未禁用的物品继续执行原来的自选礼包判断。空物品或非自动使用物品仍按原路径跳过；其余指令、行号、函数及现有客户端补丁保留。这是根据当前禁用检查和奖励窗口控制流制定的本服兼容方案，未宣称已核实旧版函数实现。

候选只修改奖励页面 Lua 记录及其模块目录，不改游戏程序、协议、商店价格、玩家库存或任务。安装复用既有受控流程：游戏必须已退出，核验原文件和准备文件、先备份 Lua 入口及启动清单，写入新分块后原子切换；校验失败回退入口。客户端仍运行时不自动结束进程、不写入客户端。

## 验证与边界

修复前，三个原始窗口的自动使用分支均在有限指令回放中复现空函数调用，六种允许/禁用情况均无法继续；新增回归先失败。修复后专项检查覆盖三个窗口的未禁用、禁用、空物品及非自动使用分支，确保其他函数和后续礼包指令不变。隔离客户端检查完整重读 19,644 条 Lua 记录，除模块目录和三个目标页面外保持不变；验证运行中拒绝安装、篡改候选拒绝、备份、安装和重复安装。模拟仅执行相关 Luau 指令与观察桩，不运行真实 UI。

2026-11-15 专项 Python 8 项通过，连同已有 Lua 兼容测试共 42 项通过；新增失败回滚检查和工具函数导出检查也单独通过。完整 `scripts/build.ps1 -TestForks 8` 实际执行 749 类、20,331 项 Java 测试，失败、错误和跳过均为零。

候选准备位置为 `build/reward-autouse-20261115/prepared/`。本机游戏尚在运行，候选尚未安装，未启动或操纵客户端，也未修改正式玩家数据。购买结果、真实奖励窗口关闭后的画面、输入恢复、其他两个窗口的实际行为和完整商店流程都仍需实机核验。
