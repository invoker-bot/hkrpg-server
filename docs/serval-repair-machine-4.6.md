# 永冬城之夜维修机器没有 F 提示

## 原因与修复

用户在机械屋贴近任务标记的机器，目标为「帮助希露瓦修理机器」，但没有 F 交互提示。2026-11-02 正式数据库只读检查确认玩家位于 `P10101/F10101007`，主任务 `1010206` 和目标 `101020109` 正在进行，前置 `101020108` 已完成，机器尚无交互收据。未修改正式玩家进度，也未操作客户端。

原始机器是组 12、实例 300002、物件 301058，摆放状态为 `Locked`。目标脚本 `Config/Level/Mission/1010201/Mission_101020109.json` 只有独立的 `ChangePropState`，应在接取目标后恢复为 `Closed`。旧 `StoryDoors` 没有识别这份 `CablePuzzle_03` 图，加载楼层时也清除了该物件的 `ValueSource`，丢失镜头、拼图板和自身目标绑定。

修复把它加入有原始来源约束的自身状态交互。仅普通世界、准确地图、物件、主/子任务、前置定义和完整启用脚本匹配时恢复就绪；同时核对原始三项共享绑定，防止额外动作或其他对象被误启用。楼层加载借助已有控制器识别保留这些绑定，任务刷新同步已加载实体，重新登录按同一规则恢复。

接取目标只启用机器，不完成拼图或任务。原始客户端拼图的完成回调才发送交互 `1010`，服务端复用 `ScenePropTransitions` 保存 `Open`、发送同步与原生回包、完成 `101020109` 并接取 `101020110` 希露瓦对白；退出拼图不应产生该完成报告。保存失败回退，成功保存但任务回调中断可以凭同源收据恢复。不开放脚本解锁 `1200`，不通过 GM 跳过剧情。
