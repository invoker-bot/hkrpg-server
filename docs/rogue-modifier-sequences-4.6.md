# 4.6 修改器等待序列与延迟能力刷新

`RogueModifierSequences46` 补入普通等待序列的两组计数、开始/推进/结束顺序与延迟能力刷新。执行计数直接复用 `RogueModifierReplace46.State`，现有 `RogueTaskSequence46.Sequence` 实现该序列接口，联合验证使用真正的 Java 子任务序列。原生任务配置工厂、虚表绑定、世界注册和实际修改器仍待完成。

开始时，缺失序列直接返回；存在序列则先分别增加执行计数和等待计数，再以零 delta 调用 Step。返回 Success 或 Fail 时保存终态，其他结果统一置 Executing，随后再次调用修改器 Tick，delta 仍为零。等待序列因而可在同一次开始中接收两次 Step；不能合并为一次 Begin 或漏掉第二次零 delta。

Tick 只在 Executing 时调用 Step 并保存其返回状态。Success/Fail 走相同收尾：先 Reset，再明确写 Ready，再减少等待计数，最后进入明确提供的序列结束虚调用绑定。Ready 和未知状态不推进；开始规范化后，后续未知返回值也不伪造完成。原生体没有负 delta 或 NaN 门槛，原始明确接口按输入传递；现有 Java 子任务序列继续遵守项目的非负有限 delta 和四类状态规则。

结束刷新先减少执行计数，再根据减少前的有符号值判断：原计数大于1时暂不刷新，原值为1、0或负值时继续检查延迟能力。所有计数按 Int32 回绕，没有饱和或下限裁剪。延迟能力为空时跳过上下文；非空时在读取上下文前保存该能力，更新明确上下文、运行后续虚调用，然后清空延迟字段。回调即使改动待刷新字段，最后成功清空仍覆盖它；异常保留已发生的计数和上下文写入，不增加 finally、回滚或提前清空。

等待计数偏移124，执行计数偏移152，延迟能力偏移72且类型是来源能力。序列字段偏移16是回合 TaskState（54773），使用 `0x7777/0x8888/0x9999/0xaaaa`，不能混用另一个同名枚举。五个完整PE方法共3,229字节，包含三个修改器方法及实际子任务 Step/Reset；读取器重新比对方法身份、完整字节、字段和枚举。

新增33项 Java 回归覆盖两次零 delta、终态收尾、嵌套计数、Int32 回绕、空绑定、回调重读、异常中断以及“子任务等待→实际替换入口延迟能力→子任务完成→刷新同一上下文”的联合路径。九项 Python 核对来源和未完成边界。这里为新实现的正常与异常回归，没有把故意错误候选冒称既有生产代码的先失败缺陷。

进一步按方法元数据的编码虚槽核对六项声明：基础和回合修改器的 `OnStack` 为槽28，`OnModifierCasterChanged` 为槽30，`_SequenceEndAndFlush` 为槽31。替换后的两个明确虚调用分别对应前两项，等待序列终结对应第三项；没有按方法排列顺序猜测。回合覆写的结束体先调用基础刷新，再检查执行计数与等待计数，决定解除叠加、销毁清理和待释放状态；这些回合收尾动作尚未在本批安装，不能把基础刷新当作完整回合覆写。
