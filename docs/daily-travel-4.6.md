# 4.6 所属主任务接取门与楼层移动日常委托

本轮补齐原始日常任务图的服务端资格检查，覆盖 3020101–3020108、3020201–3020203、3020205–3020206 共十三条对话委托，以及 3012001、3020204 两条带实际楼层移动的委托。原始主任务仍为 Manual，自动分配继续是本服策略；原始任务图、前置、单日一条名额、每次 5000 信用点及活跃目标 2100003 的 200 点奖励均不改。

原始十五个起始目标的 TakeType 为 Auto，TakeParamIntList 只有所属 MainMissionID。此前日常安全图检查拒绝所有非空 Auto 参数，导致这些图无法自动分配和跨日重接。现在只有本图唯一首目标可以使用单个所属主任务编号；外来主任务、多个编号、空元素、非首目标、重复首目标和未处理字符串参数继续拒绝。普通不带参数的既有 Auto 图沿用原有规则。

两个移动目标保留完整原始脚本：301200108 为 EnterMap(1010203, group 24, anchor 1)，302020403 为 EnterMap(1020201)，后者保留原始 IsLoop=true 声明。有限资格规则要求完整脚本只有这一条 EnterMap，来源入口、目标 plane/floor 与当前已加载普通楼层一致，并拒绝回溯、剧情维度或额外任务。此处读取客户端移动声明；实际推进仍由服务器确认的 Scene.loadScene/转场触发，不因资格检查自动完成目标或播放演出。

3012001 的验证路线经过原始 101→107→108→109 分支，实际进入 10102003 后才完成 108。3020204 经过 401→402→403→404，实际进入 10202001 后完成 403，最终 404 仍按来源要求回到 10202004 报告。错误楼层、同楼层加载、目标尚未接取时的到达和与当前位置不符的入楼报告不会推进目标。

接取周期、完成日统计和领奖周期沿用原有界限。合法已结算轮次在下一日归档旧任务、目标、动作游标与奖励收据后，建立新轮；新轮必须重新完成原始目标才发奖。未完成旧轮先按既有日界规则保存到期证明，再分配新轮；旧轮不是完成记录，不能增加新日活跃目标。原始奖励计划及按周期领取防重继续保存，不增加新的玩家字段或改变奖励事务。

新增夹具含 142 条原始行、42 份完整资源证明，来源固定为 TurnBasedGameData `724b139d8c9c32d12552eb95745a4fee72bfe48b`；抽取时与该提交的完整 Git blob 逐份比较 JSON，保存安装资源 SHA256 与 Git blob SHA256。Python 三项检查核对完整资源、十五个接取门与两条移动声明。

Java 回归使用实际 Player/Scene 进行自动分配、源目标推进、每日主奖励及活跃领取、同日防重、跨日重新完成和到期处理；两个移动分支另通过实际 Morphia Player 文档的多次保存/读取检查进行中目标、来源接取日、归档及各轮奖励收据。旧实现的 50 项测试中 36 项真实失败，目录资格和自动分配断言均已由 `build/daily-travel-red-tests.xml` 留证。修正后 50 项全部通过、错误与跳过为零，报告另存 `build/daily-travel-green-tests.xml`；Assignment、Expiry、Repeat、StageWin 的 128 项相关检查同时通过。最终全量构建仍由本轮统一验证报告记录。

隔离原生验证入口为 `scripts/smoke-daily-travel.py`，辅助探针和时钟命令只从 `scripts/fixtures/java` 编译到隔离目录，不进入服务 jar。冻结服务产物 SHA256 `3948948ca7cba698c4a6c4e0fdb1c40bb45f7a3815f8753ddb00f43a5c8d9163` 上，两条原始移动委托的实际 KCP 验证通过：212 次请求、170 项检查、16 个登录快照，合计六次正常停止与四次同 UID 的 H2 进程恢复。每条委托在受控两日分别实际取得原始 5000 信用点、单独领取 200 活跃点，验证真实楼层移动、重复交付与领取拒绝、旧轮归档和第二轮收据；报告为 `build/daily-travel-native.json`。报告与本轮全量构建分别记录，不能把这个产物上的结果推断为其他产物或客户端 UI 已通过。

两个并行验证会话曾共用汇总输出路径，只按保留的报告及其两个目录的独立 probe/server 日志记录一次通过，不增加第二份验收计数，也不推定会话归属。匹配目录为 `daily-travel-3012001-4qguar14` 和 `daily-travel-3020204-nnzu8fbu`，快照、请求、检查、时钟视图与正常停止记录已逐一核对，另留 `build/daily-travel-report-log-check.json`。
