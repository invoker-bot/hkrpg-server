# 4.6 战斗结算后的能量换算

旧结算先把 `left_sp` 截为整数，再乘固定的 100。例如剩余 50、上限 130 时保存为 5000；剩余 22.5、上限 90 时保存为 2200。两个结果都没有保持实际报告的比例。

现在按 `left_sp / max_sp × GameAvatar.getMaxSp()` 四舍五入，沿用已有的 10000 存储尺度。上述结果分别为 3846 和 2500。先除再乘避免两个有限大数相乘溢出；合法的零剩余、零上限保存为零。负值、非有限数、超上限和零上限非零剩余继续由现有校验拒绝，不消耗进行中的战斗。

仍通过战斗保存的队伍写回生命和能量。普通、额外、剧情和经典宇宙的原有分支存储各自保留；失败结算继续应用已有生命下限，退出继续不写回报告中的生命或能量。没有调整角色基础能量需求或引入特殊能量机制。
