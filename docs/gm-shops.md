# GM 商店商品上下架

GM 控制台增加「商店管理」，可查看当前资源已加载的商品、中文物品名、价格、每份数量和刷新限购，按商店、上架状态及商品名/物品 ID/商品 ID 筛选。点击「查看」可单个上架或下架；列表勾选支持跨页保留，表头勾选本页，一次最多提交 500 个商品。切换筛选条件会清空勾选，执行前确认具体商品和全服影响。无需选择玩家，零在线玩家时也可管理。

上下架只管理现有目录。上架恢复商品原定义，下架使其从服务端商店查询中消失，并在购买入口拒绝旧页面或直接发送的购买请求。重新打开游戏内商店可获取新目录；没有主动刷新已经打开的游戏画面。轮换商品按商品位管理，整个商品位下架，其各月份物品均不可购买。

价格、每份数量、货币、原有限购和玩家累计购买次数保持原样，重新上架不会重置限购。商品协议不包含可任意覆盖价格/数量的字段，客户端仍使用固定资源中的商品定义；本功能不创建客户端未知的商品编号、不修改定价，也不改变充值、活动门槛或真实支付。

## 接口和保存

同源会话中的 `GET /gm/api/shops` 返回 `shops`、`total` 和 `items`；支持 `shopId`（省略或 0 为全部）、`state=listed|unlisted`、`q`、`offset`、`limit`（1–100，默认 30）。商品状态描述服务端上下架开关，不代表客户端的其他原始条件全部满足。

写入沿用 `POST /gm/api/operate` 的 Cookie、CSRF、请求编号及持久操作记录。`action` 为 `shop-list` 或 `shop-unlist`，`uid` 省略或为 0，`shopGoods` 为 1–500 个不重复的商店/商品对：

```json
{
  "requestId": "42c54f06-ae57-4edc-b6b0-a44a0ee7a15d",
  "action": "shop-unlist",
  "shopGoods": [{"shopId": 101, "goodsId": 101001}]
}
```

状态保存在运行数据目录的 `ShopAvailability.json`，只记录下架的商店/商品对。查询与无变化的上架不安装默认文件，也不覆盖运营资源。每次真实变更先完整验证当前文件和整批目标，保留根级运营扩展字段，备份到 `gm-shop-backups/ShopAvailability-<请求编号>.json`，同目录临时文件写入并强制落盘、原子替换后再发布到内存。任一目标不存在、文件损坏、备份或保存失败均不发布本批变更。文件损坏时启动明确失败，避免静默恢复为全部上架；修复文件后再启动。没有文件监听器，手工编辑需要重启，或在下一次有效 GM 操作时完整核对并加载。

商店购买持有上下架读锁；修改持有写锁，允许不同玩家同时购买。已通过准入检查的购买先结束，再确认下架；下架确认之后的新请求不会继续付款。上下架过程不取得玩家锁，避免与玩家购买的锁顺序形成环。旧/4.6 查询使用同一份完整开关快照；下架后为空的商店不下发。

历史请求继续使用原编号核对结果，不重复执行。已下架后再上架，重放早先的下架请求不会再次下架。异常未确认的操作仍遵循原有 GM 人工核对流程，不自动补做。

## 验证与边界

先失败证据 `build/gm-shops-red.log` 覆盖原来不存在的商品接口、网页模块和全服写入操作。Java 回归覆盖筛选分页、鉴权/CSRF、非法与重复目标、整批失败、原始资源保留、备份失败、损坏文件、运营字段保留、正常重启、购买付款前拒绝、限购保留，以及下架等待已准入购买结束；4.2/4.6 编码验证均过滤下架商品与空商店。

复现命令：

```powershell
.\scripts\build.ps1 -TestForks 8
python scripts/smoke-server.py
python scripts/smoke-gm-shops.py
# 同一隔离服务暂停，供真实网页操作验证；在日志给出的运行目录创建 continue 后结束。
python scripts/smoke-gm-shops.py --browser-pause
```

原生脚本只启动独立端口和独立 H2 数据库，使用现有 4.6 资源与实际 KCP 玩家：先零在线批量下架，验证查询不展示、余额充足也不能购买，重新上架后实际扣费与到账；同 UID 正常重启后下架状态和累计购买次数保留，重新上架不重置次数，历史下架请求重放不覆盖较新的上架。脚本最后恢复隔离商店目录，生产账号和商店不参与写入验证。

这些证据证明 GM 管理、已实现购买入口及协议目录的行为，不代替真实游戏商店按钮、动画、门槛和全部商品的客户端验收。
