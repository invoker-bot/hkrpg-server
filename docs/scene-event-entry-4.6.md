# 4.6 场景事件入战

本批修复原生 `SceneEnterStageCsReq` 将事件编号误当直接关卡编号的回退。命令 1404 的字段 11 为事件编号，字段 10 仅支持客户端默认枚举值 0；响应命令 1419 沿用冻结描述符。内部 `BattleService.startBattle` 仍可供既有脚本直接指定关卡，新原生入口调用 `startEventBattle`，在玩家锁内精确读取事件、世界等级、关卡及怪物波次，再通过既有任务与实例回调创建战斗。

`PlaneEvent` 必须与查询的事件编号和世界等级一致，关卡对象必须对应映射的正数编号并具有非空、正数怪物波次。缺失事件不改用同值关卡，也不回退到其他世界等级。重复标量、超出 32 位的别名、负数、未知字段、截断报文、错误线类型和未实现枚举选项先于开战拒绝。已有战斗、剧情迁移状态或未登录会话不会建立第二场战斗。

固定资料来自 `TurnBasedGameData` 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。夹具保留两个事件的 14 条映射、14 条原始关卡及两份任务脚本，共 30 份原件、四个源文件；完整文件 SHA、源提交字节 SHA 与原始记录位置均保留。两条事件分别为 20134221 和 20134222，七个世界等级精确映射到对应末位 0 至 6 的关卡。

本机客户端证据固定 GameAssembly.dll 与 global-metadata.dat 的 SHA。只读方法链确认 `TriggerBattleByEventLegacy` 将事件参数原值写入请求对象偏移 0x1c，使用命令 1404；请求写出器将该位置写为字段 11。`AdventureStatic.GetStageIDByEventID` 调用 `PlaneEventExcelTable.GetData`，后者将事件与世界等级组成二元键。定点数 `ToInt32` 读取 64 位原值，不支持将本次差异直接归因于普通单精度浮点取整。保存的五段反汇编明确截断于本方法边界，参数类型单独核对。

原始任务 301160201 的 `TriggerBattle.EventID.FixedValue.Value` 是 20134220，但当前事件表没有此编号。服务端保持拒绝，不能凭相邻编号自行补映射。任务动态取值绑定、NPC 对话资源、完整客户端脚本分发及官方可达入口仍未核对；上述静态方法也不证明 `TriggerBattle` 任务的完整执行。此缺口必须继续调查。

50 项新增 Java 检查覆盖原始 14 个变体、实际波次、资源损坏、原生报文、已有战斗、12 个并发请求和旧内部接口。原有 11 项检查中 10 项真实断言先失败；编译失败、缺失会话的测试夹具以及随机战斗编号假设均另存为排除记录，不计行为失败。两项原始日常图检查在显式前置、位置与时钟夹具中，用新事件入口创建实际关卡战斗，确认胜利推进 StageWin，完成原图尾部后实际得到 5000 信用点。空队伍单位夹具不属于真实游戏战斗验收。

`scripts/smoke-scene-event.py` 独立启动实际服务器与 H2，用正式初始角色经 UDP/KCP 开始两个原始世界等级 0 事件，核对怪物波次、当前战斗快照、错误结果编号、重复入战和重复结算。82 项检查覆盖四次同账号会话、三次正常停止和两次 H2 进程重启；拒绝入口前后库存与任务列表不变。事件和关卡表未改，剧情脚本目录刻意隔离为空，未填入完成任务或奖励。它验证原生服务端入战，不证明原始日常任务的正向 KCP 链或完整事件授权。

本批全量为 4164 项 Java、15 项脚本、151 份冻结协议。最终当前包、独立源码构建以及新 82 项事件网络检查和复用的 74 项周期、68 项日常、60 项剧情书籍、两项 Dispatch 检查，以 `build/sceneevent-4164-source-verification.json` 为最终核对记录；准备中的或较早包的网络结果不计最终包验收。功能仍为部分实现，官方客户端 UI、全剧情、宇宙与活动、跨文档事务及断电恢复均未全部完成。
