# 场景动作入口与字段语义（2026-10-23）

## 问题与处理

此前实机怪物攻击先后暴露两个旧字段名与原生含义不一致的问题：`cast_entity_id` 是 Ability UseID，实际施放者在 `attacked_by_entity_id`；字段 6 虽名为辅助怪物列表，实际受击时可以包含当前队伍角色。上一版本已修复实机请求并通过用户入战确认，详见 [怪物伏击记录](monster-ambush-4.6.md)。本次继续消除分散解释这些字段的入口。

`SceneCastRequest46` 作为唯一攻击适配器，集中解析流水号、施放者、技能索引和四种已核对回调阶段。根据当前场景实体类型归并普通、扁平辅助和分组辅助列表，去重后再检查目标数量与类型。角色受击、辅助怪物、可破坏物保持各自处理方式。物件不再能凭恰好等于角色实体号的 UseID 被倒置为玩家攻击；兼容的旧直接目标形式必须具有明确当前角色、非空能力名和直接阶段，仍经过实际技能检查。

`SceneActionWire46` 覆盖 1460 攻击、1408 秘技扣点和 1405 交互，先于 protobuf 解析检查重复单值字段、线类型、uint32 溢出、未知嵌套字段和有界集合。正常打包/非打包列表、负数 zig-zag 坐标及完整 uint64 交互上下文保持有效。16 KiB 报文、最多四层嵌套和单字段 128 个原始条目为本服解析预算，不宣称来自原版服务器；归并前后的每类唯一目标仍保留既有 64 个上限。随后才允许修改秘技点、破坏场景物件、推进交互任务或创建战斗。线格式错误返回明确失败响应，不因解析异常直接断开连接。战斗已开始时返回忙碌状态，不再归为参数不存在。

`SceneActionDiagnostics46` 在拒绝时记录命令、UID、楼层、原因、相关编号和目标数量，每会话每分钟最多八条，弱引用最多保留 256 个会话预算。既不打印完整报文，也不记录口令、令牌、客户端任意文本或背包。正常请求不产生这些日志。这样可以从服务日志区分字段、实体、技能、场景状态或入战配置问题，无需每次临时附加观察器。
