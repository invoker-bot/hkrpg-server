# 4.6 古梦年华零价与推荐商品价格

用户要求保留古梦年华商品并以零价获取，推荐商品保留原有价格。原服务对客户端 `QueryProductInfoCsReq`（96）只返回空占位，SDK 商品和价格入口也未重定向到本地；客户端的充值商店页面等待商品数据与价格准备完成，因此会一直显示加载。普通商店的推荐商品仍使用其原始 `ShopGoodsConfig` 货币和费用。

## 本服兼容规则

本服提供 6 个固定国服梦华商品，其 ID、基础数量和常规附加数量必须与本机 `RechargeConfig.json` 全部一致，否则整批拒绝并记录原因。价格使用单独的 `Local_Free` 档位，不改原始 `Tier_1` 等档位；每次有效本地领取分别获得 60、330、1090、2240、3880、8080 古老梦华。这里按资源的基础数量加常规附加数量发放，不推定旧存档的首充状态，也不伪造首充双倍记录。

`sdk-shop-prices.json` 的 88 档人民币数值来自 AGPL-3.0 的 March7thHoney-OpenSource 固定提交 `fe00bdbda3c28ca33d01f171566aa35b5ab95083` 的 `Config/Custom/QueryProductInfoConfig.json`；转换为分后保留原值。参考表不代表已核验实时官方价格，推荐商品原有游戏内货币定价、商品条件和运营资源文件未改。尚无可信活动排期或购买状态的付费礼包不会伪造为已购买或可免费领取；真实支付及现金礼包购买未实现。

本机固定国服 SDK 配置中核对出的 23 个商店、订单和支付入口改为本地地址，并保留现有本地登录配置及其他客户端资源。价格接口返回原有档位及独立免费档位。另有 HTTP 订单入口只接受实际登录的同一账号和有效会话令牌，不连接真实付款服务；其他商品、错误账号、错误令牌或不支持的请求均拒绝。

实际客户端的 `PayModule.Pay` 会再次执行充值禁令检查，并要求价格大于零，因而仅放行页面按钮或伪装为零价 SDK 订单都不足以领取。固定客户端的商品按钮对上述 6 个完整商品 ID 使用 `List<String>` 调用原生 `NetworkManager.GCBGBBMFIJN`，通过当前已登录游戏会话发送商品 ID；其他商品保留原按钮与充值禁令。该方法在本机静态核对会发送 4183、类型为 2；服务端仅在单个完整 ID 属于这 6 个商品、该会话已查询目录且玩家与会话对应时发放，随后使用原有奖励通知与确认。当前会话中的重复请求共用标识，关闭奖励提示后才允许下次领取；跨提示完成后的迟到重试不能视作完整的跨会话事务保证。

上述调用限定于 `GameAssembly.dll` SHA-256 `8cc7380066343b6152069a6d1c90e230322aa78b780b1e738c13185b3692f1d3` 和已核对的 Lua 资源。`PayModule.Pay` 在 `da8b42f` 检查禁令，在 `da8b4ef` 检查正价格；`GCBGBBMFIJN` 在 `d99a32b` 设置类型 2、在 `d99a3d1` 发送 4183。`_OnQueryProductInfoScRsp` 将商品消息的 `+0x10` 和 `+0x18` 分别传给本机 `Product.SetProduct` 的商品 ID 与价格档位，对应冻结描述符的字段 9 与 3；不套用另一协议版本字段互换的注释。准备时逐条比对 19644 条 Lua 记录，仅商品按钮和模块目录记录发生变化，既有时装及地图兼容资源保留。

余额和本地订单收据保存在同一玩家文档，先保存后通知；保存异常时回退内存并阻止该会话继续免费领取，需重新登录核对。收据达到上限后停止发放。奖励提示的确认只处理本会话内已经发出的 `Local_Free` 通知，未知转换请求不冒充成功。没有根据仅在线玩家数量猜测账户，也不记录令牌或订单原文。

## 验证边界

先补失败回归，覆盖 4.6 商品查询、价格接口、订单入口、客户端零价入口及奖励提示确认。定向测试检查六档商品、推荐价格档位不被置零、来源资源不符拒绝、会话绑定、重复及并发请求、防止未知付费商品领取、保存失败保护和本地 SDK 地址替换。隔离 KCP、HTTP 与 H2 重启验证只使用临时账号，不改正式玩家。

静态核对了本机客户端页面的加载条件、商品查询、原生购买限制和奖励确认调用；本地补丁没有执行客户端。真实客户端加载、价格文字、点击领取、奖励提示及推荐商品 UI 尚未实机验收。旧 SDK 订单接口如缺少可校验的账号和令牌会拒绝领取并记录简短原因；不猜测玩家，不发起真实付款。
