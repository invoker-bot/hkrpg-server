# 当前场景角色传送与位置版本

2026-10-18 实际加载记录出现未处理的 `SceneEntityTeleportCsReq` 1491。此请求现由独立的 4.6 入口处理，返回 1487，并更新玩家实际三轴位置和朝向。它只定位当前场景内的自有队伍角色；跨地图仍走已有场景入口流程，不创建角色、完成任务或发放奖励。

## 原生契约和项目规则

冻结协议保持不变。1491 的字段 3 是 EntityMotion、9 是当前 entry、10 是 uint64 场景运行编号。EntityMotion 字段 2 是实体、11 是 MotionInfo、13 是地图层；Vector 是 sint32，负坐标按 zigzag 保留。1487 字段 3 回送接受的 motion，4 是返回码，9 是位置版本。

已安装客户端的发送函数 `d9c4630` 从 `MapDef.MapRuntimeID` 与 `CurMapEntryID` 构造请求；接收函数 `c5deb30` 成功后直接采用回包版本，再发送 1439 确认。SceneInfo 字段 14 和已有 1442 校正通知的字段 3 也直接赋值给同一个客户端版本。这里没有证据要求官方版本必须从 1 开始或每次加 1。本项目明确选择：新 Scene 版本为 0，每次接受传送递增一次；失败不变，uint32 用尽拒绝；1439 只确认已发布值，不能改写权威版本。SceneInfo、1487 和当前入口的 1442 输出同一版本，成功传送不额外发送 1442。

当前楼层的 `LayerToAreaMask` 数组长度定义普通层编号 1..N；mask 值本身不是层编号。原生玩家层查询对 0/无效层回退当前层，因此本入口的 0/省略保留当前层。非零层必须属于当前楼层。701 份运营楼层都已检查此数组；未知布尔字段 7 的 true 分支尚无可靠语义，明确拒绝。特殊移动层、非队伍实体和其他未核对变体仍不计为支持。

来源为本机固定 DLL `8cc7380066343b6152069a6d1c90e230322aa78b780b1e738c13185b3692f1d3`、metadata `09ce2093b78779d4bbe9dc866bb472438efd96cc6546b7cbc34edf4006736130` 和冻结 descriptor；辅助比较采用 AGPL-3.0 的 March7thHoney `fe00bdbda3c28ca33d01f171566aa35b5ab95083`。未复制无明确许可证的参考代码。原生逐函数证据位于 `build/login-loading-followup-20261018/` 的 `position-version-contract-20261018.json`、`teleport-maplayer-bool-contract-20261018.json` 及 `unhandled-1491-contract-20261018.json`。

## 状态与保存

请求必须匹配当前 player/scene 的 plane、floor、entry、runtime 和真实队伍成员。重建场景后的旧 runtime 即使碰到相同实体编号也会被拒绝。全部验证完成后，在玩家锁内一次更新位置、朝向、地图层及版本。不调用 `moveTo()`，不触发额外强制移动或锚点治疗。损坏、重复、未知字段、错误线类型及越界整数不得改变状态。

位置沿用普通移动的保存周期，不增加每次传送写库。地图层快照与位置同存 Player，绑定 plane/floor/entry/dimension/story、位置与朝向；正常保存捕获当前运行时层，重建场景仅在身份和坐标匹配且层资源仍有效时恢复。不同锚点没有新的层报告时保留原先默认层行为。事务位置回退同时恢复原层快照。版本和确认属于单次场景运行，不跨重连持久化。
