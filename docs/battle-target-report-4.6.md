# 4.6 战斗目标报告解析边界

原生 `PVEBattleResultCsReq` 的战斗统计在协议转换前检查目标报告。修复前，目标字典被整体跳过，重复类别、重复目标身份、重复标量、溢出整数、嵌套未知字段及截断目标都能通过身份检查。`BattleTargetReports46` 现在直接读取原始字节，避免先解析 protobuf 抹去重复字段。

外层 `battle_target_info` 字段 28 的 map entry 只接纳字段 1 的 uint32 类别和字段 2 的目标列表；列表只接纳字段 1 的目标记录，目标只接纳 uint32 的 id、progress、total_progress，字段分别为 1、2、3。全部整数在截断前校验完整无符号 32 位范围。重复类别、同一列表中的重复目标及单条记录重复标量拒绝；不同类别可各自包含相同目标身份。最多 32 个类别、每类 1024 个目标，原有请求 1 MiB 上限继续生效。

protobuf 默认值保持兼容：省略键等于类别 0，省略 value 等于空列表，省略进度等于 0。显式键 0 与省略键构成重复类别，不能绕过检查。最高合法 uint32 值 `4294967295` 原样通过既有桥接，不能把所有 uint32 当成有符号 int 上限。该步骤只验证编码和身份唯一性，具体关卡允许的类别、目标、阈值与战斗归属仍由玩法上下文校验；空列表不产生任何目标完成。

29 项新增 Java 回归中 28 项行为检查在修复前真实失败；另 1 项确认原始类别 5、目标 5001805 和最高合法无符号进度通过现有桥接。异常案例沿原始请求的 stt 字节进入检查，未先用 protobuf 解析测试坏数据。

## 固定本机客户端的静态连接

`StatisticsComponent.BuildPVEStatistics`（533439/RVA `e7602e0`）在 `e764df2` 调用原始目标统计方法，在 `e764eaa` 写入内部 `PVEGameStatistics` 的 `0x70` 目标列表。`GamePlayStatic.CreateBattleStatsProto`（541662/`e6b5de0`）将该列表装入协议目标列表，并在 `e6b64c0` 以类别键 5 添加到目标字典。

转换对象的本机类型槽核对为 `LCCJKNEADPL`，目标字典物理偏移 `0xe0`。该类型的 wire `MergeFrom`（146028/`1e8b9f80`）在 `1e8ba53f` 比较 tag `0xe2`，对应字段 28，随后读取相同偏移；元数据常量亦明确为 28。转换方法范围以已核对的下一方法 541663/`e6b68c0` 限定，未把周边下一方法计入转换证据。这里类别键来自实际转换指令，不来自配置 `ChallengeTarget=1` 枚举，也不是完成目标数量。

本机 DLL、元数据和设计索引仍固定为[原始资源说明](local-legend-native-resources-4.6.md)中的 SHA。未运行或修改官方客户端。本次证明的是结算统计字典的键，不证明 `SceneBattleInfo` 初始目标字典的完整消费，也不代表传奇挑战入口、队伍、历史进度、奖励或游戏 UI 已完成。

## 完整服务核对

```powershell
python -s -X utf8 scripts/smoke-scene-event.py --reject-local-legend --check-target-reports
```

隔离完整服务在两个原始日常事件战斗中各提交 28 种非法目标统计，共 56 次。每次必须返回失败并保留相同当前战斗，整批前后背包及 Quest 必须相同；随后有效胜利结算仍通过，重复胜利仍拒绝。连同三种传奇挑战通用入口拒绝，共预期 172 项检查，四次同 UID KCP 会话、三次正常关服及两次 H2 恢复。原始事件、关卡和两份日常脚本 SHA 不变，脚本目录为隔离空夹具；未执行完整官方剧情授权、战斗输入重演或断电事务。实际结果以最终验证报告为准。
