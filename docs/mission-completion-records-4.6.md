# 4.6 剧情前置与奖励的完成证明

任务阶段不能单独证明完成。MissionStateRecords 对存档键和任务编号、明确的阶段、进度目标及完成时间一起检查：主任务的有效目标为1，子任务采用加载定义的有效目标；旧定义进度0仍沿用既有目标1。正常进行必须为DOING、时间0、非负且小于目标的进度；完成历史必须明确为FINISHED、CLAIMING或CLOSED，时间为正且进度正好达到目标。取消的主任务或子任务不提供前置和奖励资格。非法记录保持原值，不补造完成时间、进度或奖励。

MissionManager 的主任务MultiSequence、子任务AnySequence/MultiSequence、主任务最终子列表、实际对话/资源动作授权，以及Mission地图组的Accept/Finish条件均按这些证明判断。剧情区间的开始、结束和已知状态也检查实际已接受的父子记录；异常终点不能让区间提前关闭或重新开放。主/子奖励无论使用已冻结计划还是旧主任务的资源奖励，都必须来自对应存档键下的有效完成记录；仅有计划不能发奖，其他键下同编号的记录不能代发。正常领取中、已领取历史继续提供完成前置，不回退领取阶段。
