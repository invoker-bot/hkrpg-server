# 4.6 角色变化、离场和不可选中参数撤销

三个普通撤销入口先捕获参数。参数为空时直接返回，不要求 owner 或世界；非空时先清空修改器字段，再从显式共享的清理状态读取 owner。移除或回收失败时，最初的字段清空和已完成操作保留，不回滚，也不在重试时补做已失去参数的操作。

角色变化移除传递调用者的布尔参数，回收捕获的旧对象成功后才通知事件 990，通知参数为空、立即发送。离场移除将替换参数引用传为空，再回收对象，不发送该通知。不可选中移除从 owner 的实体读取 GameEntity._OwnerWorldRef，取得 GameWorld.BattleInstanceRef，再取得 BattleInstance._TurnBasedGameMode；逐项要求非空，再以空替换引用撤销并回收。

对象链来自声明字段及完整继承字段核对，offset 136 是游戏世界引用，offset 152 是战斗实例引用，不是技能组件或技能上下文。移除、查询、回收或通知回调写入的新参数引用不在尾部再次清空；所有回收都使用最初捕获的旧参数。

新增 44 项 Java 回归和 8 项 Python 原件检查。安装前与现有模块联合的 913 项 Java 回归、25 个测试类通过。覆盖空参数、owner/世界缺失、四层对象链中断、调用者布尔值、空替换引用、事件参数、移除及回收失败、重试、回调替换引用、兄弟字段保留，以及真实终结任务序列到清理和延迟销毁的联动。初版曾把离场与不可选中的空替换引用解释为 false；两个既有实现行为的失败回归已复现，并在修正后通过。初版整体构建结果保存为 build/owned-effects-before-null-replacement-full-build.log，不作为最终验收。证据冻结前修正了 Windows 换行的哈希归一化。
