# 星魂与晋阶奖励修复

这轮检查覆盖普通角色养成中的星魂激活和晋阶领奖，接续 [突破、行迹和装备保护](progression-gates-4.6.md)，不代表所有玩法已完成。

## 复现的问题

- 4.6 星魂请求的材料字段 `cost_data` 没有映射到内部 `item_cost_list`，正常携带材料的请求会被严格协议转换拒绝。现在 308/368 返回实际激活结果，格式错误也有对应失败回复。
- 星魂旧入口从通用角色查询取对象，可能命中临时角色；修改未使用的命途时，又会按当前命途扣材料和升级。现在只处理正式角色库和实际持有的目标命途，材料必须与该命途下一阶的原始配置一致，不切换当前命途。
- 材料验证补齐归属、实际库存对象、类型、锁定、数量和配置完整性，实际扣料后核对差额；并发请求共用玩家锁。扣料前保存处理记录，保存中断后保留待处理状态，阻止不确定的重复扣料。
- 晋阶奖励原先先写已领取标记，再硬编码发一张车票，忽略真正到账结果。库存已满时会失去领奖机会。现在从 `AvatarPromotionReward` 和 `RewardData` 读取奖励，先检查容量和已达成的晋阶，实际到账后才保存已领取标记。完整发奖记录存在但角色标记保存失败时，只修复标记，不重复发奖。

## 来源

固定资源来自 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`；47 条完整原始记录、7 份本地文件哈希保存于 `src/test/resources/fixtures/avatar-milestones-4.6.json`。只读审计同时核对固定 Git 原件，本地格式和换行差异不视为内容变更。

协议字段核对 March7thHoney-OpenSource 提交 `fe00bdbda3c28ca33d01f171566aa35b5ab95083` 的 `Proto/4.6/CmdAvatarType.proto`：星魂请求 308 的角色、阶数、材料字段为 7/6/14，回复 368 的结果字段为 9；晋阶奖励请求 317 的角色/晋阶为 5/2，回复 338 的奖励/结果为 1/13。没有手改生成协议或执行参考仓库的程序。

星魂一次请求只激活下一阶；`rank` 元数据不解释成任意批量升级，沿用固定参考接收逻辑。角色实际持有和服务端下一阶材料始终是执行依据。
