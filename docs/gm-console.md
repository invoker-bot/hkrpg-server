# 网页 GM 控制台

入口为当前 HTTP 服务的 `/gm`。本地 Compose 地址是 `http://127.0.0.1:18080/gm`；在项目目录双击 `GM控制台.cmd` 可自动读取本地管理密钥并登录。也可运行：

```powershell
.\scripts\open-gm-console.ps1
# 自定义本机端口与数据目录
.\scripts\open-gm-console.ps1 -Url http://127.0.0.1:8080/gm -DataDirectory D:\hkrpg-work\data
```

先启动新版服务，第一次启动会在配置的 `dataDir` 下创建 `gm-console.key`。页面也支持手动输入该文件中的管理密钥。密钥与游戏账号、SDK 令牌独立，不打印在服务日志或启动脚本输出中；已有文件不覆盖。自动登录脚本只接受本机地址，通过 URL fragment 交给页面，页面在发起请求前移除 fragment。网页资源包含在 JAR 内，不需要单独启动 Node 或安装前端依赖。

## 操作范围

| 页面 | 当前实现 |
| --- | --- |
| 玩家管理 | 在线玩家搜索、UID/等级/世界等级/场景/战斗状态；选定目标后恢复生命、补满秘技点、返回当前场景起点 |
| 资源发放 | 按中文名称或 ID 搜索，物品/角色/光锥/遗器分类，分页；数量与等级/星魂/叠影预览；显示实际入库数量 |
| 邮件发送 | 在线目标、标题/发件人/正文、最多 5 种附件、30 天有效期；保存邮件并发送通知 |
| 历史卡池 | 查看角色/光锥历史 UP，按版本、类型、名称或 ID 筛选；设置 1–365 天并复刻到全服，结果进入操作记录 |
| 指令终端 | 现有指令参考与搜索、独立目标 UID、当前调用的回显；保留既有指令的具体支持边界 |
| 操作记录 | 最近 1000 项操作，按 UID/摘要/请求编号搜索，查看结果、时间、目标与回显，重启后恢复 |

玩家列表只显示在线玩家，不暴露账号密码、SDK 凭据或内部 Player/Account 对象。选择目标后其他页面沿用该 UID；玩家离线后移除选择，不自动改为其他玩家。资源、邮件与快捷操作仅支持在线玩家。终端可以执行既有离线 `unstuck` 指令，目标 UID 单独填写，指令中不填写 `@UID`。

在线“解除卡死”重载当前地图起点，战斗中拒绝执行；缺少起点时不修改位置。它没有自动跳过任务、战斗或剧情。已有角色不会重复发放，属性修改可使用 `avatar` 指令。网页表单普通物品每次最多 100 万，装备每次最多 100 件，角色每次 1 位；光锥与角色最高 80 级，遗器最高 15 级或当前配置较小上限。背包或货币封顶时按实际增量显示部分完成，不把请求数量当成已收到数量。邮件附件仅支持当前服务可发放的货币及可堆叠材料、消耗品，不支持通过附件配置装备属性。

终端复用当前 `CommandManager`；每次调用单独收集最多 200 条、每条最多 2000 字的输出，不挂接全局日志。`returned / 指令已返回` 只表示既有处理器返回，不保证任意指令的玩法已经完成；应结合回显和玩家状态核对。`account`、`clear`、`permission`、`giveall`、`reload`、`kick` 及其别名要求确认完整指令；停服指令留在服务端终端或部署工具中。网页终端 `x` 数量参数上限 10000，较大普通资源发放使用表单。

## 登录与操作记录

- 登录会话最长 8 小时，Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 下附加 Secure；退出登录使服务端会话失效。重启需重新登录。
- 登录与写入接口检查同源 Origin；写入同时验证 CSRF 值、JSON 类型与 64 KiB 请求上限。错误密钥每来源一分钟最多尝试 5 次。没有通用默认密码。
- 页面使用同源脚本和样式，无外部 CDN；启用 CSP、禁止嵌入及 no-store，不将密钥写入浏览器持久存储。
- `gm-audit.jsonl` 先写入操作意图并刷盘，再执行变更，再保存结果。最近 1000 项已登记请求按请求编号去重，同编号不同参数拒绝；正常重启后仍生效。日志约 4 MB 轮转，保留当前文件与三个历史文件。
- 网络中断后网页保留原请求编号，使用“核对上次操作”查询/重试同一项。未完成的意图拒绝再次执行，异常可能涉及部分变更时显示“结果待核对”。人工核对玩家与记录后，可解除网页等待状态。此机制不宣称数据库事务或无限期恰好一次投递。

本地 Compose 保持只绑定 `127.0.0.1`。密钥文件、数据库和操作记录在同一持久数据目录，备份与恢复时一起保留。POSIX 文件系统创建密钥时使用 0600；Windows 沿用数据目录 ACL。调整访问权限或对外暴露服务由部署方另行配置。

## 实现与设计

HTTP 路由、鉴权、校验、操作日志和真实游戏适配器分别位于 `org.hkrpg.server.gm`；网页分为 app/api/ui/players/resources/mail/terminal/audit 模块。沿用本项目 Java/Javalin/JAR 发布结构，选择原生 ES modules，避免引入独立前端构建与 Node 运行服务。页面只使用真实接口数据，不注入演示玩家或统计数值。

游戏循环在在线玩家表锁内只复制本次快照，释放表锁后逐个取得玩家锁，再处理该玩家的场景和周期逻辑。网页操作使用相同玩家锁，防止循环持有表锁等待玩家、网页持有玩家锁查询表时形成相反顺序；两项真实 tick 方法回归先失败后修复。快照之后新增的玩家在下一次循环处理。

参考本机 LunaGC `abdedaf1969d0b4fdec153fc00d4bcff094ed1fb` 的 GM 玩家选择、资源检索及命令回显工作流；没有复制它的实现或添加运行依赖。界面使用独立生成的设计图，深色页面 `#151d28`、侧栏 `#131c26`、边框 `#303d4e`、正文 `#e5ebf3`、辅助文字 `#a1aec0`、主操作 `#58d5bd`；Segoe UI/Microsoft YaHei 字体、Cascadia Mono/Consolas 数值字体。桌面为顶部状态、左导航、玩家表格和右详情，手机为五项紧凑导航、表格与下方详情。用户、资源箱、邮件、终端、记录、搜索、刷新、箭头、恢复、闪电、警告和信息图标使用一致的 1.7px 描边 SVG。
