# 4.6 任务组延后卸载

原始P80112/F80112001/G2的NPC1013在主任务1000400完成后加载；1000401完成触发UnloadCondition，但DelayToLevelReload=true要求它保留在当前楼层，到下次新建场景才移除。旧代码没有读取延后标记，也没有对这个普通任务组应用加载/卸载条件，前置未完成便显示NPC，完成卸载目标后重新进入仍然显示。

参考March7thHoney-OpenSource固定提交fe00bdbda3c28ca33d01f171566aa35b5ab95083、AGPL-3.0：Common/Data/Config/Scene/GroupInfo.cs保留DelayToLevelReload，GameServer/Game/Scene/SceneEntityLoader.cs的SyncEntity保留当前组、LoadGroup在重建时应用卸载条件。该参考的注释以此黑塔场景解释延后卸载；本项目用固定资源与独立Java实现核对，不将参考注释当作本机官方客户端验收。没有导入参考可执行文件或运行依赖。

新增普通Town/Maze/Train场景中当前规范任务组的延后卸载路径。尚未加载时必须满足原始加载证明，且卸载条件明确未满足；未知卸载形状不能生成新演员。已经加载的组保留到楼层重建，仍遵守原有主任务拥有者有效/取消/过期检查，拥有者完成可以立即移除。未标记组、宇宙/挑战/试用场景及其他组类别沿用既有路径。这里只解释UnloadCondition上的延后标记，没有把LoadCondition或ForceUnloadCondition的标记推测为同一流程。
