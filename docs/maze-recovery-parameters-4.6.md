# 4.6 探索恢复参数

技能参数加载和生命回复按以下范围实现；能量回复仍保留待核对项，全部玩法与真实游戏客户端尚未验收。

`AvatarSkillParameterExcel` 将必需的 `AvatarSkillConfig.json` 与可选的 `AvatarSkillConfigLD.json` 按技能编号/等级加载到独立缓存。不同等级不相互覆盖；保留触发键、攻击类型、最大等级与原始参数单位。缺失参数、字符串/布尔值和非有限数不自动变成零。可选表不存在时跳过，存在但格式错误仍报告失败，不能替代必需表。没有覆盖运营资源，也没有将参考仓库变成运行依赖。

`MazeRecoveryValues` 读取明确的非负固定 `AddRatio`，并提供两个受限的动态绑定：原始 `LocalPlayer_PlayerBoy_MazeSkill` / `LocalPlayer_PlayerGirl_MazeSkill`、角色8001/8002、单一哈希-850066311、`AQAR`表达式对应各自 `SkillMaze` 一级参数0（技能800107/800207）。每次施放检查实际角色及其 `SkillList`，读取当前参数缓存，拒绝缺失表、错误触发键/攻击类型和未知绑定。原始参数0.15产生1500点归一化生命回复；本项目测试将参数改为0.22后无需重编译即可回复2200点。

这两个绑定是**受限推断**：本机固定DesignData字符记录同时包含正确角色名、原始哈希的zigzag编码，以及连续的 `00 00 00 01 09 SkillMaze 00` 字节；本机元数据提供三个FixPoint字段和读入类型/字符串/索引字段，`DynamicValueReadType.SkillParam=1`。字段与记录共同支持“技能参数0”的推断，但本次没有完成整个角色二进制解码器或原生表达式解释器。证据见 `client46-maze-recovery-evidence.json`，不能把这两个限定绑定推广成全部动态表达式已接通。

生命回复在玩家锁内作用于实际当前队伍，仅处理仍属于该玩家/队伍的施放者。归一化增量先封顶到10000再转整数，避免大比例转换或相加溢出；整队仍沿用既有不复活规则。普通队伍、剧情试用角色和宇宙队伍分别使用已有生命存储。零比例不通知，不能用未知参数补回15%。目前整数截断属于项目规则，未证明与原生取整完全相同。

任务仅支持明确HP类型、整队目标和缺省/明确 `Add`，拒绝显式客户端专用、其他目标、`MinRatio`/`ModifyValue`变体及其他运算。两种原生任务构造函数明确写入 `PropertyModifyFunction.Add=2`；偏移0x10的标记、客户端/服务端调度与通用效果链仍未完成交叉核对。服务端继续采用现有 `TaskInfo` 显式 `IsClientOnly` 过滤，不能据此宣称官方双端执行规则。

原始男/女开拓者HP叶、停云SP叶及五条技能/三条角色表行来自固定资源提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b`，夹具保留完整原始对象、文件SHA256和Git来源对象SHA256。恢复叶在测试中显式调用，不证明外围动画、等待、通用效果及完整原始秘技。

新增45项Java检查：参数加载16项、恢复29项。16项资源注册与23项恢复问题已在旧实现真实复现；首次测试编译问题不计入真实失败。恢复增加的三项检查核对宇宙生命不修改普通队伍，以及内部旧版/原生4.6处理器中实际被请求的试用角色以构造的22%叶施放、消耗秘技点并回复当前队伍；测试在攻击服务边界停止，不是KCP或真实客户端验收。能量参数50的绝对单位、归一化换算、其他动态绑定、完整动作链和其他玩法继续待完成。

探索能量回复已按停云限定技能参数/基础容量与明确Caster接入，普通初始化公式有本机静态证据；绝对任务单位和动态绑定仍为受限推断，特殊能量/完整执行器和客户端验收待完成。详见maze-sp-recovery-4.6.md。
