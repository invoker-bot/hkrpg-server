# 探索条件分支中的入战标记

已支持的 `PredicateTaskList` 分支中，`AddAdventureModifier` 的施放者标记和秘技 `AdventureTriggerAttack.TriggerBattle` 现在作为运行时动作记录。共享技能缓存只保留原有无条件默认值；每个施放者持有独立的暂态施放结果，开始下一次施放时重新初始化，命中及攻击阶段延续当前结果。

战斗入口读取实际施放者的结果：选择到忽略弱点标记时使用既有入战效果1000119，未选择时保留角色属性的既有效果；选择到禁止入战时不创建战斗。已经执行的分支不会因后续移除效果而重新判断，其他施放者或其他技能不能覆盖该结果。未知条件仍跳过整枝，未解析的修饰器目标和客户端专用条件修饰器不制造施放者标记。

新增20项Java检查：16项施放状态检查和4项战斗服务检查，其中最初14项状态回归有12项真实断言失败；单独恢复旧战斗入口读取方式后，4项服务检查有2项真实断言失败。状态检查覆盖成功/失败分支、嵌套顺序、下一次施放清理、不同技能、24个并发施放者及显式攻击阶段。真实Morphia内存Mongo按生产Fastutil编码保存、重载角色，原始文档不包含暂态标记，重载后读取默认值。普通Gson反序列化不支持Fastutil接口的测试夹具错误，以及首次服务测试缺少异常声明的编译错误，不计入行为失败。

战斗服务检查使用构造的火属性试用角色、槽位1、怪物和空波次测试关卡，仅验证入口及原生4.6效果结构中的标记、所有者/目标槽位。未验证可玩战斗、完整角色原始技能、官方脚本任务解释器或实际游戏界面。普通无条件标记仍保留既有缓存处理；本项不提供 `GlobalModifiers` 的创建/销毁、计时、监听、任意目标求值或完整修饰器生命周期。只在攻击阶段才设置的禁止入战标记，不能追溯改变此前已经完成的入战决定。
