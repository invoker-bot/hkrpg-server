# 经典宇宙下载装置的验证范围

2026-10-30 追加：地图 2 的黑塔教学下载已单独补齐，见 [教学下载流程](rogue-tutorial-download-4.6.md)。下文正式角色及拒绝额外列表的描述为原休息房间实现；当前字段 11 仅在原教学装置与指定 4000005 试用角色匹配时允许，其余普通下载限制保留。

Java 核心保留 LunarCore lite 4.2 内部消息。原生下载入口使用既有 4.6 定义和命令 1864/1821，不改生成类、冻结描述符、命令表或客户端文件。

下载目标必须是真实正式角色缓存中的同一对象，归属对象和保存 UID 均匹配当前玩家，基础编号及角色资源身份有效。当前命途另须有对应原始基础角色关系、当前玩家的实际命途记录和反向角色绑定。临时缓存、外来角色、脱离存储的命途及伪造资源不能取得本局生命/能量。下载仍使用入局冻结的初始能量比例；不改变普通角色生命/能量，也不自动部署。

请求装置字段 6 只允许出现一次，角色列表字段 14 同时支持标准打包和非打包编码，总计只允许一名正式角色。未知字段、错误线格式、重复装置、超出 uint32 的数值及额外列表字段 11 的任何出现均先拒绝，再解析。字段 11 的特殊角色含义尚未确认，不能用空列表绕过检查。

装置须是当前资源休息房 5 的实际 1001 场景对象，入口、楼层、资源组和原始实例匹配，且处于 Closed/Open。下载生命、能量和站点/房间/组/实例使用标记在同一玩家文档保存，随后装置变为 Locked。重建场景实体编号不能重用。每局每台一次免费下载一名采用本项目规则，未确认全部官方限制。

新增 `UniverseDownloadValidation46Test` 27 项检查，其中 18 项在修复前真实失败；原有下载和编队的 19 项继续通过。正式下载对象改用固定资源的 1202，另有 8001/8003 实际命途关系。初始单人队伍和单元场景位置仍为隔离夹具。14 份原始记录保留九份源文件的 SHA、固定提交和 Git blob SHA；提交为 `724b139d8c9c32d12552eb95745a4fee72bfe48b`。旧测试的列表排序调整不计入行为修复。

`scripts/smoke-rogue-download.py` 使用独立资源视图和 H2 存档。只将本服首房池安排为原始房 306；房间、入口 8000103、组 22、装置实例 300004 和角色表保持原值。独立欢迎邮件实际取得 1202/1102，后者用于已用装置拒绝验证。16 项 UDP/KCP 检查覆盖重复装置、整数截断别名、未持有正式角色、未知额外列表、打包下载、可用角色池、装置锁定及原生双人编队。实际队伍为 8001/1202，领队槽 1，两人生命 10000、能量 5000、碎片余额 50；下载前保留单人部署。离开恢复普通队伍 8001 的原始能量 0 和所有普通队伍状态。同 UID 首次、重连及正常 H2 进程重启三份快照保留下载、编队、领队、生命/能量和装置使用状态；九份原始 SHA 不变。首轮探针正式类型枚举错误已修正，属于验证夹具错误，不计真实先失败。

只读本机客户端证据见 `client46-rogue-download-evidence.json`。七个方法按元数据身份和 PE 完整 unwind 范围核对并保存字节 SHA，包括请求构造、上限读取、响应消费及两组 WriteTo/.cctor。请求命令 1864、字段 6/14/11，响应字段 13/15/6 与冻结定义一致；未用参考文件的偏移注释代替本机证据。

以上证明当前项目规则的服务端逻辑和合成网络流程。特殊下载类型与上限、全部宇宙模式、官方剧情取得条件、完整游戏 UI 以及写入中断的原子性仍待完成或验收，功能状态保留部分完成。
