# 剧情屏障完成目标后仍挡路

## 现象与定位

2026-10-23，用户在卡芙卡和银狼的开场走廊报告无法继续前进，随后明确可以自由移动，只是穿不过橙色屏障。因此本次处理场景屏障生命周期，不改动角色教学、移动权限或试用队伍。

原始基座舱段组 17 的物件 `100006 / 300001` 位于 `(-18.59, 0.147062, 178.39)`，配置要求子任务 `100010130` 完成后卸载整组。用户存档中该目标已经完成；只读在线快照也确认组 17 的 `loaded=false`、`shouldLoad=false`、实体列表为空，角色未在战斗中。用户仍看到该处屏障，说明服务端实体列表清理不能作为客户端屏障已消失的验收。

`Scene.refreshMissionGroups` 原来删除实体和服务端组登记，只发送类型 3 的逐实体变更，遗漏类型 2 的整组卸载通知。客户端组图、局部触发器和效果没有收到明确的卸载。修复在原有逐实体删除完成后，发送带准确楼层与组编号的 `SCENE_GROUP_REFRESH_TYPE_UNLOAD`；即使组中已经没有服务器实体，也会卸载一次。重复刷新不重复发送，原有任务前置、卸载条件和存档记录仍决定是否放行。

## 来源与范围

原始组 17 和大厅组 33 与 [TurnBasedGameData 固定提交](https://github.com/Dimbreath/TurnBasedGameData/tree/724b139d8c9c32d12552eb95745a4fee72bfe48b) 的 JSON 内容逐项一致。完整组对象、屏障定义和任务条件片段保存在 `src/test/resources/fixtures/story-group-unload-4.6.json`，包含安装资源文件的 SHA-256。楼层和主任务基础资料复用既有开场场景夹具；测试玩家历史为隔离构造，任务片段保留原安装补全来源。

修复位于共享任务场景组刷新路径，适用于由该路径卸载的组。本次原始配置正向覆盖大厅组 33（目标 `100010122`）和走廊组 17（目标 `100010130`）。它不把所有屏障强制打开，不预先完成后续监控室战斗，也不修改原资源或生成协议。4.6 整组卸载使用现有描述符的类型 2、组字段及楼层字段，与原类型 3 的实体删除分开保留。

## 验证边界

`StoryGroupUnload46Test` 先在旧实现上复现三项失败：两个原始屏障组删除后没有整组卸载通知，以及无剩余服务器实体时没有卸载通知。其余检查覆盖前置未完成和无关任务不能提前放行、重复刷新幂等、状态重载后不再生成已完成屏障。捕获并转换实际发送包，核对 4.6 的楼层、组号和卸载枚举。

`scripts/smoke-opening-stage-win.py --barriers --readings` 在独立账号、端口与 H2 数据库中，从初始卡芙卡推进首战、剧情门、大厅战斗、银狼入队、走廊门和走廊战斗，核对战败保留、胜利卸载、下一个目标仍待完成、同 UID 重连和正常进程重启。移动和战斗结果为合成请求，不替代真实客户端碰撞、演出或逐点验收。诊断与验证证据保存在忽略目录 `build/opening-switch-lock-20261023/`。

新增 5 项 Java 回归及相邻 19 项开场加载检查全部通过。旧 JAR 的实际网络流程在大厅击杀目标完成后因缺少整组卸载通知失败，记录为 `native-red-failure.log`。修复版通过 305 次 UDP/KCP 请求、6 次同 UID 会话、4 次正常停服及 3 次 H2 进程重启；两个原始屏障组的卸载通知、走廊战败时保留、胜利后消失、重连/重启不再生成和下一战斗目标仍未完成均已核对。首次扩展重连检查误用银狼实体发送卡芙卡技能，修正探针选择当前队长后全部通过；该夹具失败单独保留，不计为服务端产品回归。

`scripts/build.ps1 -TestForks 8` 完整构建通过：576 组、14,880 项测试，零失败、错误或跳过；其中新增回归 5 项。标准启动/登录烟测通过两次进程运行，确认 H2 账号持久化。验证后核对 2,196 个构建输入未变化，完整构建、原生网络探针与候选镜像使用相同 JAR，SHA-256 为 `e013abd47c9cd42295c226c8c4cf2fdd57b1cfb087e2952754a22dcf218c036e`。

服务发布结果将在部署后补记。真实客户端穿过屏障仍待部署后复测；运营账号 10001 不重置、不跳任务。
