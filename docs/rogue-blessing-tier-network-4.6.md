# 4.6 祝福图鉴奖励的网络正向领取

在 [祝福图鉴任务与奖励](rogue-blessing-quests-4.6.md) 的 90 项 Java 回归及单祝福网络进度基础上，增加两个真实 UDP/KCP 正向场景：原始存护任务 3000101 需要五个不同祝福，领取 RewardData 106001 的 80 星琼；永久追加任务 3000130 需要 24 个不同祝福，领取 106005 的 30 星琼。

玩家从空收集记录、零星琼开始。每次实际开始探索、找到原始 1007 商人、查询库存、购买尚未收集的原始一级祝福，再检查重复购买拒绝、实际余额/祝福通知、暂停和图鉴查询。库存没有新祝福时先暂停，再放弃并开始下一次探索；不会直接写入祝福历史或任务完成记录。达到原始不同祝福数量后使用原生 TakeQuestReward 请求领取，核对真实星琼通知在成功响应之前、实际 Item1 数量、唯一成功任务编号、再次领取无奖励，以及原生任务查询中的 Closed 状态。

之后在同 UID 的重连、正常关服/H2 重启、结束探索及再次正常重启中复验全部收集记录、钱包和 Closed 状态。每项包含五份会话快照、四次 stop 正常关服和三次 H2 进程重启；后续会话不会再次购买或发放奖励。

## 隔离夹具和验收边界

保持安装资源、玩家运营配置及数据库不变，全部流程在新的 build/smoke 子目录中执行。首房和商人入口沿用此前隔离场景；初始碎片改为 30,000。隔离资源副本只将选定的五个/24 个原始存护祝福的 UnlockIDList 置空，其他祝福加上一个未定义的锁定条件，以控制商人候选资格。全部原始祝福定义仍保留，IsShow、等级、命途、MazeBuff 绑定、53 个图鉴目标、阈值、奖励及其金额均不修改。商人价格是已有项目规则；这些流程不能证明官方房间生成、完整解锁门槛或原价。

未在服务器、数据库或响应中预置完成。数量由实际购买累计，原始 80/30 星琼通过正式背包/任务领取路径到账。客户端使用合成的原生协议连接，不能等同于真实国服游戏 UI 验收，也没有验证断电原子性或自动对账。

运行方式：

```powershell
python scripts/smoke-rogue-shop.py --verify-handbook-blessing-tier 3000101
python scripts/smoke-rogue-shop.py --verify-handbook-blessing-tier 3000130
```

原型已通过两个场景，最终构建、独立源码副本和字节/来源核对以 `build/blessingtiers-4364-source-verification.json` 为准；该文件产生前不视为本批最终复验完成。上一批单祝福核对仍保留在 `build/blessingquests-4364-source-verification.json`，其网络正向领取标志仍保持 false，避免将新证据写回旧构建。
