# 4.6 支持日常委托自动分配

MissionManager.refresh现在在登录已有调用点和任务查询入口分配支持的日常委托。原始88条委托的主任务接取门均为Manual、开始门均为Auto；资源不修改，自动分配是明确服务器策略，通过原有手动门判断后创建实际主任务与第一个子任务，而非伪造完成记录。客户端GetMissionDataCsReq可以看到已分配的实际进行中委托，无需预先知道编号并发Accept请求。

候选必须通过DailyMissionData前置、原始活跃目标2100003的1010403教程解锁、每日数量/分组限制及已有纯对话/内部汇总图检查。按玩家UID和国服04:00日界形成稳定随机种子，在排序后的候选分组、组内编号中抽选；结果与主/子任务一起保存，当日查询、登录、并发请求和重登不重抽。原始DailyCount=1已验证，不宣称官方抽选权重、组内剧情顺序或数量大于1已验收。

已完整结算且符合既有重接边界的委托，下一日可自动归档旧轮并创建新轮。旧委托尚在进行时保留原图，不推测过期规则；缺失前置、损坏历史、复杂变量图和不安全的重接候选不自动接取。未完成委托的过期、跨日完成后的重接及复杂任务图仍待实现。

同时修复轮次记录异常时的奖励结算缺口。已发放后、最终关闭前的合法FINISHED状态可凭正确周期及收据关闭，信用点不再发放；错误未来/过去日界、空周期、缺失接取周期或损坏旧归档时，冻结/结算及旧奖励回退路径都暂停，保持任务与原始奖励证明供核对。异常周期不能生成新奖励键再支付已经发放的5000信用点。

新增17项Java检查，原实现17项中12项AssertionFailedError先失败，build/dailyassign3832-original-red.xml留证。覆盖无Accept请求自动分配、源Manual门保持不变、两种实际前置、12次不重抽查询、24个并发查询、原始下一日重接发放、未完成旧轮、复杂图拒绝、32个UID三候选/两分组的稳定结果、实际Player文档两次Morphia恢复、冻结4.6GetMissionData入口字段，以及五种坏轮次不重复结算和正确轮次的合法关闭恢复。

沿用33条原件的daily-assignment夹具与daily-today夹具中的原始活跃池条目，合计引用14份原始资源，固定TurnBasedGameData提交724b139d8c9c32d12552eb95745a4fee72bfe48b。三个教程完成历史、位置、日常池、固定时钟及保存计数是夹具；32个UID的选择分布不是官方随机概率证明。

全量3832项Java、15项Python、151份冻结协议、独立源码构建及Dispatch存储冒烟以build/dailyassign-3832-source-verification.json的passed为准。没有新增实际UDP/KCP、客户端登录/任务UI、真实跨日或断电原子性验收。自动分配与已结算纯图重接尚不构成完整日常系统，宇宙、完整剧情和活动亦继续待办；没有修改运营数据、配置或原始资源。
