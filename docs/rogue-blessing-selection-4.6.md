# 4.6 祝福领取的精确资源检查

经典宇宙待选菜单的一级和强化祝福现在统一要求对应 ID / 等级的战斗资源仍可读取，且资源行自身 ID / Lv 与菜单匹配。已经持有该祝福也会拒绝，避免覆盖或降级已有祝福。失败发生在菜单消费、持有、永久图鉴、回响排队及保存之前，整份待选状态保持原值；资源恢复后，可以继续提交同一菜单请求。

20 项行为回归覆盖两个等级、缺失资源、索引仍存在但行身份或等级错配、既有一级/二级持有，以及领域调用与 4.6 原生 5676 请求。每项包含拒绝后的完整 Gameplay JSON 对比、恢复前置后成功领取、同请求重试及 Gson 保存重载。原实现有 18 项真实行为断言失败；强化候选的两项资源缺失检查原来已经通过。最初借用的三候选夹具与本批单候选来源不符，已单独归档为夹具错误，没有计入这 18 项失败。

来源夹具保留 TurnBasedGameData 提交 724b139d8c9c32d12552eb95745a4fee72bfe48b 的原始祝福 612050 两级完整 RogueBuff / RogueMazeBuff 行、对应两份原件哈希和逐行哈希。一级菜单由实际服务端生成；二级菜单是明确的待选状态夹具，没有声称真实取得信标着色剂。角色、地图、通关和资源恢复同样是隔离前置。原生请求使用现有协议及字段，没有新造命令、字段或协议类。

全量 11,720 项 Java（447 类）已执行；首次发现两项旧测试缺少本次要求的一级战斗行，第二次全量仍有一项同类夹具遗漏。补齐两个合成祝福的资源行后，该类 6 项重新通过；最终 11,720 项通过结果由未改动运行时代码的全量结果与这 6 项夹具修正结果合并，未声称单次全量零失败。累计 1,083 项 Python 检查沿用前批已核对结果，测试文件未变，本批没有重跑完整 Python 套件。3,213 个源码文件与 151 份协议快照核对通过。最终产物通过 49 次原生 KCP 请求、4 次正常关服、同一 UID 的 3 次 H2 进程重启：五场原始资源遭遇的胜利报告生成菜单，菜单和目标持有没有预写；正常关服后仅移除独立夹具中的一级 RogueMazeBuff 行，重启仍保留原菜单并拒绝领取；恢复资源后，同批菜单可成功领取，再次重启后持有和碎片余额保持一致，旧领取请求被拒绝。2,261 份原始来源文件未改动。区域难度、地图房间路径和候选资格为明确夹具，未更改原始房间、场景组、NPC 或战斗关卡。报告为 `build/blessing-selection-verification.json`，产物为 `build/blessing-selection-certified.jar`，SHA-256 为 `5a017159395213873739b6e242f15469a236d429a4c8bac19356bb44f8b4eb67`。

二级候选、错误资源身份和已有持有仅由隔离 Java 请求验证。永久图鉴的 JSON 恢复经过 Java 验证，本批没有单独查询其 H2 重启后的状态。网络战斗使用已接受的胜利报告，没有复现客户端战斗输入；真实游戏 UI、全部祝福战斗演算和完整宇宙验收继续待完成，功能保持部分支持。
