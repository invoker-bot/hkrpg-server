# 探索任务分发边界

仅由完整任务类型名选择服务器动作；自定义类型包含已知类型的部分文字，不会被当成同一种动作。明确声明 `IsClientOnly=true` 的任务不登记服务器动作、回调或共享入战标记，包括判断容器的内部列表。

`PredicateTaskList` 继续由已支持判断选择成功或失败列表。其他任务不能仅凭存在 `SuccessTaskList` 就展开内部动作；例如原始 Cyrene 的 `SetComponentAssetLoadStateWithAnimState` 需要动画及加载状态，当前没有实现其成功判定。对其直接展开会绕过前置条件。其原始完整对象、固定资源提交、路径及 SHA 保存在 `maze-task-dispatch-4.6.json`，隔离检查不代表完整 Cyrene 技能可用。

明确的 `AdventureTriggerAttack`、`AdventureFireProjectile` 使用各自攻击或弹体回调；无关成功列表不会覆盖这些回调。未知或缺失任务类型只跳过该任务，独立已知同级动作保持原顺序。这是当前简化解释器的规则，不能据此认定未知等待及其后续同级动作的时序已经正确。

无条件 `AddAdventureModifier` 的显式目标必须是 Caster，未声明目标时保留旧版定义缓存兼容查询，并按脚本位置写入本次施放元数据；条件分支仍要求明确 Caster。空白名称不登记。这里维护的是既有标记缓存和每次施放元数据，不包含完整修饰器创建、销毁、监听或跨场景生命周期。
