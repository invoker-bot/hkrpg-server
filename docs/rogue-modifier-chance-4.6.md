# 4.6 效果概率、修正列表与筛选

`RogueModifierChance46` 补入普通标准数值的概率计算、名称/行为条件筛选和显式临时列表绑定。它继续使用 `RogueModifierNumbers46.Dynamic` 和三元组接口；没有把未知动态表达式、实际组件字典、抗性或随机命中默认放行。宇宙玩法仍为 `partial`。

## 已实现的顺序

原始 Chance 先在来源上下文求值，随后读取覆盖上下文。直接覆盖使用这次已读取的上下文，保留原始标准数值；即使存在直接覆盖，原始求值的副作用和失败仍然发生。没有整数舍入或 0～1 限幅。

没有直接覆盖时，非负原始值才执行 `base × (One + percent) + additive`。百分比和加项分别再次读取当前覆盖上下文；负值哨兵跳过这些单元。直接覆盖能够替换负值哨兵。

外部修正忽略各记录的直接覆盖单元，只按列表顺序累计百分比和加项，最终统一执行 `input × (One + Σpercent) + Σadditive`。输入为负、列表不存在或为空时保留输入；每项的百分比和加项分别读取其当前上下文，每项结束后重新读取列表长度。项目支持最多 255 项、标准编码且显式绑定上下文的有限输入；此限制不是客户端的列表上限。

非空名称按 UTF-16 内容精确比较，命中后不读取行为标志。名称为空/缺失时，需要至少一个定义包含且组件没有屏蔽的行为枚举；缺失屏蔽集合和缺失组件均不屏蔽已匹配标志。非空标志列表配合缺失定义继续失败。收集器保留对象身份、重复项和遍历顺序，无匹配时返回缺失列表。

显式 `AdjustmentPool` 先收集，后求值，仅在正常返回且列表存在时回收同一个列表；失败时不加入原件不存在的 `finally` 回收。默认 Java 收集器使用普通列表，未声称实现客户端的原生引用池。

## 原件与验证

本机 4.6 的 GameAssembly、global/startup 元数据保持既有 SHA 基线；冻结证据为 `src/test/resources/fixtures/rogue-modifier-chance-4.6.json`。九个 PE 完整方法共 9,875 字节包括原始入口、Chance 构造、概率覆盖、外部聚合、收集、筛选、行为查询、字符串比较和 FixPoint 常量构造。七类声明字段、字符串到修正对象字典、行为枚举集合，以及 `AcquireList<MDJOLMBECHA>` 的实际 MethodSpec 单参数均独立核对。泛型声明本身没有原生主体地址，未把共享调用地址冒充已核对的泛型方法实现。

One 使用实际初始化来源；Zero 从 16 字节配对初始化器的第二个字读取，并匹配完整构造器的配对写入，未用虚拟零填充代替初始化证据。六条原始共鸣任务全部省略 Chance，保留构造器的负值默认，不把省略当成 0 或必定命中。

三项有意义的 Java 回归先因计算顺序、负值哨兵和多项乘算行为失败，修复后新增 38 项 Java 与 10 项 Python 通过。全量 `scripts/build.ps1`、9,331 项 Java（384 个测试类）和 606 项 Python 均通过；2,849 个交付源码文件、151 份协议快照核对通过。结果为 `build/rogue-modifier-chance-verification.json`，封存 JAR 为 `build/rogue-modifier-chance-9331-certified.jar`，SHA `494eec41483b8d5d6d4764647d28ea19969eaa10c3ca80602beb2c001f0ff135`。
