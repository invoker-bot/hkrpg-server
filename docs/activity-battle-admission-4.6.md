# 活动占用时的战斗入口

钟表剧本、音游或跑酷局进行中时，普通场景事件、动态难度事件、直接关卡、材料副本、迷宫攻击和材料关卡再次进入均拒绝创建新战斗。剧情进入或返回仍在转换时，再次进入材料关卡也会等待转换完成。检查在分配战斗编号、冻结波数与体力、执行迷宫技能回调或处理场景实体之前发生；保留原有玩法状态、场景实体和体力。已有剧情分支与宇宙局仍可执行自身战斗。

20 项新增行为回归在修复前均出现真实断言失败，修复后均通过。场景事件和动态难度事件使用已匹配的 4.6 原生请求与来源事件目录；迷宫攻击调用实际入口与场景怪物，材料副本检查实际工厂的波数和体力冻结，材料关卡重入检查编号分配。每种占用释放后重新验证可创建战斗。

占用及释放由隔离的域状态夹具设置，资源与角色使用已有完整测试夹具或合成目录。没有用这些测试证明官方活动全内容，也没有证明客户端 UI 交互。首次 18 项回归后来扩展了剧情进入与返回转换两项，最终失败基线与候选均为 20 项。本批不增加命令号或协议字段。

全量 11,651 项 Java（445 类）及新增 20 项行为回归通过。Python 文件未变化，沿用前批 1,079 项独立检查，本批未重跑该套件。3,200 个源码文件与 151 份协议快照核对通过。最终产物复查既有钟表剧情 151 次 KCP 请求、7 次正常关服、同一 UID 的 6 次 H2 重启，2,316 份来源文件保持原值；这些网络请求验证钟表正向与恢复流程，入口冲突仍由隔离的 Java 原生请求夹具覆盖。报告为 `build/activity-battle-verification.json`，产物为 `build/activity-battle-certified.jar`，SHA-256 为 `b2cccd53ff62e91716582b57eab105919f2cca4d115b2fd4a0c9defb7ca510c3`。完整战斗、剧情、宇宙与活动玩法仍保持部分支持。
