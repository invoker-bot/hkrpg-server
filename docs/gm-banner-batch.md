# GM 卡池批量管理与配置补齐

已配置卡池现在按基础卡池、版本升序、期次和编号排序，同一版本的角色池与光锥池相邻。版本来自已核对的卡池 ID 模板，运营自定义 UP 不会让已知版本信息丢失；无法匹配模板的自定义卡池排在末尾。已配置页支持版本、类型、状态与文字组合筛选。

列表新增逐项勾选、本页全选、全选筛选结果、清空及批量启用/停止。翻页保留勾选，改变筛选或视图清空勾选，执行前展示本次数量和目标。一次批量操作最多 500 个，复用现有会话/CSRF、确认弹窗、请求编号、审计与重放去重。后端在同一锁内验证整批候选，只写一次备份与原子替换；缺失 ID、已过期排期或保存失败不会发布部分切换结果。

当前资源支持的目录包括常驻 1001、新手 4001，以及 1.0–4.6 的 278 个已核对角色/光锥活动池，共 280 个。旧运行配置只有 53 项，活动池只包含到 2.5 的部分条目。新增“补齐缺失配置”仅追加缺少 ID，保留已有内容、扩展字段、排期和开关。新手五星候选使用现有七名基础五星角色，四星与三星沿用已有抽取服务的候选规则；新手类型及 ID 对应现有 4.6 GachaBasicInfo 资源。联动专用类型及 4.6 以后的资源不包含在此目录。

新增配置默认停用。新增活动池以 `gmTemplatePending=true` 和空排期保存，首次明确启用时设置 1–365 天开放窗口，默认 30 天。既有排期的恢复启用不延期；已经到期的池仍通过历史复刻重新排期。停止或重复请求不会重设时间。新手与常驻作为基础池按开关控制，不安排首次活动窗口。`scripts/complete-gm-banner-defaults.py` 可复核新安装默认目录；启动默认安装逻辑不会覆盖已有运营文件，已有实例通过明确的补齐操作迁移。
