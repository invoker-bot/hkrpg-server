# 4.6 角色弱点栈移除和状态刷新

实现CharacterWeakness普通执行路径的四种撤销：Override0、Protected1、Attach2、Secret3。入口按实际枚举及独立跳转表分派，栈位置采用无符号边界检查。先清除对应占用位，再检查并清零对应掩码槽，随后刷新该类别聚合和活动列表。后续槽不存在或越界时，已经清除的占用位保留，不回滚其他状态；没有改动其他三类栈。

四类聚合先保存旧掩码，再清零当前聚合，然后仅合并实际占用槽。覆盖类别在没有占用槽时读取默认弱点；占用的零值仍算存在，抑制默认回退。秘密类别合并后与当前附加/覆盖掩码的并集取交集。聚合值变化才设置脏标记，值未变不会清除此前已有脏标记。聚合阶段缺失/越界保留已写入前缀，不提前发布新的成功状态。

活动刷新在脏标记为false时返回，不要求世界、目录或视图列表。否则捕获附加/覆盖并集，活动掩码为该并集去除当前保护位；随后清空当前视图，清零全部掩码。按明确绑定的伤害类型目录生成视图，读取每次当前目录，保留目录顺序。候选必须满足原件的有符号正值位测试，状态优先级为秘密3、保护2、普通1；后续候选读取当前类别掩码和当前视图容器，附加/覆盖候选并集保持最初捕获值。每个成功追加项再合并当前全部掩码。

当前通知开关启用时，成功生成列表后向明确通知绑定传递当前owner、事件0x453和immediate=true，owner允许明确为空。通知成功后才清除脏标记；通知失败保留已经完成的掩码、视图和脏标记，重试可重新刷新。通知回调再次置脏而正常返回时，普通原件的末尾清零仍覆盖该写入，没有擅自改成延后保留。
