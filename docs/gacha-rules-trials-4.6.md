# 跃迁规则、详情与角色试用

本轮针对当前本服的始发、群星、角色活动和光锥活动跃迁；实际奖励对象以运营卡池配置及通过资源校验的基础池为准。详情页读取同一份有效候选，不读取或回显 SDK 附带的账号参数。页面包含跃迁规则、实际 UP 与基础对象清单；历史记录仍未实现，不把它展示成空记录。

## 新手与保底

- 始发跃迁仅接受十连，每十次消耗 8 张星轨通票，累计最多 50 次；未提前获得五星角色时，第 50 次保证获得五星角色。独立保存累计次数、是否已获得五星和四星/五星保底；与群星跃迁和活动跃迁相互独立。
- 五星基础概率：始发、群星、角色活动为 0.6%，光锥活动为 0.8%；群星和角色活动分别以 90 次、光锥活动以 80 次为五星硬保底。四星基础概率分别为 5.1% 和 6.6%，每十次至少获得四星或以上对象。
- 角色/光锥活动池分别共享各自五星与四星保底。默认五星 UP 为 50% / 75%，四星 UP 为 50% / 75%；非 UP 后下次对应星级保证 UP。基础池也包含当期 UP 时，实际获得 UP 的概率会增加，获得 UP 后保证状态会重置。活动四星基础池包含角色和光锥。
- 五星和四星的递增曲线为本服兼容近似：公开说明未给出每次跃迁的完整软保底曲线。角色和群星五星使用第 74 次起每次增加 6 个百分点；光锥五星使用第 66 次起每次增加 7 个百分点；四星的本服递增从后段开始。不能宣称与官方逐次概率完全一致。
- 本服明确配置的 `eventChance` 优先于默认值；升级不会覆盖已有运营文件。GM 新建/复刻光锥池默认 75%。首次启用带 `gmTemplatePending` 的旧光锥模板时，只有编号、五星和四星名单均与内置历史模板一致且旧值为 50% 的条目，才将旧生成器默认值改为 75%，并在操作结果中告知；已排期、修改过候选或使用其他显式概率的条目保留。当前本机 113 项待启用旧光锥模板均属于此类。此前新手与群星共用保底且没有独立累计记录，无法可靠推算旧账号已抽多少次，升级时不会凭猜测更改旧常驻保底或补发奖励。
- 玩家记录和各库存物品分存储文档；正常保存及重启经测试，不等于异常断电时扣票、奖励和保底的跨文档事务具备原子性。

## 角色试用

固定客户端的常驻试用页面读取 `AvatarDemoModuleConfigRow.AvatarDemoType=Normal`；本机资源中有七个此类关卡，模块同时属于 `ActivityConfig.ResidentModuleList`。群星跃迁开放时允许这些真实关卡进入，保留试用资源、原队伍恢复和领奖防重；没有将普通限时试用自动变为常驻。客户端读取链经本机固定版本静态核对，不代表屏幕显示已验收。

为开放中的角色活动池寻找原始 `ActivityAvatarDemo`、`ActivityConfig`、`ActivityModuleDemo` 与 `AvatarDemoConfig` 的唯一对应关系：同一活动可以包含并行池的多位五星，但四星集合必须和本池一致。仅在卡池当前开放、配置有效、活动面板前置满足且匹配唯一时，按资源派生当前 UP 对象的活动面板/模块时间窗；其试用进入、退出和领奖沿用既有试用副本和防重逻辑。显式运营窗口优先，未找到唯一匹配的卡池不会猜测试用映射。当前实际运营配置中池 2001 对应面板 20001/模块 2000101，池 2002 对应面板 20002/模块 2000202。

2026-10-31 对本机 139 项角色活动池配置和 4.6 资源作只读匹配审计：111 项能找到唯一完整关系，28 项缺少可验证的模块或对应关系；后者中的部分较新活动存在缺失模块，不能由本轮工作宣称已可试用。审计包含停用的历史模板，不改变任何运营配置。匹配数量不等于全部关卡已做实机验收。

本机固定 4.6 客户端的跃迁试用按钮会读取可用角色试用活动；客户端资源和本服配置的活动时间或前置条件仍可能限制按钮。该映射、测试号的原生网络请求和网页浏览器结果不能替代真实游戏窗口中的试用页面、战斗和奖励验收。
