# 4.6 修改器实例查找与来源筛选

`RogueModifierSearch46` 补入明确候选集合的普通匹配、逐项查找和当前实例回退。名称/状态/类别、施加者、来源实体和能力筛选按原件保留顺序；候选是明确提供的状态，不代表已创建或安装在线修改器。

先比较名称，使用区分大小写的字符串相等，双方为空也可相等。状态筛选0要求实例状态按无符号比较小于等于1，筛选1只接受Alive=1，其他原始筛选整数跳过状态限制。来源类别100是Any，其余整数精确匹配。这是来源类别 `ModifierStackingFlag`，不能把它当叠加模式。

施加者参数为-1或0时直接通过，连非空能力筛选也跳过。其余参数读取当前任务上下文和施加者实体；实体自身编号直接匹配时不读取来源组件，编号不匹配则再次读取上下文和施加者。第二个实体为Destroyed=8时使用其自身编号；否则查询明确绑定的来源实体编号，组件缺失退回自身编号，第二个实体消失则为0。读取能力时还会再次读取上下文；即使施加者不匹配也不短路，按对象身份比较能力，最后合并结果。

来源组件已通过实际MethodSpec注册确认是 `GetComponent<APFKPHPNCEC>`（56967）。实际读取是 `<SourceEntityID>k__BackingField`，UInt32、十进制偏移36，即指令的0x24；十进制24是组件的列表字段，不能混用。Java以Int32保存同一32位编号，不改变负值位模式。明确绑定名称为 `sourceEntityId`，没有把整个未知组件替换成统一的“所有者”假设。

逐项查找返回首个匹配对象。每个不匹配后重新读取当前列表，保留回调期间列表变化；空列表可以继续，缺失列表或元素拒绝。普通搜索失败后读取明确保留名称，只有相等时才查看当前实例；先读一次判断非空，然后再读一次返回，第二次可能已经改变或为空。原件保留名称的值及实际世界执行栈未解析，因此必须由调用方提供，不设置隐含默认回退。
