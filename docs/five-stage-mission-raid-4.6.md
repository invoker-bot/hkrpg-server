# 4.6 五阶段符玄任务副本

本批继续补齐原始 `43201`，保留五个主任务 `2020502 → 2020503 → 2020504 → 2020505 → 2020506`、前置/后续 `2020501`、`TrialOrPlayer [1101208]`、7号 `IncludeAvatar 1208`、`SkipUI`、`RecoverType [Unknown]` 与原始无副本额外奖励行。来源固定为 `724b139d8c9c32d12552eb95745a4fee72bfe48b`，30份完整Git blob、161条完整原始记录、42个子任务逐条比对；原件及安装资源保持，换行分别记SHA并核对完整JSON，见 `build/five-stage-raid-source-proof.json`。

原始结束目标 `202050211/202050310/202050409/202050505` 分别执行服务器转场到 `43201002/43201003/43201004/43201005`。仍由现有 `MissionRaidSequence` 检查每阶段来源、原始接取门、结束目标依赖及实际转场收据。第五阶段原始 `202050602` 完成且所有先前阶段证明有效后才结算副本；后续/父任务不由此固定完成。只有DisplayRewardID的子主任务不按展示奖励发奖。

第三阶段原始 `202050410` 与 `202050412` 都是完整单指令 `ReplaceTrialPlayer`，分别选择 `1101208` 与 `1101001`，保持原始 `None` 接取门并在明确接取后执行。初始只选 `1101208` 时条件观察已有角色；混合入场队伍已持有同一基础试用角色时，替换引用所属基础角色，独立保存剧情队伍数值并保留一次原始执行收据，避免身份重复。后续 `1101001` 由同一原始任务上下文创建，入口允许选择的试用列表仍只有 `1101208`。

剧情试用快照新增 `entryRoster` 保存实际入场队伍。原始替换在验证该队伍仍有7号要求的角色、所属缓存/资源/基础快照有效后，可以按明确任务指令选择当前出战角色；该入口限制不阻断已验证的剧情替换。此规则限于无额外等级/人数/命途/固定领队/禁止换队规则的TrialOrPlayer子集；未知复杂规则保持待实现。快照损坏时，在角色发布前拒绝恢复。旧数据未记录的入口队伍不会自动补造。创建/添加与非该类型队伍沿用原校验。

基础队伍与剧情视图的生命、能量及秘技点分别保存。暂停再进入保持当前阶段与原始执行收据。第三阶段完成后释放其剧情角色，后续阶段恢复自身入场基础队伍；此处采用任务所属范围，不证明所有其他副本的跨主任务角色保留。生成协议、命令号、版本常量及正式角色/编队文档维持原样。

目前14项新增Java检查通过：原始五阶段入口/前两次转场、试用/正式替换、混合队伍复用、四次转场后结算、错误入场角色、受损入口证明、独立数值与暂停重入、三个实际Player/Morphia场景各两次恢复。前三项行为与四种受损恢复在修复前失败，见 `build/five-stage-raid-behavior-red-final.xml` 和 `build/five-stage-raid-entry-proof-red.xml`。初期资源夹具未按装备加载顺序绑定、恢复夹具修改了只读剧情视图的失败属于夹具修正，不计为实际玩法缺陷。
