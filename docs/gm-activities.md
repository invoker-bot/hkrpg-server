# GM 活动目录与往期活动排期

网页 GM 的「活动管理」可搜索当前资源中的往期及现有活动，按活动模块、常驻模块、角色试用、缺少面板关联，以及本服排期状态筛选。无需选择玩家，零在线也可操作。

选择活动后可立即开放 1–365 天，或按浏览器显示的本地时区填写开始和结束时间，最长 365 天。时间以 Unix 秒保存，开始时刻包含、结束时刻不包含；自定义结束时间必须晚于执行时刻，协议范围截止 `4294967295` 秒。可提前设置未来窗口，到期自然停止进入。

「关闭活动」保留原时间并停用模块；「按原排期恢复」恢复同一时间，不延长。原窗口已到期或模块配置不齐时需设置新窗口。重新开放保持玩家进度及领奖收据，已经领取的奖励不会重新发放。关闭阻止后续通过现有时间门槛的入口，不会撤销已进入流程或正在进行的战斗。游戏中需重新打开活动页，GM 列表可点「刷新活动」更新到期状态。

## 目录来源与边界

- 使用当前 `resourceDir` 的 `ExcelOutput/ActivityConfig.json`，仅接受明确的 `ActivityPanelID`；名称从 `ActivityPanel.json` 的标题/页签及中文 TextMap 解析，不根据相同数字猜测面板。
- 每条活动的 `ResidentModuleList` 与 `ActivityModuleIDList` 合并展示和排期，保留模块原身份、面板原始解锁条件。不同活动共享同一模块时，现有玩法只能按模块校验，整条标为仅查询，避免关闭一个活动仍能经另一面板进入。
- 角色试用继续跟随卡池管理；缺少明确面板、没有模块、模块共享或面板未加载的活动仅供查询，直接请求也拒绝修改。
- 当前资源没有可核实的原始发行版本及官服历史开放日期，因此界面展示本服配置时间；没有补造版本和历史日期，也没有默认全开活动。
- 排期管理接入现有活动入口与领取校验，不代表目录内全部活动剧情、关卡、结算或游戏 UI 已实现。单元回归使用隔离签到活动证明关闭、重开和领奖防重；原生探针核对真实资源的排期及解锁门槛。

## 保存与接口

排期写入当前 `dataDir/Gameplay46.json` 的 `activities`；不使用旧的 `ActivityScheduling.json`。未知根字段、非目标行及目标行扩展字段保留。停用行保存 `"disabled": true`，服务启动不会加载其窗口。

全文件验证通过后先在 `dataDir/gm-activity-backups/Gameplay46-<requestId>.json` 保存原文，再原子替换配置，一次发布完整运行快照。损坏、重复模块、备份或保存失败时保留原运行配置。目录与操作仍使用现有本机会话、CSRF、同源校验、确认预览及持久请求去重；旧开放请求在关闭后重放不会重新开放。手动修改文件需重启服务，或在核对后通过一次有效排期操作发布；GM 列表读的是文件配置。

`GET /gm/api/activities?q=&type=&state=&offset=0&limit=30` 返回总数及分页活动、模块、状态、时间、可操作性和原因。最大每页 100；`type` 为 `event/resident/trial/unmapped`，`state` 为 `unconfigured/active/scheduled/stopped/expired/mixed`。`q` 支持中文名、活动/面板/模块 ID。

`POST /gm/api/operate` 使用以下操作，`uid` 为 0 或省略，每次新意图使用独立 UUID `requestId`：

```json
{"requestId":"<UUID>","action":"activity-open","activityId":30013,"durationDays":7}
{"requestId":"<UUID>","action":"activity-open","activityId":30013,"beginTime":1900000000,"endTime":1900604800}
{"requestId":"<UUID>","action":"activity-stop","activityId":30013}
{"requestId":"<UUID>","action":"activity-enable","activityId":30013}
```

立即开放与自定义时间不能混用。操作记录以全服显示活动 ID、开放天数或明确时间；玩家数据不在排期事务中修改。旧协议查询已去掉固定历史清单和共享缓存，改为当前玩家可访问窗口；4.6 继续使用相同运行窗口。
