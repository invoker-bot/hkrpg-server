# 4.6 特殊战技点登记撤回与变化通知

本批补入 Java 21 `RogueSpecialBpWithdrawal46`，用于普通 UnStack 的特殊战技点模块撤销。登记元素直接复用已匹配 HPHEBLCCOOK 的 BpDirty 值投影，按共享修饰器引用身份比较。原生来源固定在本机国服 4.6 客户端，不启动客户端或参考二进制，不改运营数据、资源、协议和版本。

有效登记总量使用 Int32 加法（保留溢出），对有效槽求和后与最大值取 signed min。最大值先读 Nullable<Int32> 的存在性和值，否则读字段 100 的兜底；目录为空或计数零直接返回零，不套用负上限。负计数跳过数组但仍执行 signed min。Java 容器使用 255 的明确有限边界，未知或无穷列表不伪装成完整 CLR 容器。

撤回先保存有效总量，再捕获当前登记列表，仅按 modifier 引用身份移除首项：size 先递减，必要时移动后缀，重读当前数组和 size 清空尾值，随后 version 增一。null 数组槽代表值结构全零，null 修饰器可匹配它；重复身份只移除第一项。未找到或计数非正时不通知；移除后只有有效总量改变才执行变化尾部。通知失败保留已移除的登记，不回滚列表或 version，重试不会补发之前失败的通知，这一点按原件保留，不能宣称事件可靠投递。

特殊点计数读取环形点列表当前头，逐节点累加 flag & 1；next 为空直接结束，否则必须读取当前节点 owner，并在 next 等于该 owner 当前头时结束。计数不依赖列表 size。原始链表和点元素泛型身份已核对，但没有把泛型模板字段偏移当成闭包实例布局，有限 Java Point/Points 保持明确投影。

变化后值大于之前值时，计算列表 size 减特殊点数，再按原件的 signed Int32 差值与最大值计算需移除的普通点数；先捕获移除次数，再逐次以 false 调用普通点数移除。回调修改最大值或点数后不重算当前循环。无论是否增加，正常尾部先刷新模块，再以已捕获 after 整数发送原始事件 869、immediate=true。整数装箱的元数据用法独立解码到 kind=8，未当作 CLASS 类型或假定 native payload 是类型定义；Java 通知绑定接收整数，不声称原生装箱对象身份。
