# 选角后的剧情切图

## 故障与修复范围

用户在选角成功、后续演出结束后报告切换地图黑屏。10001 的保存记录显示角色路径已选为 8002，100010136 与移除试用角色目标 100010120 均已完成，100010121 正在进行，位置仍为 P20001/F20001001。

原始 `Mission_100010121.json` 只有一项 `EnterMap(2000201)`，目标要求进入 P20002/F20002001。入口 2000201 又列有完成 100010121 与主任务 1000101 的条件；原 `SceneMap46` 将它们无条件作为切图前置，导致当前任务需要先完成自己才允许进入目的地。隔离新号沿原始剧情链执行到选角演出结束，旧产物同样返回 `EnterSceneScRsp=2404`，没有进入目的地。

`MissionSceneEntrances` 为当前已接取、前置已完成、来源场景匹配的单步字面量 `EnterMap` 提供进入许可。核验完整原始脚本、所属主任务与目标、实际目的地图层，且只允许脚本指定的入口和默认出生锚点。入口中无关的完成条件继续执行；复杂脚本和自定义锚点不借用这条路径。真实场景切换成功后仍由原有到达事件完成目标，后续对白由原任务接续，不直接完成主任务或伪造对白。

## 验证边界

新增回归使用冻结的原始入口、任务与锚点，实际执行 `Player.enterScene`；前序对白完成记录和场景实体裁剪是明确的测试夹具。测试覆盖切图前后目标变化、未接取/取消/损坏记录、未完成前置、来源位置不符、脚本缺失/多任务/错误目的地、其他入口/传送点、无关前置和目标锚点缺失。旧代码先出现一项行为失败，其余拒绝路径保持通过；修复后针对性测试通过。

`scripts/smoke-opening-stage-win.py --ambush --readings --opening-transfer` 将现有开场原生 KCP 验证继续到结束选角演出、移除卡芙卡、切图、接取醒来对白，以及同 UID 重连和正常停服后的 H2 恢复。它使用隔离账号、端口和数据库，发送对白完成回执，不播放客户端演出；不操作 10001。

独立构建通过 586 类、15,001 项 Java 测试，失败、错误、跳过均为 0；新增 14 项回归。产物 SHA256 为 `81c633e5fb268935df7de10a1f405acc0e622f393d70c889f106e506d15bf554`。同产物原生验证通过 428 次请求、8 个会话、5 次正常停服及 4 次同 UID H2 恢复；首次切图、重连与重启均检查目标地图、到达目标完成、后续对白待播放，以及基础角色 8001 与选定命途 8002 分别保存。Dispatch 与账号重启保存冒烟也通过。

独立副本初次归档改变了旧夹具的换行字节，已核对 283 份夹具只存在换行差异并恢复工作区原字节后重跑全量；该次中断结果不计入通过。探针先后把队伍和场景中的基础编号误认为命途编号，这两次失败已保留，最终按正式协议分别检查基础编号与命途，服务器未为迎合测试修改角色编号。证据在 `build/opening-transfer-20261023/`：`red-behavior.xml`、`native-red-response.log`、`fixture-byte-restore.json`、`full-build.log`、`native-opening-final.json`、`smoke-server.log`。

服务部署结果将在完成后追加。真实客户端画面和完整演出须由实机复测确认；本修复不将服务端回归等同于客户端验收，也不宣称整段新手剧情已经全部完成。
