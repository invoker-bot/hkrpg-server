# 条件召唤与入战标记

召唤任务现在先核对明确任务类型、服务器用召唤定义、施放者位置目标和固定时长，再登记既有禁止入战策略。缺失或动态时长、未知目标、缺失资源行/定义、客户端召唤和未知近似任务名称不再改写技能默认入战标记。

有效创建任务在已支持的条件分支中，仅在该分支实际执行时记录当前施放者的暂态标记，不改变共享技能缓存。其他施放者和同角色下一次未选中的施放恢复默认；后者不凭空删除之前仍有效的召唤物。失败列表中的创建也遵循实际所选分支。原有无条件有效创建任务继续保留既有默认策略。

新增13项检查，修正“缺失定义”夹具初始化后重新恢复旧实现，其中12项真实断言先失败；最终检查同时保留原有召唤叶任务、时长、创建/销毁顺序及条件标记验证。夹具采用原始Aglaea创建叶、原始召唤表行和定义，在构造的施放者效果判断中显式执行，核对实际场景召唤指针及拥有者。原始技能的外层条件和完整技能链未接通，本项也未证明官方4.6召唤禁止入战规则，只使已有服务器策略遵循实际有效分支。

第一轮缺失定义夹具尝试对已设置定义调用 `setInfo(null)`，该受保护的设置方法不会清空既有定义；此夹具已改成新的、没有初始化定义的原始资源行。累计行为失败只使用修正夹具后的重新复现记录，不使用首轮该项误判。

未验证真实游戏界面、完整目标求值、原始全部角色技能或召唤生命周期的全部行为。条件元数据与召唤物生命周期保持独立，完整修饰器创建/销毁/监听仍待完成。
