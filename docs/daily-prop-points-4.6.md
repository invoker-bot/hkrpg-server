# 4.6 日常破坏目标与活跃度奖励

原始日常目标2100125和2100144均使用`PropDestruct`、`Equal`、进度3，整数参数为默认零、文本为空且筛选列表为空。日常池现在选择这类明确形状，实际破坏事件在当前场景成功移除可破坏实体后推进目标。规则执行时重新校验；含未知参数的修改规则保持未支持，不借用同类目标。

场景已有实体身份和当前场景检查，重复或并发破坏只接受一次，旧场景、非破坏型复苏装置不能增加进度。中国时间每日4点后的第一次事件使用新一天状态。这里沿用项目“一种池类型选一个已解锁支持目标”的轮转策略，没有证明官方抽取算法。

原始`RewardData`的103001至103005分别给道具23以50、100、150、200、500数量。`ItemConfig`中23为Virtual，其图标是`SpriteOutput/DailyMission/ActiveIcon.png`；源表没有道具35。此前把35当活跃度，原始23便落入不支持的普通虚拟物品发放路径，导致领取失败并停在领取中。现由日常状态单独增加23的活跃度，沿用领取锁、领取阶段及每日500上限。原始活跃度不增加普通背包物品；未知35不会被当成活跃度。旧`GameplayProgressTest`奖励夹具据此从35改成23，原有断言保留。

`daily-prop-points-4.6.json`固定提交`724b139d8c9c32d12552eb95745a4fee72bfe48b`，保存16份原始记录，涉及六个文件：日常池、QuestData、FinishWay、RewardData、ItemConfig、MazeProp。每条记录包含原始路径、文件SHA和Git blob SHA。复用恢复物件夹具中的原始RogueRoom306、入口8000103及组22；另外装载原始1002复苏装置定义，确保反例实际存在，未伪造为破坏物件。

新增21项检查：

- `DailyPointRewardTest`八项，覆盖原始自动目标2100132的真实103002奖励、其余四份原始奖励的明确RewardID变体、重复/并发领取、未知35及4.6查询响应字段。八项修复前均为真实断言失败。
- `DailyPropDestruct46Test`十三项，通过实际Scene破坏三个源物件、原始200活跃度领取、并发/重复/旧场景/复苏装置、4点换日及六类未知规则变体。修复前十三项先在原始破坏目标未被选择的断言失败，不能称为十三种独立运行时缺陷。随后发现反例夹具未装载复苏装置定义，已补原始定义；该夹具错误不计入真实先失败数量。

这些新测试使用真实场景销毁与Inventory实现，玩家保存为测试替身；响应验证止于现有4.6字段转换和解析，没有新增UDP/KCP、H2重启或真实游戏UI的日常正向验收。物件恢复收据、任务进度、日常进度仍按既有分步保存；玩家锁保证并发事件顺序，不表示断电后的跨系统事务原子性。

原始日常池53条目标尚有多类完成条件未支持，本批补两个破坏目标和实际奖励结算，不表示完整日常、剧情脚本、宇宙或活动小游戏已经完成。4.2冻结基线、4.6协议命令/字段和版本常量未因本批更改。


后续新增 `scripts/smoke-daily-prop.py` 与 `LoopbackDailyPropProbe`：八项实际UDP/KCP检查通过，同UID首次连接、重连、正常H2进程重启三份快照保持300活跃度、2100132/2100144已领取状态和破坏进度3。查询实际原始日常池，原始自动目标奖励100，再用一次普通攻击破坏组22三物件完成原始2100144并领取200；重复两种奖励、陈旧三个物件请求均拒绝。奖励响应无普通背包项目，重连/重启后已破坏物件不再生成。

核对11份原始资源SHA且源文件未变；隔离副本只把首房池限制306、碎片初始钱包50改300，日常池、QuestData、FinishWay、RewardData、ItemConfig、原始房间/组和物件定义没有更改。正常重启验证不表示断电原子性；合成客户端不等于真实游戏UI验收。前述21项单元/场景检查的测试替身边界仍有效，新增网络证据单独记载。
