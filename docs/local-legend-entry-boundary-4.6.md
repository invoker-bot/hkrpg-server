# 4.6 传奇挑战通用入场边界

传奇挑战关卡不能通过通用 `SceneEnterStageCsReq` 跳过活动规则。原始组 1 的 Easy、Hard、Fearless 分别使用事件 426004、426001、426005 和关卡 4260040、4260010、426005；固定原始表明确将三者标为 `LocalLegend`。修复前，低于活动面板 21 级门槛的测试玩家仍可沿通用入口创建这些战斗。

`SceneEventBattles.resolveClientEvent` 保留准确的事件、世界等级和波次检查，并拒绝 `LocalLegend`。4.6 通用处理器和 `BattleService.startEventBattle` 都使用这条检查。原始配置查找与服务端内部 `startBattle` 仍可供已校验上下文的脚本使用；后者不是已验收的客户端活动入口。没有改写原始事件、关卡、生成协议类、命令号或版本常量。

9 项新增 Java 回归使用 6 条完整原始事件/关卡记录，保留参考源提交和资源 SHA。三种难度的原生处理器与服务层各 3 项行为回归在修复前真实失败，共 6 项；另外 3 项确认原始查找及内部脚本入口保留。修复后 9 项及相关 77 项战斗回归通过。拒绝请求不创建战斗、不分配战斗身份、不保存玩家、不发奖励。

完整服务追加验证使用以下命令：

```powershell
python -s -X utf8 scripts/smoke-scene-event.py --reject-local-legend
```

它复用现有隔离配置与 H2 数据库、只读原始资源表和空剧情脚本目录。四次同 UID 合成原生 KCP 会话覆盖无战斗时三种难度的拒绝，以及两个原始日常战斗中拒绝活动入场后保留当前战斗；同时检查背包和 Quest 不变、普通怪物波次及结算。预期检查数为 46、22、22、22，共 112 项；三次正常关服、两次 H2 进程恢复。未传该选项时仍执行原有 82 项检查。是否实际通过以最终验证报告为准。

这项修复只关闭已证实的通用绕过。专用请求 6591/响应 6583 已有本机静态发送点证据，但尚未完成活动开放、剧情前置、正式/试用队伍、目标报告归属、难度解锁、历史进度和整组奖励接入。合成 KCP 报告不代表官方客户端输入重演、断电事务或游戏 UI 验收。四份完整原始表和进度位掩码的已核对范围见[原始资源说明](local-legend-native-resources-4.6.md)。
