# 4.6 挑战结算与任务接取绑定

忘却之庭的 `ChallengeFinishCnt`、无回溯 `ChallengeFinish` 和虚构叙事的 `ChallengeStorySettleCnt`，现在只推进入战时同一条主任务和子任务接取记录。任务 ID、定义和 DOING 状态相同的替换记录，也必须由新入战推进。战斗本身的合法通关与历史记录独立保留。

`MissionBattleAcceptance` 保存运行中的玩家、主/子任务对象、原有进度、周期键、已解析任务字段及完整原始任务脚本。结算重新核对接取资格和这些绑定。此快照只属于运行中的 Battle，不修改存档结构、冻结协议、客户端文件或经营者资源。相同字段与原始脚本的资源重载仍可通过；任务改挂另一父任务不能借用旧战斗。未解析的任务配置字段尚不在这层字段比较范围内。

新增 25 项行为回归：旧实现有 21 项真实断言失败，覆盖两个忘却之庭目标及虚构叙事胜利/回合上限结算时替换主记录、子记录、两者或 JSON 克隆，以及更换忘却之庭目标父任务；四个相同定义重载对照通过。修复后旧结果不消耗新记录，新战斗可以推进新记录。虚构叙事夹具明确准备第一半场分数和已接取教程，测试最终半场的绑定，不能称为新增完整双半场客户端验收。相关 168 项、八类回归已通过。

有明确 `IsBackTrack=true` 的历史查询规则继续采用既有行为。每日目标 2100119 继续按有效通关完成时的当前日周期计入；该规则与剧情接取快照分别处理，没有改变既有 04:00 周期口径。完整日常随机规则、跨日实际墙钟结算和真实游戏 UI 尚未验收。

日常网络探针原先将未主动请求的任务快照全部视为已领取。旧产物和修复接取绑定的产物都在同一位置失败；实际快照是剧情完成通知先发出、日常尚未更新的进度0/进行中。诊断中间版只放宽到已完成仍失败，不能算通过。正式修正允许领取前的进行中或已完成快照，已确认领取/恢复后只接受已领取；战斗响应后的主动查询仍严格要求进度1/已完成、实际领取200活跃度和重复拒绝。11项真实4.6响应帧回归在旧探针出现三项行为失败；修正探针与旧服务器的隔离对照通过29项原生检查。探针问题与21项任务接取行为失败分别记录。

最终全量构建、原生网络兼容、源码/协议核验及产物 SHA 记录在 `build/challenge-acceptance-verification.json`。网络探针用原始挑战 1/15 和虚构叙事 20011，接受条件、前置介绍、角色和入口有明确隔离夹具，战斗报告由探针构造；不将 Java 替换记录回归冒充网络负例。完整战斗运算、原始教程演出、末日幻影和所有玩法仍待完成，功能状态保持部分支持。

最终固定产物的全量 Java 回归为 12,577 项、465 类，失败/错误/跳过均为零；本批 36 项新增回归中，旧行为实际失败 24 项，相关九类 179 项通过。原生虚构叙事执行 53 个请求、两个实际半场胜利、三次正常关服和两次同 UID 的 H2 进程恢复；忘却之庭/日常完成 29 项检查、两次正常关服和一次同 UID 恢复。后者运行器初版误把项目正常退出码 1000 当作失败，修正后重新执行通过，该检查错误没有计入玩法回归。鉴权/调度重启检查、两项源码打包检查、3,325 份源码和 151 份冻结协议核验通过。Python 的 1,110 项累计验收中，373 份脚本沿用未变基线，唯一变化的日常运行器另经本次实际 KCP 验证，没有声称重跑全套 Python。

打包输入的 2,117 份哈希及原始资源哈希复核一致；最终普通包、固定网络复验包和认证包的 SHA256 均为 `43489a1a372e39d88879d29a96c223594fc24408f84b97059d8827f8043089e1`。资源、经营者数据和客户端均未修改；网络检查不等于真实游戏 UI、战斗输入回放或跨日墙钟验收。
