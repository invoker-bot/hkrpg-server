# 4.6 剧情机关状态与可回溯目标

本次补齐普通场景及当前任务副本中的免费机关状态保存，原始实例为 `40431 / 40431002 / G46 / 300002 / 104022`，交互配置 `1010`，对应子任务 `104040807`。并检查 `1040408` 从首次战斗、换层、机关到锚点移动、升降平台锁定、第二场战斗及最终对话的必经流程。完整 34 项目标、特殊解谜流程及真实客户端动画仍未完成验收。

## 原始依据

来源固定为 `TurnBasedGameData@724b139d8c9c32d12552eb95745a4fee72bfe48b`。`raid-prop-interaction-4.6.json` 保存七份完整原件的 Git blob SHA256 与本地检出 SHA256，以及完整楼层、四个关卡组和相关表记录。原始 `104040807` 为 `PropState / Equal / IsBackTrack=true`，在 `104040806` 后接取，要求该机关状态为 `Open=1`；交互 `1010` 的源状态缺省为 `Closed`，目标为 `Open`，费用列表为空。

## 保存与恢复

`ScenePropState` 分别存在于玩家普通场景状态和每次任务副本中。快照包括平面、楼层、维度、剧情线、组、实例、物件编号、状态及规范化物件定义指纹；副本快照额外绑定主任务接取标识。场景重建及序列化重载据此恢复，替换接取或改变原始物件定义后不能沿用旧状态。旧世界状态只在默认维度、默认剧情线且无新格式记录时回读。

机关操作先以静默方式准备实体与保存记录，在同一次玩家保存成功后通知物件变化并推进任务。保存失败时恢复实体、保存记录和接取标识，不发布成功变化。`PropState` 的可回溯目标只依据合法保存记录进行恢复；普通初始状态和旧世界格式记录不能直接生成新的回溯证明。完成原始主任务和副本结算后，尚未离场的场景仍可恢复同一接取的记录，但不能执行新的机关操作。通关后重连曾复现机关回到初始状态，已补入独立失败回归及原生网络场景。

4.6 沿用已冻结的 `InteractPropCsReq` 和 `SceneGroupRefreshScNotify`。原生网络验收发现旧 `GroupStateChangeScNotify` 没有 4.6 命令映射，已停止在 4.6 中发送该额外通知；4.2 真实会话保留原行为。没有新增命令号、推测字段或修改生成协议类。

## 验证边界

十二项新增 Java 回归覆盖原始机关、保存失败、先操作后接取、序列化重载、新接取、4.6 实际通知编码、来源变化、未知保存版本、必经流程的两个锚点与九项保存动作、通关后场景重建、通关后序列化登录及拒绝新操作。初始五项测试记录四项行为失败，独立通知编码回归另记录一项真实失败，通关恢复的十二项检查记录两项真实失败；编译夹具错误另行保存，不计行为失败基线。原始资源的四项 Python 来源核验已运行通过。

原生网络验收以独立账号、数据库及精简楼层进行，保留完整原始关卡组与物件定义，只设置父任务接取和回程位置。目标接取、两场战斗胜利、跨层、机关操作、后续对话和完成记录必须由实际网络请求产生；不会预写目标接取或机关状态证明。拓展流程明确核对十六项必经目标、原始楼层保存值和 `G41.Lock=1`，再检查通关后重连、正式离场及普通场景的再次恢复。网络探针中的战斗 WIN 和交互请求是服务端链路验证，未代表真实玩家输入、客户端画面、完整剧情脚本或动画验证。
