# 客户端已读偏好的保存与重复提示排查

## 已确认的问题

2026-10-25 用户实机反馈：上一轮任务历史通知修复后，仍有已开启功能重复提示。因此 [任务历史修复](function-unlock-history-4.6.md) 不能登记为该弹窗已通过验收。

本机日志另外记录了多次未处理的 6160 请求。固定 4.6 协议中它是 `UpdateServerPrefsCsReq`，但旧适配没有对应入口，继承的旧版处理器也仅返回编号。6134 查询此前属于登录占位响应，总是返回空偏好。客户端已经报告的已读状态无法保存、重登后无法恢复，这是一处独立可复现的缺口。

本轮接通 6160→6116 更新、6134→6125 全量读取、6105→6175 单项读取，按玩家原样保存不透明字节。重复提交相同值不重复保存；明确提交空值可覆盖旧值；不存在的编号查询不写入数据。单值上限 64 KiB、最多 512 个编号、合计 1 MiB，防止无界增长。非法或截断参数返回错误；异常存档拒绝操作；保存失败还原内存且不返回成功。

该数据与任务、角色、奖励、教程进度分开。服务器不自行标记“所有提示已读”，不提前开启功能，也不屏蔽真正新功能的通知。旧账号没有该字段时按空记录加载，不伪造过去的确认。
