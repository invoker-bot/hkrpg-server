# 2026-11-03 基础链路遗漏检查

本轮沿最近的剧情机关、切图、宠物、角色成长、光锥及跃迁修复检查共用路径，确认并修复下列五类问题。这里只记录已由失败回归证明的问题；源码检查、资源目录、隔离服务及真实客户端验收分别描述，不声明全系统无缺陷。

最终独立源码检查通过 **688 组、18,903 项测试，失败、错误、跳过均为 0**，并完成同一打包程序的隔离登录、抽取和重启恢复验证。新增 19 项回归，功能完成等级仍维持原有边界。

## 确认的问题和处理

| 问题 | 触发与原行为 | 修复后的行为 |
|---|---|---|
| 十连容量检查只检查“是否已满” | 光锥背包还剩 1–9 格时仍扣票并推进保底；抽取结果可列出十件，而实际库存拒绝放不下的光锥 | 在扣票及修改任何抽取计数前，为每次抽取预留一个光锥位置，容量不足整批拒绝；新手十连按十个位置检查，仍只扣八张票。检查至发放持有同一玩家锁；取卡池配置时不同时持有玩家锁 |
| 删除保存失败后物品已从内存消失或数量变少 | `deleteItem` 先减数量并移除索引，再保存；保存抛错后旧物品仍在数据库，但当前会话已看不到它 | 保存返回成功后才移除索引；保存失败恢复原数量，保留唯一编号索引和背包页索引，不发布虚假的删除 |
| 发放保存失败后出现未保存物品或虚增数量 | 新物品先加入背包再保存；堆叠材料先加数量再保存。写入失败后，重试可能在错误的内存库存上继续累加 | 新物品保存成功后才加入索引；已有材料增加保存失败时恢复原数量，重试只增加一次 |
| 批量中途失败漏掉已成功部分的同步 | 按参数扣除或批量发放中，前一项已保存、后一项抛错，方法直接退出，前一项的库存通知和任务观察没有执行 | 在结束清理阶段同步已确认成功的部分，只观察真实成功的取得/消耗；失败项保持原库存。整批操作仍抛出异常，既有待对账计划继续保留 |
| 旧装备关联缺失角色时中断加载 | 旧存档只有 `equipAvatarExcelId`，关联角色不存在时调用 `setEquipAvatar(null)`，空引用中断库存加载 | 清除不存在的旧关联，保留光锥并继续加载；重复清除为无变化操作。相同持久化角色编号按值比较，并重建实际运行对象引用 |

库存修改复用现有 `Inventory` 和 `GameItem`，没有引入新的存档格式。旧协议核心仍为 LunarCore lite 4.2.0，4.6 继续使用现有适配器，未手改生成协议类。功能目录的完成等级不因本轮缺陷修复提升。

## 失败回归及验证范围

新增 `InventoryPersistenceTest`、`LegacyEquipmentLoadTest` 和 `GachaCapacityTest` 共 17 项测试，并为心绪表盘补上两项“扣除已确认、后续回调中断”的回归，合计新增 19 项；同时在已有 `ItemSaleTest` 中补上失败物品必须保留的断言。

- 第一批在修复前运行 13 项，11 项失败；包含四类卡池的十连容量不足、删除失败回退、部分扣除通知、旧关联加载和已有分解失败路径。
- 顺查发放路径后再次补充回归，8 项库存检查中 4 项新增发放用例失败，前面已修复的四项扣除检查通过。
- 测试使用实际库存索引和通知构造，保存失败由测试物品主动拒绝写入。卡池测试使用原有固定星级资源夹具，降低测试背包容量，执行真实扣票、抽取、物品入包及保底变化；没有操作正式玩家。
- 测试替身位于 `org.hkrpg.server.gameplay` 并使用静态类，避免进入运行时 `emu.lunarcore` 数据库实体扫描或干扰测试存储映射。首次完整检查因测试隔离不当而中止，该轮日志单独保留，不计为全量通过。
- 校正心绪表盘、骰子升级及供奉原有的写入中断回归：保存拒绝时库存保持原值，预留仍阻止自动重试；心绪表盘另在库存方法已确认扣除后注入回调异常，保留原先的实际扣除和防重复扣费验证。写入失败与已确认扣除后的中断不再使用同一种故障注入。

本地证据目录为 `build/bug-audit-20261103/`。`red.log`、`red-results/`、`grant-red.log`、`grant-red-results/` 保留两批失败；各轮通过结果、全量构建和隔离服务结果在同目录分别保存。

共享工作区另一次完整运行期间，其他并行检查重新生成了测试资源目录，并编译了新的持久化测试替身，导致大量缺失资源与实体映射错误；这轮结果不计为本次修复的全量结论。最终验证使用 `6e9a09f` 的已提交源码，加上本轮 12 个代码、测试和文档文件，冻结为 `validation-source/` 独立副本；其他未提交改动不进入该副本。382 份测试资源与构建后的复制文件逐项摘要一致。隔离服务也从该副本生成的程序重新执行。

独立副本首次使用八个测试进程时遇到本机原生内存分配失败，JVM 崩溃记录保留于 `validation-source/hs_err_pid104288.log`，该轮不计为通过。随后仅在验证进程中设置 `JAVA_TOOL_OPTIONS=-XX:ActiveProcessorCount=4 -XX:CICompilerCount=2`，改用 `scripts/build.ps1 -TestForks 2 -RerunTests`；没有修改正式服务或全局 Java 设置。
