# 4.6 修改器数值绑定

`RogueModifierValueBinding46` 补入修改器当前整数到动态变量的显式绑定。它与叠加和寿命逻辑共享状态：层数、计数、最大层数与剩余寿命分别通知槽位0～3。提供对已声明的 `RogueResonanceVariables46` 普通数值容器的明确适配，仍未建立实际战斗世界、原生数值数组或容器。

## 读取与写入

先检查绑定数组是否存在、对应掩码位是否开启，以及值类型是否在0～3之间。无数组、未开启或超出类型范围直接跳过；启用时目标槽位必须存在，动态变量容器和明确写入绑定必须提供。数组是 `StringHash` 值数组，有限投影保留原始有符号32位Hash键，不重新按名称散列。

类型0读取当前层数，1读取当前计数，3读取当前寿命；2先以Int32回绕计算 `BaseMaxLayer + ExtraMaxLayer`，再保证至少为1。没有额外钳制其它整数，也没有把计数、寿命或永久哨兵当成最大层数。

整数绝对值小于 `0x40000000` 时左移33位生成普通数值；边界及以上左移26位并置低位标记。绝对值计算使用更宽整数，保留Int32最小值。这里只补整数编码，没有开放扩展数值的动态求值、夹取或混合算术。

标准容器适配先核对容器类型，再查目标键。键不存在直接跳过，甚至不会校验未使用的编码值；这是原件查找失败早于读取/夹取/设置的顺序。已有键交给已验证的标准变量写入逻辑，保留界限夹取和通知；扩展数值写入已有标准单元仍拒绝。写入回调失败会中断当前通知，不回滚已经发生的外层修改器写入。

## 原件与验证

只读核对3个完整PE方法共1,959字节和3类字段：修改器数值通知、最大层数getter和动态容器setter。字段包括数组432、无符号掩码644、当前数值、最大层数两项来源，以及动态变量字段104的实际类型。`StringHash.Hash` 为Int32；不把装箱字段的布局偏移直接用于数组元素地址。

三项Java回归验证整数边界使用带标记编码、最大层数加法先回绕，以及缺失变量键在未使用数值校验之前跳过。修复后新增43项Java与10项Python，覆盖四槽位、掩码与类型门控、符号/边界、动态读取、写入异常和标准容器夹取；叠加替换及寿命推进的联合测试实际更新同一个 Java 变量容器。

叠加模式与数值绑定同批联合验证：全量 `scripts/build.ps1`、9,555 项 Java（390 个测试类）和 666 项 Python 均通过；2,885 个交付源码文件、151 份协议快照核对通过。结果为 `build/rogue-modifier-value-binding-verification.json`，封存 JAR 为 `build/rogue-modifier-value-binding-9555-certified.jar`，SHA `8f79e70c3d1a19f3921278a649ed264aa6420a646822d98cf170623d28c86b64`。
