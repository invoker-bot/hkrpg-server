# 4.6 活动面板的原始解锁条件

原始 10061 面板使用三个任选条件：完成主任务 4020103、完成主任务 4010106，或完成子任务 801710102。旧解析器只支持逗号分隔的条件，整条 `|` 表达式一直返回未解锁。原始 10025 面板要求 Quest 3000018 已关闭，旧解析器不识别 QuestClose。

现在先完整解析有限表达式，再读取实际玩家状态。`|` 为任选分支，`&` 和既有逗号为全部满足，全部满足优先于任选。空分支、未知条件、尾随分隔符、数值溢出、显式 null 及超过长度/条数限制均拒绝，不能因为另一分支为真而绕过未实现条件。读取在玩家锁内完成，不修改进度、保存次数或发奖。

FinishSubMission 使用既有身份、原始目标、准确进度、完成时间、父任务接取和取消状态校验。QuestClose 使用实际 CLOSED 状态及该 Quest 自身的当前目标、身份和完成时间；FINISHED 和领奖预留中的 CLAIMING 不等于关闭。

`src/test/resources/fixtures/activity-panel-unlock-4.6.json` 保存固定 TurnBasedGameData 提交 `724b139d8c9c32d12552eb95745a4fee72bfe48b` 的七份完整文件证明、10 条完整原始记录。两个面板、三个主任务、Quest/FinishWay，以及 8017101 主图、完整 partial 和 801710102 完整脚本保持来源与安装 SHA；没有把前置任务的完成当成已实现剧情。

本机只读分析将 ActivityPanelData._IsUnlocked/568687 定位到 ExprConditionChecker.DoSyncCheck/551098，并沿 _ParseExpr/551099 核对解析器、字符串槽中的 `|`/`&` 和两个原生节点的短路逻辑。CheckItemCloseQuest._DoCheckImpl/550888 比较实际状态 3。所有函数边界使用 PE 运行函数表；未知泛型内部名不重新命名为官方接口。静态证据只证明这些有限条件，不代表客户端 UI 已验收。

52 项新增 Java 检查包括原始三分支的八种组合、Quest 的四种实际阶段、父任务/子任务和关闭记录损坏、完整表达式预检、运算顺序及原生 4.6 日程报文；12 种实际 Player/Morphia 状态各恢复两次。修正等级夹具后用原有实现重跑的 40 项中 14 项真实先失败。首次夹具没有设置等级造成的结果单独排除，避免把夹具错误计入缺口。

`scripts/smoke-activity-panel-unlock.py` 使用隔离账号、原始表与唯一复制的 8017101 目录。运营窗口和三次离线前置状态修改是明确夹具，完成记录使用 CLOSED 避免登录时再结算奖励，仅写指定的主/子任务与 Quest 状态，不发奖励、不改世界等级、正式队伍、其他玩家字段、配置或源资源。候选已通过四个进程阶段、20 次 SDK 后的原生请求、七次离线检查（三写四读）、四次正常关服和三次同 UID H2 重启；每阶段重复查询内容相同。最终以同一产物 SHA 的运行报告为准，未结束的运行不计完成。离线检查器使用扩展 BSON JSON 克隆以保留 int64 类型，并显式加载唯一原始任务目录；此前的 BSON 类型、FINISHED 触发登录奖励和漏加载定义三次夹具失败均排除，不计为玩法缺陷。

本批完善活动入口条件，不证明 10061 的完整首领玩法、10025 的奖励取得、自然剧情前置、所有活动和小游戏、客户端 UI 或断电原子性。参考 Zig 项目的 onGetActivity 实际发送活动日程报文，不能据函数名新增一个没有 4.6 协议定义的命令。
