# 4.6 带种子的逻辑随机

`RogueLogicRandom46` 实现原件具体种子构造的基础 `System.Random` 序列及普通逻辑样本的定点投影，范围为未热替换的普通代码路径。Java以显式计数接口保留通知、局部赋值和全局写入的顺序。它没有安装到实际战斗世界，也没有实现原生计数事件池、无种子构造、Random子类或IFix运行时替代、所有随机操作；宇宙玩法继续为 `partial`。

## 序列与状态

原件种子构造分配56个Int32元素，使用161803398与种子绝对值初始化；最小Int32种子按最大Int32幅值处理。随后按 `(21 × index) % 55` 排列54项，再做四轮混合，索引从0与21开始。整数运算保留有符号32位回绕，不能换成Java的另一种随机序列或检查溢出的整数算法。

每次基础抽样同步推进两个索引，56回到1，减法结果为最大Int32时减一，负数加最大Int32，写回当前项。双精度结果乘原件存储的倒数，不能把每次乘法替换成除法。普通包装再乘8589934592、向零截断并清除最低位；在该基础序列的0含～1不含范围内，不进入扩展编码分支。

包装保存原始种子，调用计数从0开始。先消耗一个随机样本，再读旧计数并以Int32回绕计算下一值；通知仍看到旧局部计数，通知返回后才写局部计数、发布全局计数、返回样本。通知失败会消耗随机状态，但不会写局部或全局计数。全局发布接口是项目显式绑定，原件中的实际静态字段写入不会产生该接口的外部异常；没有据此声明原生全局存储或事件池完成。
