# 4.6 修改器寿命推进与锁定来源

`RogueModifierLifetime46` 补入显式状态和世界绑定下的普通阶段寿命、回合剩余数变化入口、锁定来源筛选和到期后的读取顺序。范围为未热替换的原件普通路径；没有建立真实修改器实例、事件分发或战斗世界，宇宙玩法继续为 `partial`。

## 寿命入口

普通入口先读定义的 `LifeStepMoment`。类型0 `Unknow` 与6 `RoundEnd` 跳过；1～5中，`LifeStepImmediately` 为真绕过同一 `RenewTurnCount` 的限制，否则当前回合与记录相同便跳过。回合剩余数变化入口仅在模式6调用同一寿命步进，不直接把剩余回合数赋给效果寿命，也不检查同回合标志。

步进先检查 `InitLifeTime == -1`，这是永久哨兵；`CurrentLife == -1` 本身不是永久标志。随后取非空状态覆盖键，否则取原始名称。缺失状态行直接进入递减；有状态行则查询显式上下文实体，实体缺失传类型0，存在读取 `_EntityType`，不是队伍类型。真实虚表与在线上下文读取尚待绑定。

只有锁定查询为真且实例 `_LockStepStatusType` 为0时保留寿命。有限锁定助手仅对Buff类型1和Debuff类型2读取对应计数：正计数立即为真；0或负计数继续查对应来源的嵌套实体类型列表，任意精确匹配即为真。缺失/空外层列表为假，命中的内层缺失或空元素继续拒绝。项目最多访问255个外层条目、255个内层数值，已匹配后不再检查未访问尾部；并未安装真实容器、接口虚调用或组件计数。

需要递减时先以Int32回绕写 `CurrentLife - 1`，再通知值类型3；随后按当时的HUD存在状态通知界面，再检查当时的寿命。即使锁定保留也会检查HUD和寿命是否已经到期。值通知或HUD回调可以改变随后读取的状态；异常会保留已经发生的写入，并中断后续动作。

寿命小于等于0时调用显式 `Destroy(LifeEnd=2)`。销毁返回后才沿任务的GameWorld读取战斗实例、游戏模式与 `_LimboEntities`：缺失世界跳过后处理，有世界则战斗实例和模式必须存在；容器缺失或计数0跳过，正计数执行明确的Limbo死亡绑定。该字段是泛型容器，未把计数偏移直接解释成数组长度。Java保存这些读取顺序，没有实现完整原生Destroy和Limbo处理。

## 原件与回归

核对8个完整PE方法共4,502字节、11类声明/继承字段，包括两个寿命入口、实际步进、状态查询、两层锁定筛选、Destroy与Limbo处理。实例 `_CurrentLife` 偏移680、`InitLifeTime` 732、立即标志741；状态标签与组件Buff计数虽然均出现偏移648，所属类型不同，按各自类型核对。

三项Java回归先因检查错误的永久字段、忽略立即推进和把值通知放到HUD之后而断言失败。修复后新增43项Java与10项Python，覆盖阶段模式、回合入口、状态键、锁定类型、寿命回绕、异常中断、回调后状态读取和到期世界链。显式接口联合测试不代表真实世界安装。

全量 `scripts/build.ps1`、9,469 项 Java（388 个测试类）和 646 项 Python 均通过；2,873 个交付源码文件、151 份协议快照核对通过。结果为 `build/rogue-modifier-lifetime-verification.json`，封存 JAR 为 `build/rogue-modifier-lifetime-9469-certified.jar`，SHA `6af7f44d381be7d42ebce00c30c20b094ebe78ac45489f85ebe8bea960019566`。
