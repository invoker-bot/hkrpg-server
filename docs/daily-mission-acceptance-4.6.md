# 4.6 日常委托接取与数量限制

原始DailyMissionData包含88条委托、17个分组，均为类型1并关联活跃目标2100003；DailyMissionCount规定类型1每日1份。DailyMissionCatalog加载这两张独立表，检查重复编号、分组、解锁主任务与数量引用，失败时不替换上一份有效目录。旧资源两表均缺失时不启用新限制；单表缺失或空目录明确报错。

MissionManager的手动接取与已有自动接取路径现在共同检查委托目录、MainMission明确Daily类型、对应完整任务图、有效结束子任务、活跃目标与其原始FinishTodayDailyMissionCnt规则，以及UnlockMainMission的有效、未取消且非未来完成证明。客户端的Manual请求不能代替原始2000116或2000120等解锁前置。

DailyMissionSelections在同一Player文档保存国服04:00周期、实际委托编号、类型和分组。接取与创建主任务共用玩家锁及一次保存，当天配额跨分组共享；再次接取同一个进行中任务不重复占额，任务完成及领取5000信用点也不释放当天配额。查询、并发请求和重登不重新抽选，历史选择保留；损坏、重复、错编号/类型/分组、错误周期键和水位拒绝新增委托。服务器时钟倒退不能开启旧周期。

当前入口使用冻结4.6的AcceptMainMissionCsReq和GetMissionDataCsReq。新增原生处理器检查验证成功/拒绝返回值、实际委托编号、进行中阶段与第一个原始子任务，没有增加未识别的命令号，也没有手改生成协议。仍需接取请求；自动每日随机分配及跨日任务重置尚未实现。04:00后可以在新配额接取其他尚未完成委托，昨日主/子任务历史保持原样，同一已完成委托仍不能重复接取，不能把每日配额视作完整可重复日常系统。
