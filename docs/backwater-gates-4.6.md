# 边缘通路控制装置按 F 无回应

## 原因与修复

用户在「躲得过初一，躲不过十五」寻找裂界出口时，靠近控制装置有 F 提示但操作无效。正式数据库只读核对玩家位于 `P20111/F20111001`、入口 `201110102`，位置接近 G21/300003；`101030104` 正在进行，普通控制台没有完成收据。未操作客户端或修改正式玩家任务。

该组普通控制台使用物件 `101001` 和原始 `BaseConsole_01A_Control_SimpleDoor` 图，门为 `101004/IronGate_06`。原加载器没有识别这种控制台，清除了控制台与门的共享绑定；普通交互也只改变控制台自身状态，没有保存并同步对应铁门。`IronGate_06` 不在旧的 `_Door_` 名称推断范围内，因此不能直接复用旧门分类。

修复在 `StoryDoors` 中识别准确的控制图和物件型号，保留两端原始绑定。操作 `1010` 前验证当前场景中的唯一原始目标、门的型号与图、反向控制台绑定及允许状态，再通过现有状态事务同时保存控制台和门。保存成功后同步两个实体，保存失败恢复两者和持久化记录，不发布成功通知。不依靠物件名称包含 Door 推断此类铁门。

G21/300008 只控制 300001，G21/300003 只控制 300002；后面的 300004 仍按原始 Locked 保持锁定，不在本次操作中解锁或代替剧情。旧版只保存控制台、未保存门的记录不会在登录时自动开门，重新操作可写入正确的成对收据。重复操作不重复保存，重新登录和重启按同源成对记录恢复。
