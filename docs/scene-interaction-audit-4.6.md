## 候选复核结果

最初的 256 条缺表引用、9,404 个客户端物件组只是关系扫描的候选范围。复查原始构造器发现，组级 `LoadOnInitial` 省略时为 false，物件/NPC 自身的省略值才为 true；`TaskEnabled=false` 的节点及其子节点也不应算执行路径。只读扫描器已修正并保留关闭节点供复查。重扫为 9,215 条未关闭的静态引用、11 条关闭引用、253 条缺表引用和 211 个类型/编号组合；默认维度的直接初始坏引用为零，不表示条件路径或所有交互都通过。

253 条逐一关联后，68 条有组/物件放置，7 条有任务脚本直接引用，178 条没有静态入口。放置中包含已删除物件、此前修复的矿车旧点及未被当前步骤绑定的旧任务组；任务直接引用中只有 `404011802` 可自动接取，其余依赖未启用步骤。对全部关卡脚本的字面量文件调用做反向闭包，没有新增间接任务/演出表入口。原始记录、位置、门槛及反查证据分别保留在 `audit-final.json`、`reference-roots.json`、`static-root-closure.json`；动态 DS 参数 158 条和省略类型的 56 条不据静态编号定性，也不据此宣称所有脚本可达性已被穷尽。

迴星港 G81 的 `4021201` 缺表，但楼层引用已删除；17 处遗器入口使用其他编号空间，均保留原路径。客户端归属目录只纳入普通提示物、纯人物和无服务端实体交互的图，复杂机关、战斗、书籍、服务端交互及不能完整解码的来源不统一过滤。未纳入目录不等于已确认故障。

## 本次追加修复

### 本地显示归属

`scripts/generate-client-visual-groups.py` 从只读候选和固定客户端导出记录生成 `src/main/resources/scene/client-visual-groups-4.6.json`。8,656 份来源均完整解码、消费至记录末尾，并核对归属、默认值、任务条件、放置编号及初始化图。生成器保留 JSON 数值原始拼写，与 Java 的完整来源指纹一致；最终安装包实际读取器再次逐项验证 8,656 份来源命中。修改资源、显式服务端归属、复杂机关及有服务端交互的组继续沿原发布路径。

`ClientVisualGroups` 保留服务端逻辑实体，过滤完整场景和增量添加/删除的重复显示记录。普通地图、剧情线与剧情副本使用同一原生上下文门槛；挑战、模拟宇宙及试用模式继续沿原机制。服务端不会因过滤显示记录而提前发奖或完成任务。

### 当前任务步骤与状态合并

`NativeMissionGroups` 将原始未初始加载、具有归属的任务组按 `GroupIDList` 绑定到实际正在进行的步骤，同时核对楼层、位面和剧情线。原有加载/卸载、取消、暂停、过期及特定玩法门槛保留，显式初始组不改成步骤组。直接 `loadGroup` 也经过此门槛。复查额外发现的六个剧情副本旧组同样处理；正常副本步骤的组仍能加载，取消后退出。

这修正了仅接到父任务就加载所有旧组、提前显示演出提示以及异地复制组借用其他楼层步骤的问题。场景中已有部分 `scene_mission_info` 时，现在追加并替换本投影负责的状态，保留无关状态和未知字段。新显示组只引用真实已保存父任务与子步骤，不虚构接取；原普通 NPC 的未完成名单仍保留“尚未完成”的协议含义。

### 缺失且不被正常流程依赖的分支

原生 `404011802` 自动分支请求 E404011800，当前表中不存在。原始主任务起点为 801，终点 803 由 804/805 达成，不依赖 802。固定客户端中主定义 19 字节、五项子定义 508 字节及脚本均完整只读核对。`UnavailableMissionScripts` 按合并任务定义和脚本的完整指纹，只在该演出缺失、原始定义未改且为实验协议时停止新接取；已有 DOING 记录在查询/同步中投影为 NONE，存档和正常步骤保持原状态。恢复演出、修改定义或旧协议均走原路径，未使用虚构演出或自动完成。

新增跳过诊断为 `inactive-mission-group` 和 `missing-optional-performance`，只记录必要编号、场景及固定原因，复用每分钟首条、重复计数和超额汇总。
