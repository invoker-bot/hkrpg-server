# 邮件附件与领取状态

新邮件分别记录已读和附件领取状态。打开后仍可领取；成功后查询隐藏已领附件，原始附件副本继续留在邮件文档中。删除已读邮件时，未领取或处理中断的附件受到保护。历史邮件只有`isRead`，无法区分“打开过”和“确实领取过”：已有已读记录保守关闭，不自动重发、不改写运营存档；旧未读记录在读取时建立明确状态。

## 发放与保存

领取在玩家锁内执行：先检查归属、到期、完整附件列表、当前资源、合并数量、实际库存容量、货币上限和物品编号余量；把预期数量与原余额预留到邮件并保存，再使用独立副本调用实际背包。比较返回结果和实际库存/钱包增量后，先保存玩家余额，再保存领取结果。仅完整到账的邮件进入成功列表；部分发放、异常中断和未知状态保留待核对记录，自动重试和删除不会重发或掩盖该记录。

普通材料、任务物品、背包可堆叠消耗品、独立光锥/遗器、信用点/星琼/古老梦华以及尚未拥有的角色卡接入这一检查。装备属性保留，邮件中的副本不取得背包归属或编号。已持有角色卡、自定义虚拟物品、宠物/展示解锁和其他尚未核对类型拒绝整封发放，后续继续补齐转换规则。8192字节、500个请求编号与500件附件是本服门槛，未声明为官方限制。每封邮件独立处理，批量结果保留实际成功项和首个错误；没有跨邮件事务或已核对的逐封失败列表语义。

管理员邮件命令也按配置数量展开独立光锥和遗器，避免数量2只生成1件。欢迎邮件既有数量规则保持。4.6读取确认回显实际邮件编号；领取和删除使用冻结定义中的字段，读取/领取/删除请求拒绝无符号截断别名、错误线格式、未知字段、过大批次与未支持的可选奖励选择。

## 已完成的验证

42项新增Java检查，修复前累计14项真实断言失败：最初领取行为7项、原生读取/选择2项、钱包保存1项、管理员数量3项、缺失状态1项。钱包测试最初缺少昵称、触发测试替身的出站编码异常；该结果不计回归证据。补齐夹具后，仅移除钱包保存步骤重新验证，正确复现“已领但没有钱包快照”，随后恢复生产保存步骤。

检查覆盖实际库存增量、独立装备属性/身份、并发一次、部分发放/异常中断、JSON保存和实际Morphia重载、历史记录策略、到期/删除、原生字段与认证状态。物品数据沿用固定资源提交`724b139d8c9c32d12552eb95745a4fee72bfe48b`及已有分解夹具的原始记录；昵称、存储替身和异常注入明确属于隔离测试。

本机客户端两份文件的SHA锁定后，只读核对8个邮件协议类型的实际字段常量、写出/读入/静态初始化共24个完整PE方法区间，见[原生证据](client46-mail-evidence.json)。四个混淆请求/确认类型与友好名称的关联沿用固定参考定义和相同字段结构，没有独立完成原生游戏发送者/消费者绑定。命令号来自固定Honey协议，不宣称本次独立解析了原生命令枚举。逐封失败结构的两个混淆字段尚未核对含义，未写入猜测值。
