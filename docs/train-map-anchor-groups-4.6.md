# 列车任务地图缺少可用锚点

## 基座舱段监控室定锚

监控室定锚对应 `P20001_F20001001` 的组 18、物件 `300002`、传送编号 `2000102`。原组要求楼层保存值 `SceneStateByMainMission = 1`，由原始主线配置写入。现场存档满足该条件，锚点状态已为 `CheckPointEnable`。此前远处地图把带保存值条件的组整个略过，地图包因此缺少这处定锚的启用状态。

远处地图现可对普通初始锚点组核对已声明的楼层整数保存值，支持简单的等值且条件。组满足条件后，回包按既有存档同时提供组、物件状态及已解锁编号。复杂条件继续交由实际进图逻辑，传送继续经过原有入口和锚点校验。

用户在「列车长的馈赠」地图点击「前往」时，先遇到「场景获取失败」；世界选择修复后又反馈「附近没有可用的锚点」，并提供只有任务标记、没有锚点的观景车厢地图。此前的世界选择和直接进图测试没有覆盖客户端寻找锚点的条件，不能作为这一步已修复的证据。

## 原因与原始资料

`SceneMap46` 原来仅为当前楼层填写 `maze_group_list`，且遍历的是保存属性/状态的 `Scene.groups`，并非实际加载的 `loadedGroups`。远处地图没有任何组；当前地图没有属性的锚点组也被遗漏。原实机回包虽然包含解锁编号 2215 和 G2/300001 的启用状态，但没有对应的 MazeGroup。

本机固定 SHA256 的 4.6 客户端只读分析显示：`MapData.SyncServerData`（方法 678558）调用远处地图策略的同步入口；该入口从 SceneMapInfo 的组列表建立可用组集合，`IsCanLoad` 按实体的组编号检查集合。仅有解锁编号不足以让远处锚点成为可用地图实体。分析不启动或修改客户端，也不代表实机验收。

原始 `P10000_F10000000` 的 G2 是初始启用的普通 Server 组，没有任务、气氛或保存值加载门槛，也没有组属性。其 300001 物件为 MazeProp 110，原状态 `CheckPointEnable`、MappingInfoID 2215、AnchorGroupID 2、AnchorID 2。注意 MazeProp 110 是普通地图物件，不应按名称将其误判为 `PROP_SPRING`。测试夹具保留原始 G2、物件表和列车平面行；来源路径及 SHA256 记录在夹具内。

## 修复范围

- 当前地图按实际已加载组返回，包括没有属性或状态记录的组；已有组属性继续使用当前值。
- 远处地图只补入能从原始资料证明可用的普通初始锚点组：Server、主维度、原始锚点/物件匹配，并且没有任务归属、加载/卸载、气氛或保存值门槛。已有特殊组排除规则保持保守。
- 地图的解锁编号和物件状态仅对应返回的可定位组；使用玩家保存的状态，不批量解锁锚点，不补亮探索区域。
- 查询读取配置及玩家状态，不构造临时 Scene，不重新分配角色实体编号，不保存、移动玩家或完成任务。

条件组的完整远程求值、其他剧情维度及完整地图探索仍未接通。本改动只补地图查询资料，跳转仍经原有入口门槛、锚点解锁和运行上下文校验。
