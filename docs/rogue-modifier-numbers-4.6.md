# 4.6 战斗效果整数参数计算

`RogueModifierNumbers46` 补入 Count、MaxLayer、LifeTime、LayerAddWhenStack 的有限标准数值计算。它返回明确的存在/缺失结果，并保留四项的读取顺序；实际参数安装、效果实例、叠层和寿命推进仍待接入。

本批核对固定客户端的八个完整 PE 方法，共 8,953 字节；另核对 SetupFields 的一个完整 1,513 字节布局提供函数。证据绑定原件哈希、原始入口、三种数值获取函数、覆盖三元组、普通舍入函数、构造器和字段布局，见 `src/test/resources/fixtures/rogue-modifier-numbers-4.6.json`。整数输出存在标志按原件独立保存，缺失不能改成零或效果定义的 99 层默认值。

普通原值使用原始舍入规则，精确半值取偶数。覆盖上下文缺失时，忽略覆盖三元组，回到普通原值；原值缺失则保留缺失。Count 只读取原任务的 Count，不从覆盖表取得值；随后依次计算 MaxLayer、LifeTime、LayerAddWhenStack。

覆盖上下文存在时，非空直接覆盖优先。它按标准原始值算术右移 33 位转换整数，而不是普通舍入；例如 1.5 得到 1，-2.5 得到 -3。直接覆盖可以为缺失的原值提供参数，并跳过原值、百分比和加项的求值。

直接覆盖缺失时，百分比和加项以 `(原值 × (1 + 百分比)) + 加项` 计算，最后进行普通舍入。两者均缺失则返回普通原值；原值缺失时，不求值百分比和加项，也不凭空创建参数。标准乘法沿用已核对的原生量化规则。One 的初始化字节、Zero 的声明布局差和 PE 文件尾零初始化范围均复核，不能把未映射区当成文件中可读取的八字节数据。

原值使用源上下文，覆盖值使用覆盖上下文。上下文在检查存在性和每次实际覆盖求值时重新读取，不能缓存第一份对象替代后续读取。原值、百分比、加项的求值及算术顺序遵循原件；异常立即传出，已发生的外部求值副作用保留，后面的参数不继续计算。本类只构造计算结果，不宣称重建原生参数对象的逐字段写入或回滚规则。

三元组为内嵌值类型。元数据的 16/24/32 是装箱布局字段位置；原生内嵌结构的 0/8/16 是同三项的载荷位置。覆盖表三项分别从 16、72、96 起始，覆盖上下文位于 128。源任务四项分别使用 Count 88、MaxLayer 96、LifeTime 80、LayerAddWhenStack 104，不互换字段。

六条已核对原始施加任务均省略这四项，共保留 24 处省略。原任务构造器也未创建这四种参数的动态单元。动态单元求值仍须明确绑定实际上下文，当前只开放标准编码和已有有限普通舍入/算术范围；扩展编码与未开放的边界结果继续拒绝。

三项断言失败回归分别覆盖直接覆盖误用普通舍入、百分比漏加 One、缺失原值被凭空替换为零；修复后通过。新增 32 项 Java 和 10 项 Python 回归还覆盖负数、空值、求值顺序、变化/消失上下文、异常、范围关闭、完整方法和来源字段复核。
