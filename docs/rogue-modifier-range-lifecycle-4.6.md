# 4.6 数值范围监听的退订与销毁退出

明确范围状态与既有替换、施加者变化共享同一个修改器身份。新增自身作用域2、所属实体作用域5的稳定监听，施加者继续使用作用域4；三个方法身份彼此独立，哈希保持完整32位。根容器写入和注入通过已经实现的范围事件执行。

销毁范围段按当前监听掩码处理所属实体32、施加者16、修改器自身4。所属能力组件、所属实体和数值组件明确绑定且要求存在，所属根数值容器缺失时失败；施加者缓存存在时不读上下文，缓存为空时重新读取上下文和施加者并写回缓存，结果为空跳过，数值组件存在而其容器为空也跳过。自身根容器要求存在。每个根容器移除末尾一个匹配监听，重复注册保留其他次数。前一个绑定改变掩码时，后续分支读取当前掩码；全部正常完成后才清零。失败不恢复此前已经退订的监听，不清零尚未成功完成的掩码。

退订完成后，捕获当前范围字典，并按值列表执行仍在范围内、具有退出序列的项。此处直接执行退出序列，不改范围状态、不增加或减少退出计数，也不使用普通范围变化的重入限制。每个列表当前长度和每项当前状态实时读取，回调追加或清空列表会影响后续。正常退出后清空状态的字典字段；回调替换该字段时仍遍历捕获字典，最终清空当前字段。失败保留当前字典及成功执行的前缀。

原件的字典值遍历每次先检查版本，结束时也检查。本工程提供明确的有限版本组，所有写入经过其接口；替换既有值同样变更版本，外部不能通过EntrySet绕过。回调期间字典变更会在当前组结束后的下一次遍历检查失败。这一版本模型、插入顺序和255项保护属于工程的明确绑定，没有冒称所有原生字典变种的变更、删除槽复用或工厂语义。退订退出仅接受该明确版本组，其他Map仍关闭。

来源核对四个完整PE方法共3,720字节、五类字段、三个绑定方法、一个递归字典字段、一项数值组件泛型参数和三个监听方法槽。所属/施加者共享GetComponent<FODPNNIJCJI>，继承的根容器字段为88。所属/施加者/自身方法槽分别为0x9648a80/0x9648a88/0x9648a90，独立匹配三个实际回调身份。字典值遍历帮助函数完整PE范围237字节，捕获版本与字典24偏移比较；该函数的注册方法身份尚未定位，单独记录，不推定具体泛型方法名。完整销毁原件被保存为证据，不等于完整销毁处理体已实现。
