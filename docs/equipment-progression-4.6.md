# 光锥、遗器养成缺口检查与修复

本轮沿新手剧情后的基础养成继续检查，处理光锥升级、遗器强化、光锥叠影三个入口。内部协议仍为 LunarCore lite 4.2.0，4.6 使用独立适配；没有修改生成协议类，也没有解锁尚未到达的剧情功能。

## 已复现问题

- 三种请求的材料容器在 4.6 中名为 `cost_data`，旧处理器读取 `item_cost_list`，此前转换缺少映射，正常请求在进入养成逻辑前就被拒绝。
- 叠影直接累加材料物件的 `rank`，专用叠影材料属于可堆叠材料，`rank` 为 0，可能扣料后没有成长。现在仅允许配置 `RankUpCostList` 明确登记的材料，每件提供一阶；同名光锥按已保存的叠影阶数贡献。普通材料、错误光锥不能代替。
- 叠影材料缺少目标自身、锁定、已装备、重复唯一编号、无效数量和整批库存校验，且失败仍回空成功。现在整批预检、同玩家串行扣料，原生响应返回实际结果。超过剩余叠影空间的整批选择拒绝，不浪费多余材料；目标光锥自身的锁定不阻止培养它。
- 光锥/遗器只检查当前等级经验表，后续曲线缺项时会先扣费再停在中途。现在预先验证本次跨过的全部等级及结果等级，再扣材料和信用点，遗器词条增长仍按每三级执行。此异常使用测试注入；当前安装资源的曲线完整性另由只读审计核对。

## 验证与边界

```powershell
python scripts/audit-equipment-progression.py
./scripts/build.ps1
python scripts/smoke-equipment-progression.py
python scripts/smoke-server.py
```

单元回归先记录三项原生请求、重复/保护材料、专用叠影器及缺失经验曲线的失败，再修复。额外覆盖整批失败不扣料、并发消费一次、有效同名高阶光锥、材料数量合并和错误响应。

独立 KCP 检查使用临时账号、临时 H2、测试服 GM 发放的材料，实际执行升级、强化和叠影，读取背包与同步通知；拒绝错误请求后继续查询，正常停服后再次登录同 UID 验证保存。该过程不操作正式账号，不代表官方客户端动画或按钮已验收。

本轮没有补齐全部养成机制。突破、行迹、批量叠影、保护/弃置的其余协议入口，以及消耗已培养光锥时的经验继承仍需独立核对。现有物品与玩家分文档保存，正常重启验证不等于突然断电时具备跨文档原子事务；异常写入不会伪装成原生叠影成功。任务审计中的未支持活动条件也继续保留，不能把本轮基础养成修复称为全游戏机制完备。
