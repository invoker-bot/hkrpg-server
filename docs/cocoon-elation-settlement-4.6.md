# 花萼战后「消息获取失败」与未开图直接挑战（4.6）

## 现场与原因

2026-11-02，正式服务记录 UID 10001 在楼层 20101001 结算花萼关卡 1024810 时被拒绝：`reason=battle-event-energy`，实际报告为 `70001 / current=0 / maximum=100000`。战斗编号 20505386 与当前战斗相同，正式参战角色为 1003、1101、1102、1211；服务器主动事件与角色事件集合均为空。这是日志中的结算拒绝，不把用户截图推定为地图加载错误。

原始 `CocoonConfig.json` 将 1024810、1024820、1024830 绑定到花萼 1029、世界等级 0；地图名称为以太之蕾·拟造花萼（金），每次消耗 10 点，上限 24 次。`BattleEventConfig.json` 将 70001 定义为 `TeamNeutral / Elation`，能力列表为空。现有报告校验只接受服务器主动事件或按参战角色冻结的神君事件，因而把这个客户端上报的空闲计数项拒绝。

当前本服普通/快速花萼工厂校验副本和关卡资源、次数、活动边界、当前战斗及开拓力，没有把已到达该地图或物件实体匹配设为入战条件，所以可以从面板直接挑战。原客户端具有独立的快速挑战流程；原 `FarmStageUnlockConfig` 1029 有世界等级与 UI 场景资料，但本轮未证明完整原版解锁策略。本次保留现有入场行为，不替玩家开放地图或生成传送点。完整地图/剧情解锁、物件身份和全部快速挑战条件仍是未完成范围，不能把“未开地图”当作本次结算拒绝的原因。

## 修复边界

`CocoonBattleEvents` 仅兼容已观察的 70001 / 0 / 100000。必须是 4.6 当前会话的真实活动花萼战斗，关卡类型、花萼和世界等级、映射、次数、完整波次及原资源费用均匹配。该项可随原报告缺省，不强制客户端增加事件；非零能量、其他上限或事件、重复项、其他关卡类型和旧 4.2 路径不因此放行。

此计数不写入模拟宇宙回响，不在出站战斗资料中追加第二个事件，不产生独立奖励。现有战斗/关卡身份、角色生命能量、非法线格式、一次结算与实际花萼掉落扣费仍由原路径处理。合法胜利继续每次扣 10 点；失败和退出不发胜利奖励。未修改生成协议、原始资源、玩家余额或任务前置。

这是一处按固定来源与实际报告限定的兼容处理，不声称已实现完整欢愉技能、非空闲计数或其他战斗模式。原始资源记录、文件摘要及现场数值保存在 `src/test/resources/fixtures/cocoon-elation-settlement-4.6.json`；只读客户端定位资料在 `build/cocoon-elation-settlement-20261102/`，没有执行客户端 DLL。
