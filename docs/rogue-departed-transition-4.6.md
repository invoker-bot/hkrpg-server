# 4.6 离场存在性迁移的事件尾部

登记列表从无离场参数变为有参数时发送 OnDepartedStart（226）和 OnListenDepartedStart（228）；最后一个参数撤销时发送 OnDepartedEnd（227）和 OnListenDepartedEnd（229）。数字和名称均来自 TurnBasedModifierEvent 的原始枚举字段，没有用猜测的自定义事件替代。

普通尾部先从明确绑定的事件池获取载荷，再读取所属实体并写入事件字段 BCBBPMNBGEI（offset 64）。实体及所属世界必须存在。战斗实例、战斗模式和事件处理器允许为空，任一为空时跳过分发，继续归还已获取的对象。

事件处理器存在时先发送角色事件，使用最初捕获的实体；源实体为空、过滤掩码为零。随后发送全局监听事件，重新读取当前能力状态的所属实体作为源实体；过滤掩码为零、附加过滤器为空。两次分发使用同一个载荷，再归还同一个对象。回调修改所属实体时，第二次分发看到新引用；回调修改载荷所属实体时不在末尾覆盖。

获取对象、要求实体或世界、查询链、角色或全局分发抛错时停止后续操作，没有在 finally 中归还载荷；成功的写入和分发前缀保留。归还失败时已完成的两次分发保留。该顺序与离场登记列表的存在性迁移相连，可见性刷新和列表移除已经发生后，事件失败不会回滚登记。
